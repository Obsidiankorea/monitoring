# 다른 PC로 옮겨 이어서 작업하기

내부망 윈도 PC에서 포크해 이어 가기 위한 문서. **이 문서만 보고 돌릴 수 있게** 썼다.

## 1. 가져오기

```bash
git clone <저장소> gnweather
cd gnweather
```

⚠️ **저장소에 없는 것이 둘 있다.** `.gitignore`로 막아 뒀다.

| 없는 것 | 어떻게 채우나 |
|---|---|
| `config/api_keys.txt` | 기존 PC에서 **손으로** 옮긴다(USB 등). `handoff-mac/config/api_keys.txt`도 저장소에 없으므로 **git으로는 절대 오지 않는다.** 그 자리에 놓아 두면 실행 스크립트가 `config/`로 복사한다 |
| `data/gnweather.db`, `data/cache/` | 채울 필요 없다. 처음 뜰 때 다시 받는다(10~40초) |

`config/api_keys.txt` 형식:

```
ORG_API_KEY=<기상청 API허브 기관용 키>
```

## 2. 실행

| | |
|---|---|
| **윈도** | `run.bat` 더블클릭 |
| **맥** | `run.command` 더블클릭 |

스크립트가 가상환경 생성 · 의존성 설치 · 키 배치 · 빈 포트 찾기 · 브라우저 열기를 한다.
처음만 1~2분 걸린다.

파이썬이 없으면 [python.org](https://www.python.org)에서 3.12 이상을 설치하고
설치 화면의 **"Add python.exe to PATH"를 반드시 체크**한다.

직접 띄우려면:

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m app.main
```

포트를 바꾸려면 `set PORT=9000` 후 실행. 다른 기기에서도 보려면 `set HOST=0.0.0.0`.

## 3. 이어서 작업하기

원격은 `origin` 하나(`github.com/Obsidiankorea/monitoring`), 가지는 `main` 하나다.
평소 흐름은 그대로면 된다.

```bash
git pull
# 고치고
git add .
git commit -m "무엇을 왜 고쳤는지"
git push
```

**PC를 옮겨도 이것만으로 된다.** 저장소에 들어가지 않는 것(키·DB·캐시·가상환경)은
전부 그 PC에서 만들어지거나 손으로 옮기는 것들이라 pull/push에 끌려오지 않는다.

몇 가지만 조심한다.

| | |
|---|---|
| **키를 커밋하지 않는다** | `.gitignore`가 막고 있지만, 새로 만든 파일에 키를 적지 않았는지 `git add` 전에 `git status`로 본다 |
| **`app/web/static/index.html`** | 4천 줄짜리 한 파일이다. 두 PC에서 같은 자리를 고치면 충돌이 크게 난다. **한 번에 한 쪽에서만** 고치는 편이 낫다 |
| **DB는 따라오지 않는다** | 옮긴 PC에서 처음 뜰 때 다시 받는다(10~40초). 과거 기록까지 옮기려면 `data/gnweather.db`를 손으로 복사한다 |
| **`data/cache/`** | 예측 그림이다. 옮길 필요 없다 — 최근 3개 발표분만 남고 알아서 다시 받는다 |
| **줄바꿈** | `run.bat`은 CRLF로 저장돼 있다. 편집기가 LF로 바꾸면 윈도에서 실행이 깨진다 |

## 4. 내부망에서 달라지는 것

### 기상청 API에 못 나가는 경우

수집기가 전부 실패하고 화면이 빈다. `data/gnweather.db`를 외부망 PC에서 만들어
복사해 오면 **읽기 전용 데모**로는 돌아간다. 정식으로는 프록시를 열거나,
`app/kma.py`의 호출부를 내부망 중계 주소로 바꾼다 — HTTP를 치는 곳은 그 파일 하나뿐이다.

### 평균강수량

**아직 구현하지 않았다.** 내부망에서 직접 받기로 해서 비워 뒀다.

- 화면: `metric === "avg"` 분기가 이미 있고, `stationsOf(sig)` 평균을 계산한다.
  서버에서 받아 온 값으로 바꾸려면 `app/web/static/index.html`의 `avgSeries()`를 고친다.
- 서버: `app/queries.py`에 `rain_avg()`를 추가하고 `/api/rain/avg`로 내보내면 된다.

## 5. 구조 — 어디를 고치면 되나

```
기상청 API ──▶ app/collectors/ ──▶ SQLite ──▶ app/queries.py ──▶ /api/* ──▶ 화면
               (APScheduler)      data/gnweather.db
```

| 하고 싶은 일 | 고칠 파일 |
|---|---|
| 새 기상청 API 붙이기 | `app/collectors/`에 파일 추가 + `app/main.py`의 `COLLECTORS`에 등록 |
| 저장 구조 바꾸기 | `app/db.py`의 `SCHEMA` |
| 화면에 줄 값 바꾸기 | `app/queries.py` |
| 수집 주기(기상청 호출 간격) | 화면 메뉴 `갱신 주기`에서 바꾼다(DB에 저장, 즉시 반영). 기본값은 `app/config.py`의 `INTERVALS` |
| 예측 이미지 장수·간격 | 화면 메뉴에서 바꾼다(DB에 저장). 기본값은 `app/config.py`의 `QPF` |
| 시군·특보구역 규칙 | `app/domain/regions.py` |
| 화면 | `app/web/static/index.html` 한 파일 |

`app/web/static/index.html`은 **단일 파일**이다. 빌드 도구가 없어 열어서 고치면 끝난다.
`mockup/`에는 서버 없이 도는 표본 데이터판이 있다 — 화면만 손볼 때 쓴다.

## 6. 절대 어기면 안 되는 것

`handoff-mac/docs/05-pitfalls.md`가 원본이고, 그중 코드에 박혀 있는 것:

1. **조회 실패와 '자료 없음'을 구분한다.** 실패는 저장하지 않고 다음 주기에 다시 시도한다.
   DB의 `quality` 열이 그 구분이다(`ok` / `missing` / `fetch_failed`).
   뭉개면 *전부 해제 → 전부 신규* 헛알림이 난다.
   화면에서는 **무강수와 결측이 같은 `—`**를 쓰되(0.0을 줄줄이 적으면 실제로 온
   칸이 묻힌다) **결측만 빗금 바탕**을 깔아 구분한다. 조회 실패는 붉은 `✕`다.
2. **비밀은 저장소에 넣지 않는다.** 코드의 기본값 딕셔너리에 넣는 것도 금지 — 커밋된다.
   로그도 조심한다. httpx가 요청 URL을 통째로 찍어 `authKey`가 남으므로 로거를 낮춰 뒀다.
3. **시각은 전부 KST.** UTC로 바꾸지 않는다.
4. **특보 레벨 문자열은 `주의`·`경보`다**(`주의보` 아님). 폭염은 `중대경보`까지 3단계이고
   레벨을 뗄 때 **긴 것부터** 떼야 `폭염중대경보`가 누락되지 않는다.
5. **RN1은 선행 1시간 누적**이라 값이 1시간 단위로만 바뀐다. 칸을 그냥 더하면 3배가 된다.
6. **예측 분포 API는 지역 크롭을 안 해 준다.** 전국을 받아 PIL로 자른다.
   크롭 박스는 소스마다 다르다.
7. **한꺼번에 많이 요청하면 중간이 통째로 실패한다.** 실측으로 확인했다(아래).
8. **'값이 하나도 없는 정시'를 받은 것으로 치지 않는다.** 정시 직후(`HH:00~HH:09`)에는
   `awsh.php`에 아직 그 시각 자료가 없다. 그때의 전부-결측을 완료로 치면 그 시각이
   **영영 빈 채로 굳는다.** `app/collectors/rain.py`의 `RETRY_HOURS`가 이것을 막는다.
   판정은 `quality='ok'`인 줄이 하나라도 있는가로 한다.
9. **마지막 칸은 '정시부터 지금까지'다.** 21:36 칸이면 21:00~21:36이다.
   매분자료의 `RN-60m`(직전 60분)을 넣으면 칸이 가리키는 구간과 값이 어긋나고,
   앞 정시 칸과 겹쳐 누적이 부풀어 오른다. `RN-60m`은 툴팁 참고값으로만 쓴다.
10. **이미 지나간 예측 시각은 버린다.** 발표가 한 박자 늦으면 첫 예측 시각이
    지금보다 앞이라, 그대로 그리면 예측 곡선이 통째로 한 시간 밀린다.
11. **무강수 0과 결측을 지점 고를 때도 구분한다.** 자료를 아예 안 주는 지점이
    0으로 묶여 다우지점 1등이 되면 그 시군이 통째로 빈다(실측: 사천공항).

## 7. 실측으로 알아낸 것

문서에 없거나 문서와 다른 것. **추측이 아니라 실제로 불러 확인한 값이다.**

| 항목 | 실측 |
|---|---|
| 예측 이미지 동시 요청 | 36장을 한꺼번에 던지면 `ef=190~240` 6장이 통째로 실패. 순차 + 1회 재시도로 36/36 성공 |
| 예측 이미지 크기 | `size=1800` → 1835×1820, 장당 약 130KB. 경남만 크롭하면 장당 약 19KB |
| 크롭 박스 | `size=1800` 기준 경남 광역 `(660, 560, 1610, 1360)` |
| 발표 감지 | 미래 시각을 요청하면 **최신 발표분**이 온다. 이미지 왼쪽 아래 발표시각 표시를 해시해 비교하면 무강수라 강수역이 같아도 속지 않는다 |
| 발표 지연 | 최신 가용 발표분은 보통 **지금보다 20~30분 전** 것이다(19:44에 확인한 최신은 19:30). 현재 슬롯을 노리고 기다리면 영원히 못 받는다 — 가진 것 다음 슬롯부터 앞으로 훑는다. `docs/02-발표주기.md` |
| 강수 자료를 안 주는 지점 | 56지점 중 **사천공항(161)·함양 백천(912)** 둘. 6개 정시 전수 확인. 나머지 54지점은 정상 |
| 대표지점 | `REP_STN` 18개 시군 전부 유효하고 모두 자료를 준다. 사천은 `917`(사천공항 `161` 아님) |
| 예측 분포 재생 깜박임 | 크로스페이드가 **원인**이었다(두 장이 반씩 섞여 색이 옅어진다). 즉시 바꾸고, 다음 장을 한 박자 앞서 감춘 겹에 깔아 둔다. 감춘 겹을 `opacity:0`으로 두면 브라우저가 미리 그리지 않으므로 `0.004`를 남긴다 |
