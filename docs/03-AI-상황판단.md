# AI 상황판단 — 규칙 · 위키 · LLM

지도에서 <kbd>I</kbd>로 여는 AI 상황판단 창이 **어디서 답을 만드는가**와, 위키를 고쳐 판정을 바꾸는 법, 답하는 LLM을 고르는 법.

> [!important] 한 줄 요약
> 보고와 예상 질문 단추는 **규칙**(대시보드 수치 × 위키 기준)이라 LLM 없이 바로 나온다. LLM은 **자유 질문 · 다시 판단**에서만, 규칙이 만든 결과를 받아 문장으로 엮는다. 숫자 계산 · 기준 대조는 LLM에 맡기지 않는다.

## 1. 답이 만들어지는 곳

| 화면 | 만드는 것 | 코드 |
|---|---|---|
| 상황판단 보고 (상황 · 중요한 점 · 할 일 · 참고) | 규칙 | `app/aireport.py` `report()` |
| 예상 질문 단추 (상황전파 · 비상단계 · 재난문자 …) | 규칙 | `app/aireport.py` `answer()` |
| 읍면동별 기준 대조 (통제 · 사전대피 · 긴급대피 %) | 규칙 | `app/ai.py` `situation()` · `ladders()` |
| 자유 질문 · 다시 판단 | LLM — 위 결과 + 위키 지시문을 넘긴다 | `app/aireport.py` `ask_free()` → `app/llm.py` |

답 글은 세 갈래에서 온다.

1. **실시간 수치** — 대시보드가 모은 특보 · 강수 · 수위 · 조위.
2. **위키에서 읽는 것** — 판정 숫자([[#2. 위키 판정값]]), 블록 문단, 재난문자 표준문안 표, 우려지역 · 지구별 대피기준(`tools/lookup.py` · `data/인명피해 우려지역.csv`), 책자 쪽수(문서 frontmatter).
3. **코드에 둔 것** — 답의 틀(칸 제목 · 문장 모양)과 판정 규칙의 구조(무엇과 무엇을 견주는지), 화면 한계 문구(예: 초단기 시우량 30㎜ 막힘).

## 2. 위키 판정값

숫자 기준은 위키 `data/판정값.csv` 한 파일에서 읽는다. 위키 쪽 설명은 위키의 `[[판정값]]` 문서.

| 항목 | 기본값 | 쓰는 곳 |
|---|---|---|
| `비상1단계_호우주의보_시군` · `비상2단계_호우경보_시군` | 4 · 3 | 도 비상단계 (`ai._stage`) · 단계 질문 · 상황판단회의 · 다음 단계 |
| `긴급재난문자_1시간` · `_3시간` · `_1시간_단독` | 50 · 90 · 72 | 재난문자 기준 (`ai.is_cbs`) · 재난문자 질문 · 할 일 |
| `상황전파_1시간` · `상황전파_일` | 20 · 100 | 상황전파 (`ai.is_relay`) · 상황전파 질문 · 할 일 · 텔레그램 알림 |

- 읽기: `ai.rules()` — 파일이 바뀌면(mtime) 다시 읽는다. 값 하나는 `ai.R("항목")`, 문장은 `ai.cbs_rule()` · `ai.relay_rule()`.
- **못 읽으면** — 파일 없음 · 숫자 아님 · 단계 겹침(비상 1단계 < 2, 72 ≤ 50)이면 위 기본값(2026-05)으로 판정하고, 모든 '참고 — 위키 · 책자' 칸 끝에 ⚠️ 경고를 붙인다. 판정은 멈추지 않는다.
- 도움말 › 백과의 비상단계 · 시우량 항목도 `/api/ai/rules`로 같은 값을 채운다(`{{항목}}` 자리).
- 설정 › AI › AI 위키 상태 줄에 '판정값 CSV 있음/없음'.

### 블록 문단

옵시디언 블록 링크(`[[문서#^ID]]`)로 문단을 그대로 읽어 보여 준다 — `aireport.block(링크, 예전 문장)`.

| 링크 | 화면 |
|---|---|
| `[[시군 상황관리반 행동매뉴얼#^전파]]` · `#^기록` | 상황전파 질문 › 전파 방법 |
| `[[위기경보와 비상단계#^특보제외]]` | 비상단계 질문 › 단계 기준 끝 줄 |

블록 ID를 못 찾으면 예전 문장을 보이고 참고 칸에 경고.

### 판례 — `적용` 속성

'⚠️ 판례로 본 점검' 칸(상황판단회의 · 대피 · 통제 질문)에 보일 판례는 위키 판례 문서 머리말 `적용: [상황판단회의, 대피, 통제]`로 고른다 — `aireport._pan_scenes()` · `_judicial(장면, …)`. 새 판례도 속성만 적으면 나오고, 번호 순으로 보인다. 요약 · 점검 글도 그 문서(`summary` · `## 도·시군 등 업무 적용`)에서 읽는다. 어느 판례에도 속성이 없으면(옛 위키) 예전 번호 목록을 쓴다.

> [!tip] 위키를 고쳤으면
> 1. 위키에서 `python tools/test_판정값.py` — CSV와 근거 문서 본문 숫자가 같은지, 블록 ID가 남았는지 본다.
> 2. PC는 바로 반영된다(파일을 다시 읽는다). NAS는 위키 사본을 따로 읽으므로 위키를 보낸 뒤 설정 › AI 위키에서 다시 읽기(`/api/ai/wiki/reset`).

> [!warning] 위키로 옮기지 않은 것
> - 산사태 · 하천 · 지하공간 통제 · 대피 사다리 값(`ai.ladders`의 100 · 200 · 170㎜ 등) — 아직 코드에 있다. 지구별 값은 이미 `lookup.py`로 위키에서 읽는다.
> - 답의 틀과 판정 구조. 위키가 프로그램이 되면 오히려 고치기 어렵다.
> - 실행되는 코드(`.py`)로 기준을 두지 않는다 — 위키를 고치는 사람이 서버에서 코드를 돌리게 된다. 기준은 CSV · 문단만.

## 3. AI 답변 설정 — 누가 자유 질문에 답하나

설정(<kbd>Ctrl</kbd>+<kbd>,</kbd>) › **AI** 탭 › **AI 답변**. 서버마다 따로 저장된다(DB `ai_llm`). 키는 이 설정에 두지 않는다.

| 고르기 | 무엇 | 필요한 것 |
|---|---|---|
| 자동 | 서버 환경변수 `GN_AI`대로(예전 방식, 처음 값) | — |
| 끔 | 예상 질문 단추만 | — |
| Claude | `claude -p` (Claude Code 구독) | PC 로그인 또는 `config/claude/token.txt` |
| 로컬 | 이 PC의 llama.cpp `llama-server` (Vulkan · Qwen3 8B, OpenAI 호환) | `~/llm/vulkan/llama-server.exe` · `~/llm/qwen3-8b.gguf` (다른 곳이면 `GN_LLAMA_DIR`) |
| 기타 | OpenAI 호환 주소 | 환경변수 `GN_AI_URL` · `GN_AI_KEY` · `GN_AI_MODEL` |

### 로컬 LLM

- **알아서 켠다** — 로컬을 고를 때, 또는 물었는데 서버가 꺼져 있으면 `llama-server`를 띄운다(주소가 `127.0.0.1` · `localhost`일 때만). 상태 줄에 '켜는 중 → 켜져 있음 · 모델 이름', 꺼져 있으면 **켜기** 단추. 로그는 `data/llama-server.log`.
- 띄우는 값: `-ngl 99 -c 16384 --jinja -np 1 -b 512 -ub 256`. `-b`·`-ub`를 작게 둔 것은 2,048토큰을 한 번에 GPU에 넘기면 Windows GPU 시간 제한에 걸려 `vk::Device ErrorDeviceLost`로 죽기 때문이다(Arc 140V에서 겪음). 500 오류가 나면 직접 띄운 서버를 껐다 켜고 한 번 더 묻는다.
- 요청에는 Qwen3 생각을 끄고(`enable_thinking: false`) `max_tokens` 700, 제한 시간 300초. 답 전체를 감싼 코드 블록과 `<think>`는 벗긴다.
- 속도(2026-11-03, 경남 전체 약 8천 토큰): 처음 172초, 같은 맥락으로 다시 물으면 56초. 시군을 고르면 맥락이 줄어 빠르다.

> [!warning] 로컬의 한계
> - NAS에서는 못 쓴다 — 서버가 PC의 `127.0.0.1`에 닿지 않는다. 로컬은 **PC 대시보드에서** 고른다.
> - 한 번 켠 `llama-server`는 대시보드를 꺼도 남아 그래픽 메모리를 쓴다(자동으로 끄지 않는다).
> - 8B는 질문에 딱 맞추기보다 지시문 틀(■ 지금 판단 · 할 일 …)을 따라가고, '근거 수치' 줄에 없는 값을 지어낼 수 있다. 위키에 정해진 내용을 묻는 데는 Claude가 낫다.
