# 국가교통정보센터 재난상황정보 API

기술기준 v1.2(2026.07.22) 기준. 침수는 기상청 호우특보, 하천범람은 하천홍수경보, 땅꺼짐은 지반침하 신고, 화재는 산불 신고에서 만들어진다.

## 부르는 법
`https://openapi.its.go.kr:9443/disasterInfo?apiKey=…&category=D&eventType=D03,D04&startDate=YYYYMMDD&endDate=YYYYMMDD&getType=json`
키가 주소에 들어간다 → 로그 · 화면에 주소를 찍지 않는다.

## 호출 한도 · 주기
| 칸 | 값 |
|---|---|
| 호출단위 | 전국 1회 |
| 원천갱신 | 호우경보 발표 · 해제 때(확인한 주기 없음) |
| 평시주기 → 비상주기 | 부르지 않음 → 15분 |
| 비상조건 | 경남에 호우특보 발효 |
| 하루호출 | 비상일 96건 — 월 1000건이면 특보가 하루 종일 약 10일 이어져도 버틴다. 950건에서 멈춘다 |

키는 **NAS 서버 한 곳에만** 둔다. PC 에 넣으면 PC 서버도 불러 한도를 함께 쓴다.

## 알아 둘 것 (2026-07~08 실제 응답 192건)
- 문서와 다르다 — 목록이 `body.items`, 결과가 `header.resultCode`, 필드는 `locationInfo` 처럼 소문자로 시작한다.
- 영역(minX 등)은 좌표가 있는 건(산불 · 땅꺼짐)만 거르는 것으로 보인다. 좌표 없는 침수 건은 전국이 그대로 온다 → 코드에서 가른다.
- 침수 163건은 지역을 가리지 않고 모두 좌표 · 도로명 · 지하차도 이름이 비었다. `locationInfo` 좌표는 산불 28건 · 땅꺼짐 1건에만 있었다(점 또는 `POLYGON((…))`). 지역 이름과 링크 번호뿐이고 경남 4건 중 링크가 있는 건 1건이다. 표준노드링크가 없어 지도에 못 찍는다.
- 경남 링크 번호는 38 로 시작한다(진주 381 · 밀양 386 · 3870 확인).
- `status` 는 모두 6 이고 해제 뒤에도 `endDate` 가 `-` 로 남는 건이 있다 — 어제 · 오늘 발생분만 믿는다.
- 하천범람(D04)은 이 기간 0건이라 실물을 못 봤다. 산불(D07)은 위치가 있는 건이 있으나 호우와 무관해 받지 않는다. 땅꺼짐에 시험 자료가 섞여 있었다.
