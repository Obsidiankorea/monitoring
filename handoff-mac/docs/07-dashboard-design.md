# 07. 상황판 화면 설계 (초안)

> 재난상황실 **벽면 모니터 상시 표출**을 전제로 한 화면·갱신·저장 설계.
> `01-requirements.md`는 "휴대폰이 1순위"였다. 이 문서는 그 전제를 **바꾼다**
> — 1순위는 상황실 벽면(1920×1080 이상), 휴대폰은 같은 자료를 좁게 접는 2순위다.
> 화면 초안: [경남 기상 상황판 아티팩트](https://claude.ai/code/artifact/1db337ec-0795-4420-9fbd-879a45937598)

## 1. 화면 구성

한 화면에 다 들어가고 **스크롤이 없다**. 스크롤은 패널 안에서만 일어난다.

```
┌─ 상태 바 ───────────────────────────────────────────────────────────┐
│ 브랜드 │ 상황단계 · 현재시각 │ 갱신주기(10/15/20/30) · 남은시간 · 지금조회 │
├─────────────────────┬────────────────────┬──────────────────────────┤
│ 다우지점 강수량      │ 초단기예보          │ 기상특보                  │
│ 시군 18행 × 시간대별 │ 상위 읍면동 순위     │ 경보/주의보/해상/예비      │
│ + 기간 누적(막대)   │ + 최대 시우량        │ + 집계표기 + 발효예정      │
├─────────────────────┼────────────────────┼──────────────────────────┤
│ 특보 발효현황 지도   │ 예비특보 지도       │ 초단기예보 분포도         │
│ nph-wrn7 tmef=0     │ 날씨누리 …b.png     │ nph-qpf_ana_img qpf=B    │
├─────────────────────┴────────────────────┴──────────────────────────┤
│ 수집 상태(자료별 마지막 성공시각·실패) │ API 호출량 · 캐시 응답 · 이미지 재생성 │
└─────────────────────────────────────────────────────────────────────┘
```

### 배치 근거

- **위: 숫자, 아래: 그림.** 3m 밖에서는 그림이 먼저 눈에 들어오고, 다가와서
  숫자를 읽는다. 숫자를 아래 두면 허리를 굽혀야 한다.
- **왼쪽에 강수량.** 시선이 처음 닿는 자리에 "지금 어디에 얼마나"가 온다.
- **오른쪽에 특보.** 텍스트 목록이라 폭이 좁아도 된다.
- **`기준시각`을 패널마다 붙인다** (F1.3). 화면 전체의 시각 하나로 뭉개지 않는다 —
  강수량은 14:00 정시 + 14:20 보강, 특보는 14:23 현재, 예보는 14:10 발표로 **전부 다르다**.

### 표에서 지키는 표기 규칙

| 표시 | 뜻 |
|---|---|
| `0.0` | 무강수 |
| `—` (빗금 배경) | 결측 — 관측값이 없다 |
| `✕` (주황) | **조회 실패** — 값 없음이 아니다. 재시도 대기 중 |

셋을 절대 같게 그리지 않는다. `05-pitfalls.md ★1`의 화면판이다.
색은 **한 가지 청색 램프**만 쓴다(값이 클수록 밝음). 기상청 무지개 색계는
**기상청이 만든 이미지 안에만** 두고, 우리가 그리는 표에는 쓰지 않는다 —
같은 화면에 색계가 둘이면 사람이 둘을 섞어 읽는다.
옅은 단계는 배경 대비가 낮으므로 **칸마다 숫자를 항상 함께 적는다**.

특보 색(주의보 노랑 / 경보 빨강 / 중대경보 보라 / 예비 회보라)은 **예약색**이다.
다른 용도로 재사용하지 않고, 언제나 글자 라벨과 함께 나간다.

## 2. 갱신 — 세 가지를 분리한다

혼동하기 쉬운 세 주기를 **따로 둔다.**

| 주기 | 무엇 | 값 | 누가 정하나 |
|---|---|---|---|
| **수집 주기** | 서버가 기상청을 부르는 간격 | 자료별 고정(아래 표) | 서버 설정 |
| **표출 주기** | 브라우저가 서버에서 받아오는 간격 | **10 / 15 / 20 / 30분** | **사용자(화면에서)** |
| **재생성 주기** | 이미지 크롭·합성 | 지문이 바뀔 때만 | 자동 |

사용자가 화면에서 고르는 10~30분은 **표출 주기**다. 이걸 바꿔도 기상청 호출량은
변하지 않는다 — 서버 DB에서 읽어올 뿐이다. **이 점이 이 설계의 핵심**이고,
"API 콜이 많아진다"는 걱정은 여기서 끊어진다.

### 수집 주기

| 자료 | 주기 | 1일 호출 | 근거 |
|---|---|---|---|
| 기상특보 `wrn_now_data` | 1분 | 1,440 | 발표 리듬이 없다. 아무 때나 나온다 |
| 강수량 정시 `awsh` | 10분 | 144 | 전 지점을 1회로 받는다(`stn=0`) |
| 매분 보강 `nph-aws2_min` | 10분 | 144 | 최근 1시간 공백 메우기 |
| 초단기예보 `nph-dfs_vsrt_grd` | 발표당 6회 | 864 | tmef 6구간. **같은 구간은 재조회하지 않는다** |
| 특보 지도 `nph-wrn7` | 지문 변경 시 | 20~50 | 특보 상태 해시가 같으면 캐시 |
| 예비특보 `날씨누리` | 10분 | 144 | 파일명을 페이지에서 읽고, 같으면 안 받는다 |
| QPF 분포도 | 발표당 1 | 144 | |
| **합계** | | **약 3,000** | 접속자 수와 무관하다 |

접속자가 1명이든 20명이든 위 숫자는 그대로다. 화면은 DB만 읽는다.

### 수동 갱신 (`지금 조회`)

**주기와 무관하게 실제로 다녀온다.** 내부 주기 함수를 그냥 부르면
"이미 처리한 발표분" 분기로 빠져 **아무 일도 일어나지 않는다**(`05-pitfalls.md ★3`).
수동 경로는 캐시 무효화 플래그를 달고 강제 조회한다.

- 누르는 순간 화면에 스윕 애니메이션 → "정말 다시 받았다"는 신호
- 조회 후 배지가 `DB 조회` → `API 직조회`로 바뀐다
- 실패하면 **이전 값을 지우지 않고** 기준시각을 주황(`stale`)으로 바꾼다

## 3. 저장 — 기간 지정 누적을 위한 테이블

`02-architecture.md`의 `snapshot(kind, base_time, payload JSON)`은 특보·예보 스냅샷에는
맞지만, **기간을 지정해 합산**하려면 JSON을 풀어야 해서 못 쓴다. 관측은 별도 테이블로 둔다.

```sql
-- 정시 관측. 기간 누적·다우지점 산출의 유일한 출처.
CREATE TABLE obs_hourly (
  stn        TEXT NOT NULL,          -- 지점번호
  tm         TEXT NOT NULL,          -- 'YYYY-MM-DD HH:00' KST 정시
  rn_hr1     REAL,                   -- 그 시각까지 1시간 강수량. NULL 허용
  rn_day     REAL,                   -- 당일 누적(00시 값 = 전날 총량)
  ta         REAL,
  quality    TEXT NOT NULL,          -- 'ok' | 'missing' | 'fetch_failed'
  fetched_at TEXT NOT NULL,
  PRIMARY KEY (stn, tm)
);
CREATE INDEX idx_obs_tm ON obs_hourly(tm);

-- 정시 이후 구간 보강(매분자료). 정시 자료를 덮어쓰지 않는다.
CREATE TABLE obs_minute (
  stn TEXT NOT NULL, tm TEXT NOT NULL,   -- 'YYYY-MM-DD HH:MM'
  rn_60m REAL, rn_day REAL, quality TEXT NOT NULL,
  PRIMARY KEY (stn, tm)
);
```

**`quality` 열이 이 스키마의 핵심이다.** `rn_hr1 = 0`(무강수)과 `NULL`(결측)과
`fetch_failed`(조회 실패)를 한 열로 구분한다. 이게 없으면 화면에서 셋을 갈라 그릴 수
없고, 감시기가 실패를 '비 안 옴'으로 읽어 헛알림을 낸다.

### 누적 조회

```sql
SELECT stn,
       SUM(CASE WHEN quality='ok' THEN rn_hr1 ELSE 0 END) AS acc,
       SUM(quality<>'ok')                                 AS bad_hours
FROM obs_hourly
WHERE tm >= :from AND tm <= :to
GROUP BY stn;
```

`bad_hours > 0`이면 화면에 누적값 옆에 **"N시간 결측"**을 붙인다. 결측을 0으로
더해 놓고 아무 말 없이 보여주면 과소평가한 값이 사실처럼 읽힌다.

**다우지점** = 시군별 `acc` 최댓값 지점. ⚠️ 시군 행의 값과 다우지점 표의 값은
**같은 쿼리 한 번**에서 나와야 한다(원본에서 산청지리산 56.0 vs 75.5로 어긋났다).

### 백필

기간을 과거로 늘렸을 때 `obs_hourly`에 없는 정시가 있으면 그 시각만
`awsh.php?tm=…`로 한 번 받아 채우고 저장한다. 같은 구간을 두 번 받지 않는다.
초기 적재는 최근 30일치를 하루 24회 × 30 = 720회로 한 번에 끝낸다.

### 보관

- `obs_hourly` — 무기한(행 하나가 수십 바이트다. 18시군 56지점 × 24 × 365 ≈ 49만 행/년)
- `obs_minute` — 7일 후 삭제(정시 자료로 대체 가능)
- 이미지 캐시 — 30일

## 4. 이미지 3장

| 패널 | 출처 | 갱신 조건 |
|---|---|---|
| 특보 발효현황 | `nph-wrn7` `tmef=0` `lon=128.3 lat=35.3 range=90` | 특보 지문 변경 시 |
| 예비특보 | 날씨누리 `KTKO50_…_108_부산b.png` | 파일명 변경 시 |
| 초단기예보 분포도 | `nph-qpf_ana_img` `qpf=B` | 발표 갱신 시 |

- `tmef=1`을 쓰면 **내일 발효 특보가 오늘 지도에 칠해진다.** 기본은 `0`.
- 예측 분포도는 **지역 크롭이 안 된다.** 전국을 받아 PIL로 자른다.
  QPF 835×820, 초단기 분포도 901×1551 — **크롭 박스를 소스별로 따로 저장**한다.
- 날씨누리 파일명은 **추측하지 않는다.** `warning.do`에서 읽는다. 과거 재현 불가.

## 5. 정하고 넘어갈 것

1. **"초단기예보 이미지(b)"의 뜻** — 초안은 `nph-qpf_ana_img&qpf=B`(융합 QPF)로
   해석했다. 날씨누리 `…b.png`(예비특보 지도)를 뜻한 것이라면 그건 이미 별도 패널로
   있으므로, 셋째 지도 자리를 `nph-dfs_vsrt_ana2`(예보 표와 **같은 산출물**이라
   표와 그림이 일치한다)로 바꾸는 편이 낫다.
2. **표출 주기 기본값** — 10분? 그리고 이 설정을 브라우저에만 둘지(localStorage),
   서버에 저장해 모든 화면이 같이 움직이게 할지.
3. **기간 지정의 상한** — 30일? 1년? 백필 비용과 직결된다.
4. **상황 단계 배지의 판정 규칙** — 지금은 "경보 있으면 빨강". 시우량 기준을 섞을지.
5. 상황실 모니터의 실제 해상도·비율(1920×1080 / 3840×2160 / 세로 배치 여부).
