# 04. 경남 도메인 지식

> 기상청 자료를 '경남 보고서'로 만들 때 필요한 규칙. 대부분 API 문서에 없고,
> 실제 응답을 보며 알아낸 것이다.

## 시군 관제순 (표시 순서)

행정 코드순도 가나다순도 아닌 **관제순**이다. 표·목록은 항상 이 순서로 낸다.

```python
DISPLAY_ORDER = ["창원", "진주", "통영", "사천", "김해", "밀양", "거제", "양산",
                 "의령", "함안", "창녕", "고성", "남해", "하동", "산청", "함양", "거창", "합천"]
```

강수량 표의 `1강`~`18강` 번호도 이 순서다(1=창원 … 18=합천).

**시/군 접미사는 붙이지 않는다.** API는 `창원시`·`함양군`으로 주지만 표기는 `창원`·`함양`.

## 특보구역 세분화

서부경남 일부 군은 특보구역이 나뉜다. **API에서 세분화 군은 상위구역(`REG_UP_KO`)이
`경상남도`가 아니라 `OO군`으로 내려온다** — 이걸 모르면 필터에서 통째로 누락된다.

```python
SUBZONES = {
    "합천": [("합천서북부", "서북"), ("합천중부", "중"), ("합천남부", "남")],
    "산청": [("산청북부", "북"), ("산청서남부", "서남"), ("산청동남부", "동남")],
    "함양": [("함양중부", "중"), ("함양서북부", "서북")],
    "거창": [("거창북부", "북"), ("거창남부", "남")],
    "하동": [("하동북부", "북"), ("하동남부", "남")],
}
```

나머지 시군(의령·창녕·거제·통영·사천·남해·진주·창원·김해·밀양·양산·함안·고성)은
아직 미세분이라 상위구역이 `경상남도`다.

세분화된 육상 구역까지 합치면 전체 **25곳**이다(축약 표기의 '전 시군' 기준).

### ⚠️ 강원도 고성 배제

**경남 고성은 세분화되지 않아** 상위구역이 항상 `경상남도`다. 따라서
**상위구역이 `고성군`인 것은 강원 고성**(`고성산간`/`고성평지`)이다.

"상위구역이 경남 시군명이면 포함" 규칙만 쓰면 강원 고성이 새어 들어온다.
`NO_SPLIT_SIGUN = {"고성"}`을 두고, 상위구역이 그 집합에 있으면 제외할 것.

## 경남 특보 필터 (육상 + 해상)

```
포함:
  · REG_UP_KO == '경상남도'                        (육상, 미세분 시군)
  · REG_UP_KO가 경남 시군명 && NO_SPLIT_SIGUN 아님  (육상, 세분화 군)
  · REG_UP_KO in ('남해동부전해상', '남해동부앞바다')  (해상)
    단, 구역명에 '부산' 또는 '전남'이 들어가면 제외
```

⚠️ 해상은 `남해동부전해상`(먼바다)만 보면 **거제시동부앞바다·경남서부남해앞바다가 누락**된다.
`남해동부앞바다`도 포함해야 한다.

## 집계 표기 규칙

특보 목록 옆에 붙이는 `<N개시군 M개소>` 표기.

- **개소(M)** = 세부구역 수(분할해서 셈). 산청 북부·서남부·동남부 → 3개소
- **개시군(N)** = 서로 다른 시군 수. 위 예는 1개시군
- **개소 == 시군이면 `N개시군`만** 쓴다(중복 표기 방지)
- **해상 특보는 항상 `N개소`만** (시군 개념이 없다)
- **집계에는 발효 중인 것만 넣는다.** 발효 예정은 따로 표기하고 세지 않는다

### 세부지역 접기

같은 시군의 세부구역은 시군명을 반복하지 않고 묶는다:

```
합천중부, 합천남부   →   합천중·남부
산청북부, 산청서남부, 산청동남부   →   산청북·서남·동남부
```

표시할 때 세부지역 부분은 **윗첨자**로 작게 쓴다(`합천` + ˢᵘᵖ`중·남부`).

## 롤업 vs 분할 — 쓰임새가 다르다

같은 특보 데이터를 두 가지로 가공한다. **섞으면 안 된다.**

| 쓰임새 | 방식 | 예 |
|---|---|---|
| 지도·시각화(시군 단위 색칠) | **롤업** — 부모 시군으로 합침 | `합천중부` → `합천` |
| 텍스트 목록·표 | **분할** — 세부구역 그대로 | `합천중부` 유지 |

## AWS 관측지점

`data/aws_stations.json` — 경남 56지점 (`stn` / 지점명 / 시군명).

**시군 대표지점**(시군별 기온·강수 대표값)은 따로 정해져 있다:

```
창원 155  진주 192  통영 162  사천 917  김해 253  밀양 288
거제 294  양산 257  의령 263  함안 920  창녕 919  고성 918
남해 295  하동 932  산청 289  함양 264  거창 284  합천 285
```

### 다우지점

**시군 안에서 누적 강수량이 가장 많은 지점**. 표기는 `산청 지리산 56mm`처럼
시군명을 작게(윗첨자) + 지점명.

⚠️ **시군 행의 다우지점 값과 다우지점 표의 값이 같은 계산에서 나와야 한다.**
원본 프로젝트에서 시군 행만 정시 자료로 따로 계산해 아래 표(매분 보강)와
값이 어긋난 적이 있다(산청지리산 56.0 vs 75.5).

⚠️ 3일 기온표 등에서 **가야산(311)·지리산(872)은 제외**할 것 — 산악이라 늘 극값을
독식해서 정보가 되지 않는다.

## 격자 매핑

`data/gyeongnam_grids.json` — `{시군: [{xy: [X, Y], emd: 읍면동}]}`, 경남 206개 읍면동.

- 인덱스 = `(Y - 1) * 149 + (X - 1)` (격자 폭 149)
- **창원은 5개 구를 하나로 병합**해 두었다
- ⚠️ 읍면동은 모델의 계산 단위가 아니라 **약 5km 격자칸에 붙인 이름표**다.
  같은 격자에 든 이웃 읍면동은 값이 같게 나온다

## 시각 기준

- 모든 시각은 **KST**. UTC 변환하지 않는다.
- 보고 기준시각은 보통 **06시** 또는 **17시**.
- **특보는 예외 없이 '실행 시점의 최신'으로 조회**한다. 기준시각을 06시로 놓고
  특보를 조회하면, 아직 발효 전인 특보가 발효로 오인될 수 있다.
- 강수량은 **정시** 자료가 기본이고, 최근 1~2시간은 매분자료로 보강한다.
  화면에는 **보강된 실제 최신 시각**을 표시할 것(정시로 표시하면 앞뒤가 안 맞는다).
