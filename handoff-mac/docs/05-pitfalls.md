# 05. 함정 모음 — 뭔가 이상하면 여기부터

> 전부 **실제로 겪은** 것이다. 원본 프로젝트에서 하루 이상 헤맨 것만 골랐다.
> 새 프로젝트에서 같은 곳에 다시 빠지지 않는 것이 이 문서의 목적이다.

## ★ 1. 조회 실패를 '데이터 없음'으로 처리하면 오보가 나간다

**가장 비쌌던 실수.** 특보 조회 함수가 어떤 예외든 삼키고 빈 값을 돌려줬다.

```python
except Exception as e:
    print(...)
    return {}        # ← 타임아웃도, 네트워크 오류도 전부 '특보 없음'이 된다
```

1분 주기 감시에서 타임아웃이 한 번 나자:

```
11:12  타임아웃 → {}     →  "특보 전부 해제" 알림
11:13  정상 복구 → 25건  →  "특보 전부 신규" 알림
```

**규칙**: 실패는 `None`, 없음은 빈 값. 둘을 구분할 수 없는 함수는 감시에 쓰지 않는다.
보고서 생성처럼 '없음으로 보고 진행'이 나은 곳도 있으니, **호출부가 고르게** 인자를 둔다.

**이중 안전장치**: 그래도 "한꺼번에 전부 바뀐" 결과는 의심한다. 특보는 보통 한두
구역씩 바뀐다. 전부 사라지거나 전부 생기면 **다음 조회에서도 같을 때만** 인정한다.
⚠️ *즉시 재조회는 소용없다* — 장애가 몇 초 이어지면 같은 오답을 두 번 받을 뿐이다.

## ★ 2. 반복 알림 — 키를 잘못 잡으면 계속 울린다

호우가 이어지면 기준(30mm)을 **계속** 넘는다. 알림 중복 판정 키를
`(발표시각, 읍면동)`으로 잡았더니 발표는 10분마다 갱신되므로 **매번 새 경보**가 됐다.

**규칙**: 첫 경보 뒤에는 **최대치가 N mm 더 올랐을 때만** 다시 알린다(30 → 40 → 50…).
기준 아래로 내려가면 기준선을 풀어 다음 상황은 처음부터 센다.

```
기준30·상승폭10 →  30🔔  30·32·35(조용)  40🔔  45(조용)  50🔔  20(리셋)  35🔔
```

## ★ 3. 값이 한 번 잘못 읽히면 화면에 계속 남는다

발표분을 고정해 읽었더니(막 올라오는 중이라) 빈 격자가 왔고, 대시보드에
"예상 강수 없음"이 찍혔다. 그다음 틱은 "이미 처리한 발표분" 분기로 빠져
**셀을 갱신하지 않아** 틀린 값이 10분간 그대로 남았다.

**규칙**
- 0이 나오면 **한 번 더 확인**한다(발표분 고정 없이 최신분으로).
- "직전에 값이 있을 때만 확인"으로 좁히면 **한 번 0에 빠진 뒤 영영 못 나온다.**
  실제로 그렇게 갇혔다. 0이면 항상 확인할 것.
- 화면에는 **조회 시각을 항상 표시**한다. 없으면 지금 값인지 아까 값인지 알 수 없다.
- '지금 조회' 같은 수동 버튼은 **주기와 무관하게 실제로 조회**해야 한다.
  내부 주기 함수를 그냥 부르면 "이미 처리함" 분기로 빠져 아무 일도 안 일어난다.

## ★ 4. 폭염은 3단계다

주의보 → 경보 → **중대경보**. 레벨 문자열을 뗄 때 **`중대경보`를 가장 먼저** 떼야 한다.

```python
# ❌ 이러면 '폭염중대경보' → base가 '폭염중대' → '폭염'과 매칭 실패 → 통째로 누락
name = atype.replace('경보', '').replace('주의보', '')

# ✅ 긴 것부터
for lvl in ('중대경보', '경보', '주의보', '주의'):
    ...
```

또한 **API가 주는 레벨은 `주의`다**(`주의보` 아님). `주의보`로 매칭하면 표가 전부 빈다.

## 5. RN1은 1시간 누적이다

- 10분 간격으로 조회해도 **값이 1시간 단위로만 바뀐다** → 구간당 1회만 조회
- **누적을 낼 때 칸을 그냥 더하면 3배**가 된다 → 1시간 구간마다 한 번씩만
- 값이 **정수 mm로 양자화**돼 상위권에 동률이 쏟아진다 → 순위는 누적으로 정렬

## 6. `RN_DAY`의 자정 특성

00시에 **전날 하루 총량**을 표시하고 01시에 0으로 리셋된다.
이걸 알면 전날 총량을 따로 조회할 필요가 없다(기준일 `0000`시 값이 곧 전날 총량).
모르면 값이 이상하다고 헤매게 된다.

## 7. 정시 자료만 주는 API가 있다

`awsh.php`는 **매시 00분 자료만** 있다. `0550` 같은 분단위를 넣으면 빈 응답이다.
06시 직후에는 06:00 자료가 아직 없을 수 있으니 **직전 정시로 폴백**할 것(최대 3시간).

최근 1~2시간이 비는 문제는 **매분자료(`nph-aws2_min`)로 보강**한다.
그리고 화면 제목에는 **보강된 실제 최신 시각**을 쓸 것 — 정시로 쓰면
"09:00 기준"이라면서 10:06 칸이 있는 모순이 생긴다.

## 8. 예측 이미지 API는 지역 크롭이 안 된다

`stn`·`zoom_*`·`lon/lat`을 줘도 **전부 무시하고 전국 이미지**를 준다.
전국을 받아 직접 잘라야 한다.

⚠️ **소스마다 이미지 크기가 달라 크롭 박스를 공유할 수 없다.**
QPF는 835×820, 초단기예보 분포도는 901×1551 — 영점도 배율도 다르다.
하나로 쓰다가 "분포도를 고르면 엉뚱한 데가 잘리는" 문제를 겪었다.
**소스별로 박스를 따로 저장**할 것.

## 9. `wrn=` 필터는 콤마 구분이다

문서에는 파이프(`|`)로 되어 있지만 **콤마만 동작**한다. 파이프를 쓰면 빈 이미지가 온다.

## 10. 예비특보는 별도 취급이 필요하다

- **`nph-wrn7` 지도에 그려지지 않는다.** 지도만 보면 예비특보가 통째로 빠진다.
  지도는 날씨누리에서 받고(`…b.png`), 목록은 텍스트로 따로 적을 것.
- **`TM_EF`가 시각이 아니라 시간대 코드**다. 그대로 찍으면 `11:59` 같은 없는 시각이 된다.
- 아직 발효 전이므로 '발효'가 아니라 **'예상'**으로 표기한다.

## 11. 날씨누리는 최신 파일만 있다

파일명을 규칙으로 만들어 넣으면 **PNG가 아니라 HTML**(없음 페이지)이 온다.
반드시 페이지에서 현재 파일명을 읽어올 것. 과거 재현은 불가능하다.

또한 `special-report/overall.do` 페이지에는 **지도 이미지가 HTML에 없다**(JS가 불러온다).
`wnuri-fct2021/weather/warning.do` 조각을 써야 한다.

## 12. 텔레그램 — `parse_mode`를 켜지 말 것

특보 지역명에 `(`, `~`, `.`이 섞여 있어 Markdown/HTML 파싱을 켜면
**400으로 전송이 통째로 실패**한다. 서식 없이 평문으로 보낼 것.

그리고 **모달 팝업보다 먼저 전송**할 것. 팝업이 뜨면 사용자가 닫을 때까지
전송 코드가 실행되지 않는다.

## 13. 비밀이 새는 경로

- 코드의 기본값 딕셔너리 — **커밋된다**. 여기에 토큰을 넣지 말 것.
- `.gitignore`의 **줄 끝 주석** — gitignore는 인라인 주석을 패턴의 일부로 본다.
  ```
  secrets.txt   # 설명    ← 이러면 무시가 안 된다
  ```
  주석은 윗줄에 따로 쓸 것.
- 텔레그램 요청은 **URL에 토큰이 실린다.** 다른 API용으로 SSL 검증을 껐더라도
  텔레그램만은 검증을 켤 것.

## 14. 문자 인코딩

- `wrn_now_data.php` 응답은 **euc-kr**이다.
- 콘솔이 cp949면 `—`, `⚠`, 이모지를 print할 때 **프로그램이 죽는다.**
  출력 스트림을 `errors='replace'`로 열어 둘 것.
- (참고, Tk 한정) **Tk는 컬러 이모지를 못 그린다.** 웹에서는 문제없다.
