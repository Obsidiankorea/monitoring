# 01. 요구사항 명세

> 명세 주도 개발(spec-driven development)의 출발점. **코드를 쓰기 전에 여기서 합의**한다.
> 합의되지 않은 항목은 `❓미정`으로 남기고, 정해지면 이 문서를 고친 뒤 구현한다.

## 목적

경상남도 재난 담당자가 **한 화면에서** 지금 비가 어디에 얼마나 오는지, 특보가 어떤지,
앞으로 어떻게 될지 확인하고, 위험할 때 **찾아보지 않아도 알림을 받게** 한다.

기존 Windows 프로그램은 *한글 보고서를 만드는* 도구다. 이 프로젝트는 *상황을 보는*
도구다. 역할이 다르므로 기능을 그대로 옮기지 않는다.

## 이용자와 상황

| 이용자 | 언제 | 무엇이 필요한가 |
|---|---|---|
| 담당자(본인) | 새벽 호우 시 휴대폰으로 | 지금 어디가 심한가, 앞으로 어떤가 |
| 담당자(본인) | 사무실 PC에서 | 시군별 표, 예측 이미지, 특보 지도 |
| 동료·상급자 | 상황 발생 시 | 링크 하나로 현황 + 관련 문서 열람 |

**휴대폰이 1순위다.** 새벽에 급히 보는 화면이 휴대폰이므로, 좁은 화면에서 먼저
설계하고 넓은 화면으로 확장한다.

## 기능 요구사항

### F1. 대시보드 (표출)

- **F1.1** 정해진 시각/주기에 기상 자료를 받아 화면에 보여준다.
  - 시군별 **강수량** (1시간, 당일 누적, 전일)
  - **기상특보** 현황 (경보/주의보/예비특보, 시군 목록)
  - **예측** — 향후 강수 예측(읍면동 순위), 예측 분포 이미지
  - **특보 지도** 이미지
- **F1.2** 화면은 **휴대폰 최적화 + PC 모드 병행**(반응형).
- **F1.3** 각 자료에 **기준 시각**을 반드시 표시한다. 언제 자료인지 모르면 위험하다.
- **F1.4** 자동 갱신(폴링 또는 SSE). 갱신 시각을 화면에 표시.
- ❓미정: 표출 주기 — 항상 10분? 상황에 따라 가변?
- ❓미정: 과거 시점 조회(재현) 기능이 필요한가?

### F2. 감시 및 알림

- **F2.1** 조건을 감시해 **텔레그램으로 알린다.**
- **F2.2** 감시 대상
  - 시우량(초단기예측 RN1)이 기준(예 30mm)을 넘음
  - 기상특보 신규 발표 / 변경 / 해제
- **F2.3** **반복 알림 억제** — 같은 상황이 이어질 때 매번 울리지 않는다.
  시우량은 *최대치가 N mm 더 오를 때만* 다시 알린다.
- **F2.4** 조회 실패를 '상황 없음'으로 오인해 **헛알림을 보내지 않는다.**
- **F2.5** 알림에 특보 지도 이미지를 함께 보낸다.
- ❓미정: 수신 대상이 본인만인가, 단톡방인가? 단톡방이면 오보 위험 때문에
  *해제* 알림을 뺀다든가 하는 필터가 필요하다.

### F3. 참고 문서 열람

- **F3.1** 사진·PDF를 올려 두면 **웹 접속자가 볼 수 있다.**
  (예: 호우 피해현황 PDF를 통째로 올려 공유)
- **F3.2** 목록 + 미리보기 + 내려받기.
- **F3.3** 브라우저 안에서 PDF를 볼 수 있어야 한다(내려받기 강제 금지).
- ❓미정: 업로드 권한을 누가 갖나? 인증이 필요한가?
- ❓미정: 보관 기간·용량 상한

## 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 가용성 | 맥미니 상주. 재부팅 후 자동 시작. 죽으면 자동 재시작 |
| 응답 | 대시보드 첫 화면 2초 이내(캐시된 자료 기준) |
| 자료 신선도 | 화면에 표시된 기준 시각이 실제 자료 시각과 일치할 것 |
| 보안 | 외부 공개 시 인증 필요. API 키·토큰은 저장소에 없을 것 |
| 비용 | 기상청 API 호출을 아낀다 — 같은 자료를 여러 사용자가 볼 때 **서버가 한 번만** 받아 캐시 |

## 명시적으로 하지 않는 것 (범위 밖)

- **한글(HWP) 보고서 자동 작성** — macOS 불가. Windows 원본 프로젝트에 남긴다.
- 기상 예측 모델 자체를 만드는 일 — 기상청 산출물을 쓴다.
- 전국 서비스 — 경상남도만.

## 합의가 필요한 미정 항목 모음

착수 전에 아래를 정하면 재작업이 줄어든다.

1. 접근 범위 — 나만? 부서 내부? 외부 공개? (→ 인증 방식과 배포 방식이 갈린다)
2. 알림 수신처 — 개인 채팅 / 단톡방
3. 과거 시점 재현 기능 필요 여부
4. 문서 업로드 권한·보관 정책
5. 표출 주기와 자동 갱신 방식
