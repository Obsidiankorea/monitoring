# 06. AI와 함께 개발하는 절차

> 표준 관행(AGENTS.md 규약, 명세 주도 개발)을 이 프로젝트 크기에 맞게 줄인 것이다.
> 1인 프로젝트에 무거운 절차를 씌우면 지키지 않게 되므로, **꼭 필요한 것만** 남겼다.

Claude Code·Codex·Cursor 등이 공통으로 읽는다. Claude Code만 쓴다면

## 작업 절차: 명세 → 계획 → 구현 → 검증

명세 주도 개발(spec-driven development)의 축약판이다.

### 0단계 — 이 일에 명세가 필요한가?

> 판단 기준: **"에이전트가 내 의도와 다르게 해석하면 짜증 날 것 같은가?"**
> 그렇다면 명세를 쓴다. 아니면 그냥 시킨다.

오타 수정, 로그 문구 변경 같은 건 명세가 낭비다. 새 화면, 새 알림 조건,
데이터 모델 변경은 명세를 쓸 값어치가 있다.

### 1단계 — 명세 (무엇을·왜)

`docs/specs/<기능이름>.md`에 짧게:

```markdown
# 시군별 강수량 카드

## 왜
새벽에 휴대폰으로 열었을 때 "어디가 심한가"를 3초 안에 알아야 한다.

## 무엇을
- 18개 시군을 관제순으로, 1시간 강수량 내림차순 정렬 토글
- 각 행: 시군 / 1시간 / 당일누계 / 다우지점
- 기준 시각을 카드 머리에 표시

## 하지 않을 것
- 지도 표시 (별도 기능)

## 완료 기준
- [ ] 휴대폰 세로 화면에서 스크롤 없이 상위 6개 시군이 보인다
- [ ] 자료가 없을 때 '자료 없음'과 '조회 실패'가 구분돼 보인다
- [ ] 기준 시각이 실제 자료 시각과 일치한다
```

**완료 기준을 확인 가능한 문장으로** 쓰는 게 핵심이다. "잘 보인다"는 확인할 수 없다.

### 2단계 — 계획 (어떻게)

에이전트에게 명세를 주고 **먼저 계획을 말하게** 한다. 바로 코드를 쓰게 하지 않는다.
계획에서 잘못된 가정이 드러나면 그때 고치는 게 가장 싸다.

확인할 것: 어느 파일을 건드리나 · 기존 무엇을 재사용하나 · 새 의존성이 있나 ·
`docs/05-pitfalls.md`의 어느 항목에 걸리나

### 3단계 — 구현

- **한 번에 하나.** 여러 기능을 섞어 고치면 뭐가 깨졌는지 알 수 없다.
- 새로 알게 된 함정은 **그 자리에서 `docs/05-pitfalls.md`에 한 줄** 남긴다.
  나중에 정리하겠다고 미루면 사라진다.

### 4단계 — 검증

**"동작할 것입니다"는 검증이 아니다.** 실제로 돌린 결과를 남긴다.

- 외부 API를 붙였으면 **한 번 호출해 실제 응답**을 확인한다
- 화면을 만들었으면 **휴대폰 폭(375px)에서** 확인한다
- 알림을 만들었으면 **조건을 인위적으로 만들어** 발화시켜 본다
  (실제 채팅방으로 보내지 말고, 전송 직전 값을 찍어 확인)
- 확인하지 못한 부분은 **못 했다고 말한다**

## 결정 기록 (ADR)

되돌리기 어려운 선택은 `docs/decisions/NNN-제목.md`에 짧게 남긴다.

```markdown
# 003. 저장소로 SQLite를 쓴다

## 상황
단일 맥미니, 작성자 하나(수집기), 읽기 다수(웹).

## 결정
SQLite. 별도 DB 서버를 두지 않는다.

## 근거
- 배포 대상이 앱 하나로 유지된다
- 동시 쓰기가 없어 잠금 경합이 없다

## 뒤집어야 할 신호
- 여러 서버로 늘어남 / 쓰기가 초당 수십 건
```

몇 달 뒤 "왜 이렇게 했지?"에 답하기 위한 것이다. 길게 쓰지 않는다.

## 커밋

```
feat(dashboard): 시군별 강수량 카드 추가
fix(alerts): 조회 실패를 '특보 없음'으로 처리하던 문제

왜 바꿨는지 한두 줄. 특히 직관과 다른 선택을 했다면 이유를 남긴다.
```

## AI에게 일을 시킬 때 실전 요령

원본 프로젝트에서 효과가 있었던 것들이다.

1. **"확인해 줘"라고 명시한다.** 그냥 시키면 코드만 쓰고 끝낸다.
   "실제로 API를 한 번 불러서 응답 형태를 확인하고 알려줘"처럼.
2. **추측과 확인을 구분하게 한다.** "이건 확인한 거야, 추측이야?"라고 물으면
   대개 솔직하게 답한다.
3. **함정 문서를 먼저 읽히면** 같은 실수를 반복하지 않는다. `AGENTS.md`에
   "작업 전 읽을 문서" 표를 둔 이유다.
4. **화면 캡처를 붙여 주는 게 설명보다 빠르다.** 특히 레이아웃 문제.
5. **에이전트가 만든 것을 그대로 믿지 않는다.** 특히 숫자가 나오는 표는
   원자료와 한 번씩 대조한다. 원본 프로젝트에서 위 표와 아래 표의 같은 지점 값이
   달랐던 적이 있다(계산 경로가 둘이었다).
