# 03. 기상청 API 레퍼런스

> 원본 프로젝트에서 **실제로 호출해 확인한** 내용만 적었다. 공식 문서와 다른 부분은
> ⚠️로 표시했다 — 문서를 믿고 짠 코드가 빈 응답을 받은 사례가 여러 번 있었다.

## 호스트와 키 — 하나로 통일돼 있다

```
https://apihub-pub.kma.go.kr/api/...?...&authKey=<ORG_API_KEY>
```

**키는 기관용 하나(`ORG_API_KEY`)뿐이다.** 아래 API 전부가 이 키로 동작하는 것을
2026-08에 실제 호출로 확인했다. (예전에는 용도별 개인 키가 5개 있었고 호스트도
`apihub.kma.go.kr`였으나 전부 정리했다.)

⚠️ **호스트와 키는 짝이다.** 기관용 키는 `apihub-pub.kma.go.kr`에서만 동작한다.
구 호스트 `apihub.kma.go.kr`에 쓰면 403이다.
⚠️ 새 API를 붙일 때는 **활용신청이 되어 있어야** 한다. 미신청이면 403과 함께
본문에 `활용신청이 필요한 API 입니다`가 온다.

⚠️ **HTTP 200인데 본문이 에러 메시지인 경우가 있다.** `raise_for_status()`만으로는
못 걸러낸다. 본문에 인증 오류 문구가 있는지도 확인할 것.

## 인증

모든 요청에 `authKey=<ORG_API_KEY>`를 쿼리로 붙인다. 키는 `config/api_keys.txt` 참고.

## 1. 기상특보 — `wrn_now_data.php`

```
GET https://apihub-pub.kma.go.kr/api/typ01/url/wrn_now_data.php
    ?fe=f&tm=&disp=0&help=0&authKey=<ORG_API_KEY>
```

| 파라미터 | 뜻 |
|---|---|
| `tm` | 비우면 **현재 발효 중**. `YYYYMMDDHHMM`이면 과거 조회 |
| `disp=1` | 특보현황(행 데이터) |
| `help=1` | 응답 끝에 **구역 코드표** 포함 (구역 목록 확인용) |

**응답**: `=`로 구분된 행. 인코딩 **euc-kr**.

주요 컬럼 (인덱스):

| idx | 이름 | 값 예 |
|---|---|---|
| 1 | `REG_UP_KO` 상위구역 | `경상남도`, `합천군`, `남해동부전해상` |
| 3 | `REG_KO` 구역명 | `창원시`, `합천군중부`, `남해동부안쪽먼바다` |
| 4 | `TM_FC` 발표시각 | `202608161010` |
| 5 | `TM_EF` 발효시각 | `202608161010` |
| 6 | `WRN` 특보명 | `호우`, `강풍`, `풍랑` (이미 한글) |
| 7 | `LVL` 레벨 | ⚠️ `경보` 또는 **`주의`** — `주의보`가 아니다 |
| 8 | `CMD` 명령 | `발표`/`변경`/`해제`/`연장`/**`예비`** |
| 9 | `ED_TM` 해제시각 | |

### ⚠️ 함정

- **레벨이 `주의`다.** `주의보`로 매칭하면 표가 통째로 빈다.
- **폭염은 3단계**다: 주의보 → 경보 → **중대경보**. 레벨을 뗄 때 `중대경보`를
  **가장 먼저** 떼야 한다. 안 그러면 `폭염중대경보`의 특보명이 `폭염중대`로 파싱돼
  `폭염`과 매칭되지 않아 **통째로 누락**된다.
- **예비특보가 같은 응답에 섞여 온다.** `CMD == '예비'`인 행이 예비특보다.
- **예비특보의 `TM_EF`는 시각이 아니라 시간대 코드**다:

  | 코드 | 뜻 | 코드 | 뜻 |
  |---|---|---|---|
  | `0259` | 새벽(00~03시) | `1159` | 오전(09~12시) |
  | `0559` | 새벽(03~06시) | `1459` | 낮(12~15시) |
  | `0859` | 아침(06~09시) | `1759` | 늦은 오후(15~18시) |
  | `2059` | 저녁(18~21시) | `2359` | 밤(21~24시) |
  | `0558` | 새벽(00~06시) | `1158` | 오전(06~12시) |
  | `1758`/`1458` | 오후(12~18시) | `2358` | 밤(18~24시) |

  그대로 찍으면 `11:59`라는 없는 시각이 된다. 분이 58/59인 값만 코드라 구분된다.
- **아직 발효 전인 특보도 함께 준다.** 오늘 16시 발표, 내일 11시 발효인 것이
  섞여 온다. 집계에는 `TM_EF ≤ 기준시각`만 넣고, 나머지는 '발효 예정'으로 따로 표기.
- **조회 실패를 '특보 없음'으로 처리하지 말 것.** 감시에서 이걸 뭉개면
  *전부 해제 → 다음 분에 전부 신규* 헛알림이 난다. 실제로 겪었다.

## 2. 강수량·기온 (정시) — `awsh.php`

```
GET https://apihub-pub.kma.go.kr/api/typ01/url/awsh.php?tm=YYYYMMDDHH00&help=0&authKey=<ORG_API_KEY>
GET .../awsh.php?tm=...&var=TA&...      # 기온만
```

**컬럼 순서** (공백 구분): `YYMMDDHHMI STN TA WD WS RN_DAY RN_HR1 HM PA PS`
→ `RN_DAY`는 `parts[5]`, `RN_HR1`은 `parts[6]`.

`var=RN`으로 부르면 컬럼이 달라진다: `… RE_SUM RE_QCM RN_DAY(idx4) RN_DAY_MI RN_HR1(idx6) …`

### ⚠️ 함정

- **정시(매시 00분) 자료만 있다.** `0550` 같은 분단위를 넣으면 빈 응답이다.
  06시 직후엔 06:00 자료가 아직 없을 수 있어 **직전 정시로 폴백**해야 한다(최대 3시간).
- **`RN_DAY`는 자정에 전날 총량을 보여주고 01시에 0으로 리셋된다.** 이 성질을 이용하면:
  - 당일 누적 = 기준시각의 `RN_DAY`
  - 전날 총량 = **기준일 `0000`시의 `RN_DAY`**
- 음수(-9, -99 등)는 결측이다.
- 타임아웃이 잦다. 30초 + 1회 재시도 권장.

## 3. 최근 매분자료 — `nph-aws2_min`

```
GET https://apihub-pub.kma.go.kr/api/typ01/cgi-bin/url/nph-aws2_min?tm2=YYYYMMDDHHMI&stn=0&authKey=<ORG_API_KEY>
```

정시 자료(awsh)는 매시 00분에만 나와서, **긴급 상황에서 최근 1시간이 비어 있다.**
이걸로 정시 이후 구간을 메운다.

**컬럼**: `YYMMDDHHMI STN … RN-15m(10) RN-60m(11) RN-12H(12) RN-DAY(13)`. 결측 -50 이하.

활용:
- `RN-60m` = 그 시각까지 1시간 강수 → 정시 이후의 '시간대별' 칸
- `RN-DAY` 증분 = 부분 구간(예 21:00~21:10)
- 금일 누계도 이 `RN-DAY`로 갱신하면 정시 지연이 보강된다

## 4. 초단기예측 격자 — `nph-dfs_vsrt_grd` ★

```
GET https://apihub-pub.kma.go.kr/api/typ01/cgi-bin/url/nph-dfs_vsrt_grd
    ?tmfc=YYYYMMDDHHMI&tmef=YYYYMMDDHHMI&vars=RN1&authKey=<ORG_API_KEY>
```

**응답**: 콤마/개행으로 구분된 **37,697개 float** = 동네예보 격자 149 × 253 (약 5km).
`-99`는 결측/무강수.

인덱스 = `(Y - 1) * 149 + (X - 1)`. 읍면동 ↔ XY 매핑은 `data/gyeongnam_grids.json`.

| 요소 | 뜻 |
|---|---|
| **RN1** | **선행 1시간 누적 강수량(mm)** |
| T1H | 기온 | PTY | 강수형태 | SKY | 하늘상태 | LGT | 낙뢰 |

### ⚠️ 함정 (중요)

- **RN1은 1시간 누적이라 값이 1시간 단위로만 바뀐다.** `tmfc=13:10`일 때
  `tmef` 13:40·14:10이 완전히 같은 값이다. 10분 간격으로 부르면 같은 격자를
  6번 받는 셈 → **선행 1시간 구간당 1회만 조회**하고 재사용할 것.
- **누적을 낼 때 칸을 더하면 안 된다.** 20분 간격이면 같은 1시간 값이 3번 반복되므로
  3배가 된다. **1시간 구간마다 한 번씩만** 더할 것.
- **값이 정수 mm로 양자화**돼 온다(실측: 서로 다른 값 27가지). 상위권에서 30·50에
  동률이 쏟아지므로, 순위를 매길 땐 시우량(peak)이 아니라 **누적**으로 정렬할 것.
- **아직 안 나온 `tmfc`를 주면 최신 발표분으로 대체해 돌려준다.** 발표 여부를
  판정하려면 `target`과 `target-10분`을 **같은 tmef로** 받아 비교한다(다르면 발표됨).
  단, **무강수면 연속 발표분이 완전히 같아** 구분할 수 없다(그땐 알릴 것도 없다).
- 실측 발표 지연: **발표시각 +2~8분**.
- 발표분을 고정(`tmfc` 지정)해 읽으면 **막 올라오는 중에 빈 격자**가 오기도 한다.
  0이 나오면 `tmfc` 없이(=최신분) 한 번 더 읽어 확인할 것.

## 5. 일자료 (기간+전 지점) — `sfc_aws_day.php`

```
GET https://apihub-pub.kma.go.kr/api/typ01/url/sfc_aws_day.php
    ?obs=ta_max&tm1=YYYYMMDD&tm2=YYYYMMDD&stn=0&authKey=<ORG_API_KEY>
```

**기간 + 전 지점을 한 번에** 준다 — 3일치 전국이 1회 조회 0.6초.
필드: `TM STN LON LAT HT VAL(+지점명)`.

- `obs=ta_max` 최고기온 / `ta_min` 최저기온 / `rn_day` 일강수량
- ⚠️ `obs`에 **체감온도 요소는 없다**(`wc_max`/`ta_wc` 모두 0행).
- ⚠️ `stn`을 `:`로 나열하는 문법은 **동작하지 않는다**(`awsh.php`도 마찬가지).
  `stn=0`으로 전 지점을 받아 걸러 쓸 것.

## 6. 동네예보 통보문 — `getWthrSituation`

```
GET https://apihub-pub.kma.go.kr/api/typ02/openApi/VilageFcstMsgService/getWthrSituation
    ?pageNo=1&numOfRows=10&dataType=XML&stnId=159&authKey=<ORG_API_KEY>
```

`stnId`: 108 전국 / 159 부산·울산·경남 / 156 광주전남 / 143 대구경북 / 184 제주 …

XML `<wfSv1>`에 본문, `<tmFc>`에 발표시각. **현재분만 준다**(과거 조회 불가).

구조: `□ (종합) …` + `○ (오늘, 14일) …○ (내일, 15일) …`

### ⚠️ 함정

- **항목이 한 줄로 이어붙어 온다.** `○` 앞에서 끊어야 날짜별로 읽을 수 있다.
- **날씨가 이어지면 항목을 묶어서 준다**: `○ (모레~글피, 16~17일) …`,
  `○ (내일~글피, 15~17일) …`. 날짜별로 나눌 때 **걸친 날짜 전부에 같은 내용**을 넣어야 한다.
- 항목 안에 줄바꿈이 섞여 오기도 한다(전국 통보문은 한 항목이 4줄).

## 7. 단기예보 육상 — `fct_afs_dl.php`

```
GET https://apihub-pub.kma.go.kr/api/typ01/url/fct_afs_dl.php?reg=&tmfc=&authKey=<ORG_API_KEY>
```

- `reg=`를 비우면 **전국 1회 조회**(0.18MB, 0.4초).

## 8. 특보 지도 이미지 — `nph-wrn7`

```
GET https://apihub-pub.kma.go.kr/api/typ03/cgi/wrn/nph-wrn7
    ?out=0&tmef=0&city=1&name=0&tm=YYYYMMDDHHMI
    &lon=128.3&lat=35.3&range=90&size=400&wrn=R&authKey=<ORG_API_KEY>
```

| 파라미터 | 뜻 |
|---|---|
| `wrn` | 특보종류 필터. ⚠️ **콤마 구분만 동작**(파이프 `\|`는 빈 이미지) |
| `tmef=0` | **발효기준** — 제목 `…기준`, 그 시각 발효 중인 것만 |
| `tmef=1` | 발표기준 — 제목 `…이후`, 발효 예정까지 포함 |
| `lon/lat/range` | 경남만 보려면 `128.3 / 35.3 / 90` (실측으로 맞춘 값) |
| `city=1` | 시군 경계 표시 |

**특보종류 코드**: `W`강풍 `R`호우 `C`한파 `D`건조 `O`해일 `N`지진해일 `V`풍랑
`T`태풍 `S`대설 `Y`황사 `H`폭염 `F`안개 `K`열대야

### ⚠️ 함정

- **예비특보는 이 API에 없다.** 지도만 보면 예비특보가 통째로 빠진다.
  예비특보 지도는 날씨누리에서 받아야 한다(아래 10번).
- `tmef=1`로 두면 *내일 발효* 특보가 오늘 지도에 칠해진다. 기본은 `0`을 권한다.
- 풍랑(`V`)은 해상 특보라 경남 타이트 프레임(range=90)으로는 잘린다. 전국 뷰로 볼 것.

## 9. 예측 분포도 이미지

### QPF (융합 초단기예측) — `nph-qpf_ana_img`

```
GET https://apihub-pub.kma.go.kr/api/typ03/cgi/dfs/nph-qpf_ana_img
    ?eva=1&tm=<발표시각>&qpf=B&ef=<분>&map=HR&grid=2&legend=1&size=800&authKey=<ORG_API_KEY>
```

`qpf=B` 융합 / `K` 모델 / `M` 레이더외삽. **단위 mm/h(강수강도)**, 10분 해상도.

### 초단기예보 분포도 — `nph-dfs_vsrt_ana2`

```
GET https://apihub-pub.kma.go.kr/api/typ03/cgi/dfs/nph-dfs_vsrt_ana2
    ?data0=GEMD&data1=RN1&tm_fc=<발표>&tm_ef=<대상>&dtm=H0&map=G1
    &mask=M&color=E&size=900&…&authKey=<ORG_API_KEY>
```

**단위 mm(1시간 강수량)**, 예측 표(RN1 격자)와 **같은 산출물** → 표와 그림이 일치한다.

### ⚠️ 공통 함정

- **두 API 모두 지역 크롭이 안 된다.** `stn`·`zoom_*`·`lon/lat`을 줘도 무시하고
  전국 이미지를 준다. **전국을 받아 PIL로 직접 잘라야** 한다. `size`만 배율을 바꾼다.
- **이미지 크기가 달라 크롭 박스를 공유할 수 없다.** QPF는 **835×820**,
  분포도는 **901×1551**. 영점도 배율도 다르다 — 소스별로 박스를 따로 저장할 것.
- 분포도는 **tm_fc·tm_ef 모두 KST**다(가이드 문서에 UTC라 적힌 건 다른 API 얘기).
- 분포도는 **10분 단위가 없다.** 값이 1시간 단위로만 바뀌고 버킷 경계가 정시다.
- QPF와 분포도는 **색상표가 완전히 다르다**(겹치는 색 0종). 범례를 따로 둘 것.

## 10. 날씨누리 특보 지도 (예비특보 포함)

기상청 API에는 **예비특보 지도가 없어서** 홈페이지에서 받는다. 브라우저 없이 HTTP 2번:

```
① GET https://www.weather.go.kr/w/wnuri-fct2021/weather/warning.do
   → HTML 조각. 여기에 현재 파일명이 있다 (세션·쿠키 불필요)
② GET https://www.weather.go.kr/w/repositary/image/wrn/img/<파일명>
```

파일명 규칙: `KTKO50_<발표시각>_108_<지방청>.png` = 특보 발효현황
`KTKO50_<발표시각>_108_<지방청>b.png` = **예비특보** (끝에 `b`)

### ⚠️ 함정

- **최신 것만 존재한다.** 과거 파일명을 만들어 넣으면 PNG가 아니라 HTML이 온다.
  파일명을 **추측하지 말고 반드시 ①로 알아낼 것**. 과거 재현은 불가능하다.
- ⚠️ **`https://www.weather.go.kr/w/special-report/overall.do`는 쓸 수 없다.**
  HTML에 `KTKO`도 `warning.do`도 등장하지 않는다(배너 이미지뿐). 지도는 JS가 따로 불러온다.
- `alt` 속성에 한글 기준시각 설명이 들어 있어 그대로 표시에 쓸 수 있다.

## 11. 텔레그램 봇 (참고)

```
POST https://api.telegram.org/bot<토큰>/sendMessage   { chat_id, text }
POST https://api.telegram.org/bot<토큰>/sendPhoto     { chat_id, caption } + multipart photo
GET  https://api.telegram.org/bot<토큰>/getUpdates    ← chat_id 찾기
GET  https://api.telegram.org/bot<토큰>/getMe         ← 토큰 확인
```

### ⚠️ 함정

- **`parse_mode`를 쓰지 말 것.** 특보 지역명에 `(`, `~`, `.`이 섞여 있어
  Markdown/HTML 파싱을 켜면 400으로 전송이 통째로 실패한다.
- **chat_id는 봇 username(@…bot)이 아니다.** 개인=양수, 그룹=`-100…` 음수.
  `@이름` 형태가 통하는 건 공개 채널뿐이다.
- `getUpdates`는 **봇이 받은 메시지만** 보여준다. 봇에게 먼저 말을 걸어야 하고,
  대기열은 계속 남아 있지 않다(확인되면 빠지고 24시간 지나면 사라짐).
- 텍스트 상한 4096자, 사진 캡션 1024자. 같은 채팅 **분당 20건** 제한 →
  변경이 많아도 한 메시지로 묶을 것.
- ⚠️ 이 요청은 **URL에 봇 토큰이 실려 나간다.** 기상청 API용으로 SSL 검증을 꺼 뒀더라도
  **텔레그램만은 검증을 켤 것**(중간자 공격에 토큰이 노출된다).
