# 경남 기상 대시보드

경상남도 18개 시군의 강수·특보·초단기예측을 한 화면에 표출하는 재난상황실 대시보드.
맥미니 상주 서버 하나로 수집·저장·표출을 모두 한다.

## 실행

폴더째 옮겨 놓고 실행 파일 하나만 누르면 된다. 가상환경 생성·의존성 설치·키 배치·
포트 찾기·브라우저 열기를 알아서 한다.

| | |
|---|---|
| **맥** | `run.command` 더블클릭 (또는 터미널에서 `./run.command`) |
| **윈도** | `run.bat` 더블클릭 |

띄우면 이 순서로 간다.

1. **새 버전이 있는지 확인하고 물어본다.** 있으면 무엇이 바뀌는지 보여 준다.
   ⚠️ **10초 안에 답이 없으면 아니오다.** 벽면 PC 는 부팅하며 스스로 뜨는데,
   아무도 없는 새벽에 물음표에 걸려 화면이 안 뜨면 안 된다. 받기가 실패해도
   멈추지 않는다 — 지금 버전으로라도 뜨는 게 낫다.
   의존성 설치보다 **먼저** 한다. `requirements.txt` 가 함께 바뀔 수 있어서다.
2. 가상환경·의존성·키·포트를 챙긴다.
3. 서버가 응답하면 **웹앱 창**으로 연다 — 주소창도 탭도 없는 창(`--app`).
   상황실 화면이라 주소창이 보일 이유가 없고, 실수로 다른 데로 옮겨 가지도 않는다.
   창 아이콘은 화면의 파비콘(비바람)을 그대로 쓴다.
   윈도는 크롬 → 엣지 순으로 찾고(엣지는 윈도 10 에 늘 있다), 맥은 크롬을 찾는다.
   없으면 기본 브라우저로 그냥 연다.

처음 실행은 의존성을 받느라 1~2분, 뜬 뒤에도 자료를 받느라 화면이 채워지기까지
10~40초 걸린다. 받아 둔 것은 `data/` 에 남으므로 두 번째부터는 바로 뜬다.

포트를 바꾸려면 `PORT=9000 ./run.command`, 다른 기기에서도 보려면 `HOST=0.0.0.0`.
포트가 이미 쓰이고 있으면 다음 빈 포트를 알아서 찾는다 — **수집기가 둘 돌면
기상청 호출이 두 배가 되므로** 같은 포트에 겹쳐 띄우지 않는다.

### 직접 띄우기

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
mkdir -p config && cp handoff-mac/config/api_keys.txt config/   # 키는 저장소에 없다
.venv/bin/python -m app.main
```

윈도는 `.venv\Scripts\python.exe -m app.main`.

## 구조 — 수집과 표출을 분리한다

**화면을 열 때 기상청을 부르지 않는다.** 수집기가 주기적으로 받아 SQLite에 넣고,
웹은 저장된 것을 읽기만 한다. 접속자가 몇이든 기상청 호출은 한 번이고,
API가 죽어도 마지막 정상 자료가 화면에 남는다.

```
기상청 API ──▶ app/collectors/ ──▶ SQLite(data/gnweather.db) ──▶ /api/* ──▶ 화면
               (APScheduler)          + data/cache/qpf/*.png
```

| 파일 | 하는 일 |
|---|---|
| `app/config.py` | 키 로드, 수집 주기, 화면 폴링 기본값 |
| `app/kma.py` | 기상청 호출 한 곳. euc-kr, 타임아웃, 재시도, 200인데 본문이 오류인 경우 |
| `app/db.py` | 스키마. `quality` 열이 무강수·결측·조회실패를 가른다 |
| `app/domain/regions.py` | 관제순, 대표지점, 특보구역 세분화, 강원 고성 배제, 중대경보 파싱 |
| `app/collectors/rain.py` | AWS 정시(`awsh`) + 매분 보강(`nph-aws2_min`) |
| `app/collectors/forecast.py` | 초단기예측 격자 RN1(`nph-dfs_vsrt_grd`) |
| `app/collectors/alerts.py` | 기상특보(`wrn_now_data`) |
| `app/collectors/shortfc.py` | 단기예보 격자(`nph-dfs_shrt_grd`) — 1시간 강수량(PCP), 오늘~모레 |
| `app/collectors/qpf.py` | 예측 분포 이미지(`nph-qpf_ana_img`) — 전국을 받아 PIL로 경남만 크롭 |
| `app/collectors/grid_rain.py` | 경남 지도 — 500m 격자(NetCDF)·실황 5km 를 받아 경남 bbox 만 저장 |
| `app/gridstore.py` · `app/gridview.py` | 격자 프레임 저장(uint16 gzip 파일) · 층 풀기·합계·지연·시군 통계 |
| `app/domain/gridproj.py` | 격자 투영(500m 타원체·5km 구면 람베르트, UTM-K) |
| `app/bangjae.py` | 스방(경남 스마트 통합 방재시스템) 호출 — 로그인, 조회 시각 규칙 |
| `app/collectors/bangjae_rain.py` | 스방 시군 평균·다우지점 + 지점별 시간강우량 |
| `app/maint.py` | 저장공간 재기·정리(보관 기간) |
| `app/demo.py` | 데모 사례 — 실제 호우 때를 되돌려 띄운다 |
| `app/queries.py` | DB 읽기. 결측을 0으로 더하지 않고 뺀 시간 수를 함께 준다 |
| `app/main.py` | FastAPI + 스케줄러 + `/api/*` |
| `app/web/static/index.html` | 화면 |

## 수집 주기

| 자료 | 주기 | 근거 |
|---|---|---|
| 특보 | 1분 | 발표 리듬이 없다. 아무 때나 나온다 |
| 강수량 | 10분 | 정시 자료 + 최근 구간은 매분자료로 보강 |
| 초단기예측 | 10분 | 발표 주기 10분, 실제 업로드는 발표 +2~8분 뒤 |
| 예측 분포 이미지 | 10분 | 발표분이 바뀔 때만 실제로 받는다 |
| 스방 강수량 | 10분 | 기상청과 같은 리듬. 다른 서버라 따로 돈다 |
| 단기예보 격자 | 10분 | 발표는 3시간마다(02·05·…·23시). 다 받은 발표분은 다시 부르지 않는다 |
| 경남 지도 500m(`grid`) | 10분 | 15분·60분·일강수 NetCDF 셋. 5분마다 만들어지고 +5분 남짓 걸린다 |
| 경남 지도 실황 5km(`odam`) | 10분 | 10분 발표 |

화면의 갱신 주기는 **이것과 별개**다. 메뉴바에서 활성 창의 자료별로 따로 정하고,
바꿔도 기상청 호출량은 변하지 않는다 — 화면은 DB만 읽는다.

## API

| 경로 | 내용 |
|---|---|
| `GET /api/rain?hours=N&src=kma\|bangjae` | 지점별 시간대별 강수량 + 누적 (`bad`=결측 시간 수) |
| `GET /api/forecast?hours=N` | 읍면동·시군 예측 순위 |
| `GET /api/alerts` | 특보 현황(집계는 시군 수) |
| `GET /api/minute?n=N` | 지금 오는 비 — 15분·60분 강수량 상위 N곳 |
| `GET /api/qpf` · `/api/qpf/{tmfc}/{ef}.png` | 예측 분포 프레임 목록·이미지 |
| `GET /api/short` | 단기예보 — 권역·시군별 예상강수량 격자 분포(오늘~모레), 직전 발표 대비 |
| `GET /api/grid/meta` | 경남 지도 — 층마다 기준시각·지연, 격자 틀, 지도 설정 |
| `GET /api/grid/{층}?tm=&test=` | 격자 한 장(0.1㎜ uint16, gzip). 층 = `obs15`·`obs60`·`obsday`·`odam`·`vsrt+1`~`vsrt+6`·`shrt_today`·`shrt_tomorrow` |
| `GET /api/grid/sigun?layer=&tm=&test=` | 시군별 최대(+그 칸의 읍면동)·평균 |
| `GET /api/grid/geo/{파일}` · `PUT /api/settings/map` | 경계·칸 지도 · 지도에서 고른 층 |
| `GET /api/bangjae` | 스방 시군 **평균** 강수량 + 시군별 다우지점 |
| `GET /api/storage` · `POST /api/storage/cleanup` | 저장공간 현황 · 묵은 자료 지우기 |
| `PUT /api/settings/retention` | 보관 기간 |
| `GET /api/demo` · `/api/demo/{slug}` | 데모 사례 목록 · 꾸러미 |
| `GET /api/status` | 수집기 상태 + 발표 지연 통계 |
| `GET /api/settings` · `PUT /api/settings/qpf` | 예측 이미지 간격·선행시간 |
| `POST /api/refresh/{kind}?force=true` | 수동 조회 — 주기와 무관하게 실제로 다녀온다 |

## 배치파일 인코딩 — 건드리지 말 것

`run.bat` 은 **CP949(한국어 ANSI)** 로 저장되어 있다. `.gitattributes` 의 `*.bat -text`
로 git 이 손대지 못하게 못 박아 두었다.

⚠️ **UTF-8 로 저장하면 실행이 중간에 멈춘다.** cmd 는 배치파일을 콘솔 코드페이지(한국어
   윈도는 949)로 읽는다. 글자가 깨지는 데 그치지 않고, 깨진 바이트가 파싱까지 어긋나게
   해서 어느 줄에선가 조용히 죽는다. 실제로 그렇게 멈췄다.
⚠️ 파일 첫머리에서 `chcp 949` 로 콘솔을 못 박는다. UTF-8(65001) 터미널에서 부르면
   CP949 파일이 다시 깨지기 때문이다.
⚠️ `—`(em dash, U+2014)는 CP949 에 **없다.** 배치파일에는 쓰지 않는다.

git 이 뱉는 커밋 제목만은 UTF-8 이라 따로 처리한다. `i18n.logOutputEncoding=cp949` 는
제목에 CP949 에 없는 글자가 하나라도 있으면 **그 줄을 통째로 포기**하므로, 파워셸로
읽어 그런 글자를 바꿔 찍는다. 그때 두 가지를 조심한다 —
큰따옴표 안에서는 cmd 가 `^` 를 처리하지 않으므로 `^|` 가 아니라 `|` 를 쓰고,
파워셸이 `@{u}` 를 해시테이블로 읽으므로 `'HEAD..@{u}'` 로 묶는다.

## 과거를 얼마나 채워 두는가

수집기는 **화면이 고른 구간만큼만** 과거를 받는다(`rain_depth` 설정, 기본 26시간).
`/api/rain?hours=N` 이 들어오면 그만큼 깊이를 올리고 그 자리에서 한 번 받아 온다.
화면은 `missing`(아직 한 줄도 안 받은 시각 수)이 0이 될 때까지 몇 번 더 물어본다.

⚠️ 이게 없을 때는 **'2일'을 골라도 26시간 앞이 영원히 비어 있었다.** 그래프 왼쪽이
   통째로 빈 채였고, 다음 주기가 와도 채워지지 않았다 — 수집기가 26시간만 보기 때문이다.

⚠️ 오래된 시각이 빈 응답으로 오면 **결측으로 적어 둔다.** 그냥 넘기면 행이 하나도
   안 남아 매 주기마다 영영 다시 묻는다(기상청에 그 자료가 없는 것뿐인데).

## 업데이트

배포처는 **GitHub 하나**다. 상주 서버(NAS)가 없어도, 각 PC 가 저장소를 클론해 두었으면
`설정 → 업데이트`에서 단추 한 번으로 최신 코드를 받는다. 속은 `git pull` 이다.

| | |
|---|---|
| `GET /api/update` | 지금 버전 · 원격에 몇 개 밀렸는지 · 손댄 파일이 있는지 |
| `POST /api/update/pull` | 받아 온다 |
| `POST /api/update/restart` | 스스로 끝난다. 실행 스크립트가 다시 띄운다 |

⚠️ **덮어쓰지 않는다.** `--ff-only` 로만 당긴다. 그 PC 에서 손댄 파일이 있으면 합치기를
   시도하다 어중간한 상태로 남는 대신 **실패하고 이유를 그대로 보여 준다.** 현장 PC 가
   반쯤 병합된 코드로 도는 것보다 안 받는 편이 낫다.
⚠️ **받았다고 바로 바뀌지 않는다.** 화면(`index.html`)은 새로고침이면 되지만 파이썬
   코드는 프로세스를 다시 띄워야 한다. 무엇이 바뀌었는지 보고 필요할 때만 물어본다.
⚠️ **확인 실패를 '최신'으로 읽지 않는다.** 모르는 것과 최신은 다르다 — 인터넷이 막힌
   내부망 PC 에서 '최신입니다'라고 적으면 거짓말이 된다.

⚠️ **첫 한 번은 손으로 받아야 한다.** 이 기능이 들어오기 전 판에는 업데이트 갈피가
   없기 때문이다. 이미 깔린 PC 에서는 `git pull` 을 한 번 돌리고 `run.bat` 을 다시
   누르면, 그 뒤로는 화면에서 받을 수 있다.

`run.bat`·`run.command` 는 서버가 **종료 코드 42** 로 끝났을 때만 다시 띄운다.
다른 코드로 끝나면(닫기·오류) 그대로 멈춘다 — 오류로 죽는 서버를 무한히 되살리면
무엇이 잘못됐는지 알 수가 없다.

## 저장공간

`설정 → 저장공간`에서 지금 얼마나 쌓였는지 보고 보관 기간을 정한다.
DB 한 파일과 예측 분포 이미지 캐시 두 군데에 쌓이는데 **이미지가 훨씬 빨리 자란다**
(한 발표분이 수십 장, 10분마다 새 발표분). 매일 새벽 4시 20분에 한 번 정리하고,
`지금 정리`로 즉시 돌릴 수도 있다. 되돌릴 수 없으므로 **오늘 것은 어떤 설정에서도 남긴다.**

## 판 대비 — 모니터마다 다르다

⚠️ **같은 색이 화면마다 다르게 보인다.** 맥에서는 바탕 `#090D13` 과 판 `#111823` 이
또렷이 갈라지는데, 흔한 윈도 모니터에서는 둘 다 '까만색'으로 뭉개져 판의 경계가
사라진다. 감마와 색역이 달라서다. 코드에 한 값을 박아 두면 어느 한쪽에서는 반드시
틀리므로, 보는 사람이 자기 화면에서 맞추도록 열어 뒀다.

`설정 → 화면 꾸미기`

| 조절기 | 하는 일 |
|---|---|
| **판 대비** | 바탕을 어둡게 밀고 판을 조금 들어 올린다. 테두리도 함께 세운다 |
| 바탕색 · 판 색 | 직접 지정. `✕` 를 누르면 자동으로 돌아간다 |

판을 크게 밝히지 않는 까닭은 글자가 그 위에 얹히기 때문이다 — 본문 대비가 같이
흔들린다. 끝까지 올려도 `#E8EEF6` 글자의 명암비는 15.5:1 → 13:1 로, 기준(7:1)보다
한참 위다. 밝은 테마는 판이 이미 흰색이라 더 들 곳이 없어 바탕만 민다.

⚠️ 대비 0은 **손대지 않은 것과 완전히 같아야 한다.** 판 계열을 판 색에서 늘
   계산하면 그게 깨진다 — 기본 토큰들이 판 색을 그냥 밝힌 값이 아니라 색조가
   조금씩 다르기 때문이다(계산하면 `#1E2836` 이 `#222832` 로 나왔다). 그래서 판 색을
   직접 고르지 않았으면 기본 토큰을 같은 만큼만 들어 올린다.

## 편집모드 — 글자 크기를 모음마다

메뉴바 오른쪽 `편집` 을 켜면 판 안의 **글자 모음**에 우클릭해 그 모음만 키우고
줄일 수 있다(70~220%, 10%씩). `Esc` 또는 `편집 중` 을 다시 눌러 나온다.

**판 전체가 아니라 모음마다다.** 벽에서 키우고 싶은 것은 판 하나가 통째가 아니라
그 안의 한 덩어리다 — 시군명만 키우고 싶을 때가 있고, 시간별 강수량만 키우고
싶을 때가 있다. 판을 통째로 키우면 자리를 먹어 오히려 보이는 줄 수가 줄어든다.

**표에서는 열이 단위다. 칸이 아니다.** 한 열은 통째로 같은 성격이라 한 시군만
키우는 일은 없다. 머리글도 제 열에 딸려 간다 — `다우지점` 은 시군명 열의 머리글이고
`누적 12시간` 은 강수량 열의 머리글이다. 그 열 어디를 눌러도 열이 통째로 바뀐다.

| 판 | 모음 |
|---|---|
| 강수 타임라인 | 판 전체 · **시군·지점명 열** · **누적 강수량 열** · **시간별 강수량 열** · **합계 열** |
| 예측 분포 재생 | 판 전체 · 판 머리글 · 시각 시계 · 발표 딱지 · 범례 |
| 예측 상위 시군 | 판 전체 · 판 머리글 · 시각 눈금 · 시군 칸 |
| 지금 오는 비 | 판 전체 · 판 머리글 · 15분 열 · 60분 열 |

우클릭한 자리에서 **제일 좁은 모음**을 집는다. 빈 자리를 누르면 `판 전체` 다.
중첩은 안쪽이 이긴다 — `판 전체` 를 120%로 두고 `시군·지점명 열` 만 145%로 둘 수 있다.

⚠️ **무엇이 바뀌는지 물들여 보인다.** 편집 중 마우스를 올리면 그 모음 **전부**가
   점선으로 물든다(메뉴가 열려 있는 동안에는 붙잡아 둔다). 예전에는 `:hover` 로
   테두리를 둘러서 **마우스 밑 한 칸만** 감쌌는데, 실제로는 열이 통째로 바뀌는데
   화면은 한 시군만 바뀔 것처럼 말했다 — 실제로 그렇게 읽혔다.
⚠️ 글자를 키우면 한 화면에 드는 시군이 줄어든다. 표는 넘치면 스크롤된다
   (`.panel > .body { overflow: auto }`). 줄 높이는 그 줄에 든 열 가운데 **제일 큰**
   배율을 따라 바닥·천장이 올라간다.

⚠️ **편집모드에서만 바뀐다.** 상황실 화면은 늘 켜져 있고 사람이 지나가며 건드린다.
   평소 우클릭은 하던 일(다우지점 얹기)을 그대로 해야 한다.
⚠️ 배율은 **규칙(`<style id="fs-css">`)으로 깐다.** 인라인 `style` 로는 안 된다 —
   표는 그릴 때마다 `innerHTML` 이 통째로 갈려 얹어 둔 style 이 날아간다.
⚠️ 타임라인은 글자를 **SVG 안에도** 그린다(봉우리 숫자·시각 눈금). CSS만 바꾸면
   그것들만 그대로 남으므로, 배율이 바뀌면 그 판을 다시 그린다.
⚠️ 판 안 글자에만 태운다. 메뉴바·설정창까지 커지면 정작 자료가 들어갈 자리를 먹는다.
⚠️ 줄 높이(`ROWH`)의 바닥·천장도 배율을 따라 올린다. 안 그러면 22px 줄에서 잘린다.
⚠️ `.panel::after` 에 '편집 중' 배지를 얹지 않는다. **거기는 '갱신 중' 띠가 이미 쓴다**
   (`inset: 0`). 얹었더니 그 inset 이 남아 판만 한 타원이 화면을 덮었다.
   편집 중이라는 것은 메뉴바 딱지와 판 테두리로 알린다.

## 종합 화면 구성

왼쪽에 강수 타임라인, 오른쪽 위에 예측 분포 재생, **오른쪽 아래**에 한 판이 더 들어간다.
그 자리에 무엇을 놓을지 `설정 → 종합 화면`에서 고른다.

| | 무엇 |
|---|---|
| 예측 상위 시군 | 초단기예측 격자에서 뽑은 읍면동 순위 |
| 지금 오는 비 | **15분·60분 강수량 상위** — 왼쪽 칸 15분, 오른쪽 칸 60분 |

`지금 오는 비`는 **기상청 매분자료(`nph-aws2_min`)만 쓴다.** 스방에는 분 단위가 없다.
15분치를 왼쪽에 두는 까닭은 그게 제일 빠르기 때문이다 — 60분치는 이미 지나간 한 시간을
담고 있어서, 막 쏟아지기 시작한 곳을 한 박자 늦게 알린다. 한 칸에 몇 곳을 세울지는
설정에서 정한다(4~16곳).

15분 칸 머리의 토글로 **`그대로 ↔ ×4`** 를 오간다. 둘은 같은 값의 다른 표기다 —
15분에 12.5㎜는 `×4` 로 보면 50㎜/h 이고, 이건 '시간당 50㎜의 기세'라는 뜻이지
한 시간에 50㎜가 온다는 말이 아니다(그 기세가 이어질 때의 값이다). 환산해서 봐야
60분치·특보 기준(시간당 ㎜)과 같은 자로 견줄 수 있고, 그대로 봐야 실제로 떨어진 양을
안다. 자료를 다시 받지 않고 표기만 바꾼다. `×4` 일 때는 색 단계도 60분 것을 쓴다.

⚠️ 두 값은 **각자 제 시각**을 찾는다. 낡은 수집기가 15분치를 안 넣고 덮어쓰면 그 시각의
   15분 칸이 통째로 비는데, 그때 화면을 비워 버리면 멀쩡한 직전 자료까지 사라진다.
   시각이 서로 다를 때만 각 칸 머리에 그 시각을 적는다.
⚠️ 막대 색은 두 칸이 **다른 단계표**를 쓴다. 같은 눈금으로 칠하면 15분에 8㎜
   (시간당 32㎜의 기세)가 옅은 색으로 묻힌다.

## 합계 칸

**숫자만 적는다.** 예전에는 값에 따라 칸을 색으로 채우고 특보 기준을 넘으면 테두리까지
둘렀는데, 바로 옆 막대가 이미 같은 말을 하고 있어 한 화면에서 같은 사실을 세 번 강조하는
꼴이었다. 결측 시간 수(`1h`)도 여기 적지 않는다 — 값인지 단위인지 읽히지 않았다.
알아야 할 때는 줄에 마우스를 올리면 나온다.

## 누적 막대 눈금

**늘 실제 값에 맞춘다.** 예전에는 특보 기준(110/180㎜)까지 눈금을 늘려 놨는데,
6.8㎜가 온 날은 막대가 3%밖에 안 차 아무것도 못 읽고 600㎜가 오면 넘쳤다.

**점선 두 줄도 실제 값에서 뽑는다.** 그때 화면에 있는 시군 누적값의 **중앙값**과
**상위 25%**(75분위)다. 값이 바뀌면 두 줄도 함께 움직인다.

⚠️ 예전에는 여기에 호우특보 12시간 기준(110/180㎜)이 박혀 있었다. **강수량은
   그보다 훨씬 유동적이다.** 900㎜ 온 날에는 두 줄이 막대 왼쪽 끝(12%·20%)에
   나란히 붙어 어느 시군도 가르지 못했고, 5㎜ 온 날에는 눈금 밖이라 아예 긋지도
   못했다. 어느 쪽이든 '기준'이 하는 일이 없었다. 분위수는 5㎜ 오는 날에도
   900㎜ 오는 날에도 늘 눈금 안에 있고, 늘 같은 것을 말한다 — **이 시군이 도
   전체에서 어디쯤인가.**
⚠️ 특보 예약색(주의보 노랑·경보 빨강)으로 긋지 않는다. 특보 기준이 아니기 때문이다.
   무강수라 중앙값이 0이면 그 줄은 긋지 않는다.

한 시군만 유독 길면 나머지가 다 뭉개진다. 그때는 눈금을 한 번 꺾어(broken axis)
뒷부분을 눌러 담고, 꺾은 자리에 **물결 자국**을 남긴다. 실측: 662㎜ 한 줄과
150㎜대 여럿이 섞였을 때 — 꺾기 전 142.5㎜는 21.5%였고, 꺾은 뒤 58.1%가 되어
서로 견줄 수 있게 됐다.

## 묶음 칸은 다른 자로 잰다

히트맵은 지난 시간을 `01~23` 처럼 묶어 한 칸에 담는다. **그 칸은 1시간 칸과
색조도 눈금도 다르다** — 시우량 램프는 청색(`--rain-*`), 묶음 램프는 청록(`--acc-*`).

⚠️ 같은 램프로 칠했을 때 **23시간 합계 64.5㎜가 1시간 50㎜와 똑같은 최고 단계**로
   앉았다. 오래 묶을수록 무조건 진해지는 바이어스다 — 색이 '많이 왔다'가 아니라
   '오래 묶었다'를 말하게 된다.

눈금은 **묶음 길이마다 따로, 그때 화면에 있는 실제 값에서** 잡는다(`ACC_FRAC`).
길이가 다른 두 묶음은 각자 제 눈금을 쓴다 — 한 눈금에 얹으면 긴 쪽이 늘 이긴다.
칸은 세로로 읽는 것이다(이 구간에서 어느 시군이 두드러지나). 실측(8.28. 사례):

```
23시간 묶음  최대 64.5㎜  →  64.5 가 그 열의 최고 단계
24시간 묶음  최대 105㎜   →  같은 64.5 는 중간 단계
```

0.5㎜를 최고 단계로 칠하지는 않으려고 눈금 바닥을 10㎜로 둔다.

## 데모 시연

비가 안 오는 날에는 화면이 온통 0.0 이라 무엇을 보여 주는 화면인지 알 수 없다.
`표시 → 데모 시연…`(또는 `설정 → 데모 시연`)에서 실제로 호우가 내렸던 때를
그대로 되돌려 띄운다. 화면을 점검할 때 쓴다 — 비가 안 오는 날에는 무엇이 고장 나도
0.0 이라 알 수가 없다.
보는 동안 화면 맨 위에 띠가 떠 있어 실황과 헷갈리지 않는다.

| 사례 | 내용 |
|---|---|
| 2026.8.28. 경남 호우 | 실측. 김해 율하 123.5㎜/일, 창원 111.0㎜/일 |
| 2026.8.28. 11시 — 한창 올 때 | 봉우리에서 끊은 화면. **그때 발표된 초단기예측이 함께 담겼다** |
| 2026.8.28. 호우 ×2 | **가상.** 같은 실측을 두 배로 키운 시연용 — 경보까지 걸린 화면 |

**강수량도 초단기예측도 실측이다.** 스방 265개소의 시간강우량과, 격자 API
(`nph-dfs_vsrt_grd`)로 받은 **그 시각의 실제 발표분**을 파일로 굳혀 둔다
(8.28. 11시 발표 → 남해 고현면 20㎜, 창원 진동면 20㎜).

담지 못한 것이 둘 있다.

- **특보.** 이력 API(`wrn_met_data.php`)가 이 키로 403 이라 과거 발표 내역을 받을 수 없다.
  그래서 담긴 강수량에 호우 기준(3시간 60/90㎜, 12시간 110/180㎜)을 적용해 **산출**하고,
  화면에 `산출`이라고 적어 발표 내역과 구분한다.
- **예측 분포 이미지.** `nph-qpf_ana_img` 는 과거 시각이 404 다. 최신분만 나온다.

예측이 안 담긴 사례에서는 **예측을 비운다** — 오늘 예측을 8월 자료 옆에 붙이면
통째로 거짓말이 된다. 분 단위 자료도 마찬가지라 `지금 오는 비` 판은 데모에서 비워 둔다.

⚠️ 스방은 며칠치만 남긴다. 그래서 사례를 **파일로 굳혀** 두고, 새 사례는 원본을 다시
   받는 대신 굳혀 둔 파일에서 잘라 만든다(`build_cut`).

## 스방 자료

기상청과 **다른 관측망**이다. 경남 자체 AWS 212개소에 기상청 것을 더해 **시군 평균**을
낸다. 기상청 값은 시군 대표지점 하나이므로 두 숫자는 뜻이 다르고, 실제로 자주 어긋난다
(고성 학림 500.5mm를 기상청 AWS는 아예 못 본다). 그래서 `obs_hourly` 에 섞지 않고
`bangjae_rain` 에 따로 쌓고, 화면에도 출처를 밝혀 적는다.
같은 응답(`dt090/list3`)에서 시군별 **다우지점**(그 시군에서 제일 많이 온 곳)도 함께
받는다 — 따로 부르면 두 값의 기준시각이 어긋난다.

### 지표가 자료원을 정한다

표 머리글을 누르면 `대표지점 → 다우지점 → 시군 평균`으로 돌아가고, **관측망도 같이 바뀐다.**

| 지표 | 자료원 | 왜 |
|---|---|---|
| 대표지점 | 기상청 56개소 | '시군 대표지점'은 기상청 관측망의 개념이다 |
| 다우지점 | **스방 265개소** | 후보가 다섯 배. 56개소로 고르면 창녕 계성 28.5㎜를 아예 못 본다 |
| 시군 평균 | **스방 265개소** | 56개소로는 창원이 5개소·진주가 3개소다. 그걸 시군 평균이라 부를 수 없다 |

스방 265개소면 창원 23·진주 18·합천 23개소가 되고, 다우지점은 스방이 스스로 내는
`rtu_area` 와 비가 온 모든 시군에서 일치한다(계성·마상·가야산·상동·구기·오부·서하…).
머리글 옆 딱지가 지금 어느 관측망인지 늘 밝힌다. 스방이 멈추면 기상청으로 물러서고
딱지가 `스방 안 됨→기상청` 으로 바뀐다 — 조용히 다른 값을 보여 주지 않는다.
설정 → 자료에서 한쪽으로 고정할 수도 있다.

시군 평균 줄은 `창원²³` 뿐이다 — 시군명만 크게, 개소 수는 윗첨자. 줄을 찾는 눈은
시군을 보지 '평균 23개소'를 보지 않는다. 시군을 누르면 같은 기간의 **지점별 강수량**이
많이 온 순으로 펼쳐지고, 몇 개소가 자료를 주는지도 함께 적는다.

### ⚠️ 스방 기간조회(list3)와 값이 다른 두 가지 이유

화면은 **그린 시간 칸을 그대로 더한다** — 표의 누적은 곡선의 합이어야 하기 때문이다.
스방의 시군별 강우량 화면(`dt090/list3`)과 대조해 보니 어긋나는 자리가 둘 있었고,
둘 다 **시간강우량(dt096) 쪽이 맞았다.** 실측 근거를 남긴다.

**하나. 여러 날을 걸치면 첫날이 한 번 더 세어진다.** `일누적`이 다음날 01시에야
리셋되는 구조라 그렇다.

```
사천 곤양  9.3. 시간강우 합계 30.5㎜  →  9.3.~9.5. list3 다우지점 61.0㎜  (= 30.5 × 2)
창녕 계성  9.2. 에 28.5㎜            →  9.3. 하루만 조회해도 계성 28.5 가 얹혀 온다
```

**둘. 시군 집계에서 기상청 관리 지점이 빠진다.** 스방은 같은 시군을 관리주체에 따라
`창원`(경남)·`창원시`(기상청)로 나눠 담는데, list3 의 시군 줄은 경남 쪽만 센다.

```
창원 9.3.  경남 18개소 평균 2.56 (최대 오동 27.5)
           기상청 5개소 평균 14.58 (최대 마산회원 44.5)  ← 여기가 통째로 빠진다
           전부 23개소 평균 5.17 (최대 마산회원 44.5)
           list3: 평균 3.7 · 다우지점 '오동(27.5)'
```

즉 그날 창원에서 제일 많이 온 곳은 **마산회원 44.5㎜**(15시에 43.5㎜)인데 스방 화면은
오동 27.5㎜를 다우지점으로 내놓는다. 대시보드는 265개소를 다 보므로 마산회원을 잡는다.
처음에 기상청 AWS 56개소를 버린 이유(고성 학림 500.5㎜)와 같은 종류의 누락이다.

하루를 통째로, 한쪽 관리주체 쏠림이 없는 시군으로 대조하면 둘이 정확히 맞는다
(사천 7.62 vs 7.3, 진주 0.97 vs 1.0, 하동 4.14 vs 4.1, 고성 1.40 vs 1.4).

**조회 시각 규칙.** 스방은 `toTime=H` 를 '**H시까지**'로 본다. 지금이 06:47인데 06으로
물으면 06:00에서 잘려 **지금 오는 비가 빠진다.** 그래서 **다음 정시(07)로 조회**하고,
받은 값은 07시치가 아니라 지금까지의 값이므로 **기준시각은 `지금 - 5분`(06:42)으로
저장**한다. 없는 시각을 적지 않으려는 것이다. 23시대에는 다음 정시가 없어 23으로 둔다.
규칙은 `app/bangjae.py` 의 `as_of()` 한 곳에 있다.

**계정은 필요할 때만 쓴다 — 없다고 건너뛰지 않는다.** 부르는 자리에 따라 로그인 없이도
자료가 그대로 온다. 상황실 내부망 PC 에서 실측(2026-09-05): 계정 없이 `dt090/list3`
18개 시군, `dt096/list` 532줄이 왔다. 그래서 **일단 부르고, `[]` 가 올 때만** 로그인한다.

⚠️ 예전에는 계정이 없으면 한 발도 안 떼고 건너뛰었다. 그 바람에 상황실에서는 화면이
   늘 `스방 안 됨→기상청` 이었다 — **서버는 멀쩡했고 부르지를 않았다.**
   수집기록에 `스방 계정 없음 — 건너뜀` 만 남아 있어 조회 실패와 구분되지 않았다.

계정이 필요한 자리라면 `config/api_keys.txt` 의 `BANGJAE_ID`/`BANGJAE_PW` 로 넣는다.
비워 두면 옆 프로그램(`code/bangjae`)이 DPAPI로 저장해 둔 계정을 쓴다. 둘 다 없는데
서버가 로그인을 요구하면 이 수집기만 `조회 실패`로 남고 나머지는 정상 동작한다.

주소는 `BANGJAE_URL` 환경변수 또는 `config/api_keys.txt` 의 `BANGJAE_BASE` 로 바꾼다
(기본 `http://112.100.10.186:8080`). 내부망 밖에서는 이 주소가 응답하지 않으므로
**연결 타임아웃만 5초**로 따로 두었다 — 한 번이 60초씩 걸리면 10분 주기를 갉아먹는다.

**내부망 SSL.** 내부망 장비가 인증서를 갈아 끼워 기본 설정으로는 검증에 걸린다.
`DISABLE_SSL_VERIFICATION` 이 기본 켜짐(=검증 안 함)이고, 끄려면 `0` 으로 둔다.

## 예측 분포 범례

그림 **오른쪽 가운데에 세로로** 얹는다. 센 값이 위 — 기상청 원본 범례와 같은 방향이라
둘을 나란히 놓고 봐도 헷갈리지 않는다. `예측 분포 재생` 창의 **범례** 메뉴로 켜고 끈다
(고른 값은 기억된다).

⚠️ 처음에는 아래쪽에 눕혀 놨는데, 비구름이 화면 아래로 몰릴 때 통째로 가렸다.
   비가 오는 자리를 가리는 범례는 없느니만 못하다. 오른쪽은 대체로 바다라 덜 가린다.

**색은 흉내 내지 않는다.** 기상청 QPF 색계는 우리 청색 램프와 전혀 달라서 비슷하게
칠하면 거짓말이 된다. 원본 그림 오른쪽 끝의 세로 색 띠에서 24단계를 그대로 뽑아
`qpf_legend` 설정에 담아 두고(`GET /api/qpf/legend`), 화면은 그것을 가로로 편다.

⚠️ 예전에는 화면이 범례 **그림**을 받아 캔버스로 색을 뽑았는데, 그 그림 주소를 담는
   변수가 끝내 비어 있어 범례가 통째로 안 그려졌다. 조용히 사라지는 길이라 아무도
   몰랐다. 이제 색을 못 받았으면 그렇게 적는다.
⚠️ 경계값은 원본 범례에 **찍힌 대로** 옮겨 적었다(그림 속 글자라 뽑아낼 수 없다).
   약한 쪽에 `0.1` 이 **두 번** 나오는 것도 기상청 범례가 그렇게 찍는 것이지 오타가
   아니다. 그래서 화면에는 `0.1 · 1 · 5 · 10 · 20 · 30 · 50 · 110` 만 띄엄띄엄 적는다.
⚠️ 단위(mm/h)를 눈금과 같은 격자에 넣으면 칸이 하나 늘어 눈금이 통째로 한 칸씩
   밀린다. 색 띠와 눈금만 같은 격자를 쓰고 단위는 그 밖에 둔다.
⚠️ 저장공간 막대에 `.bar` 라는 흔한 이름을 붙였더니 그 `height: 7px` 가 범례 색 띠를
   눌러 190px 짜리가 7px 로 찌그러졌다. `.usebar` 로 바꿨다 — 흔한 이름은 반드시
   부딪힌다.
⚠️ 어두운 상자를 눈금·단위까지 감싸면 그만큼 지도를 가린다. 상자는 **색 띠에만**
   두르고 글자는 지도 위에 그대로 얹는다(폭 52px → 31px).
⚠️ 그 글자색을 테마에서 가져오면 안 된다. 얹히는 바탕이 우리 판이 아니라 **기상청
   지도 그림**이고 그건 다크 테마에서도 늘 흰 바탕이다. 테마색(밝은 회백색)으로
   뒀더니 흰 바다 위에서 통째로 사라졌다. 검은 글자에 흰 테두리를 두른다.

## 예측 이미지 호출량

한 발표분의 장수 = **최대 선행시간 ÷ 간격**. 발표가 10분마다 나오므로
이 숫자가 곧 10분당 호출 수다. 화면의 `예측 분포 재생` 창 메뉴에서 바꾼다.

| 간격 · 선행 | 장수 | 하루 호출 |
|---|---|---|
| 10분 · 6시간 | 36 | 5,184 |
| 20분 · 3시간 | 9 | 1,296 |
| 30분 · 3시간 | 6 | 864 |

**발표가 났는지 먼저 확인하고 난 것만 받는다.** 미래 시각을 요청하면 최신
발표분이 오는 성질을 이용해, 이미지에 찍힌 발표시각 표시를 해시로 비교한다.
확인은 호출 한 번이고, 정시 이후 감시 구간에서만 한다.
재는 방법과 실측값은 `docs/02-발표주기.md`.

### ⚠️ '비가 안 오는 그림'을 '아직 안 올라온 그림'으로 보면 통째로 멎는다

**경남에 비가 없는 정상 그림은 색이 딱 두 가지다** — 바탕 `(250,250,250)` 과
해안선 `(0,0,0)`. 예전 판정(`색 2가지 이하 = 빈 그림`)이 이걸 '아직 안 올라온
그림'으로 읽었다. 그래서 **비가 그치면 수집이 멎었다.**

실측: 2026.9.7. 11:50 발표분이 **열흘 동안** 화면에 걸려 있었다. 훑기는 '가진 것
다음 슬롯'(9.7. 12:00)에서 출발하는데 그 자리에 비가 없어 첫 걸음에서 끊겼다.

⚠️ **저절로 풀리지 않는다.** 9.7. 12:00 은 과거 이미지라 영원히 안 바뀐다 —
   오늘 비가 와도 오늘 슬롯까지 가지를 못한다. 실측(9.17. 09:20, 비 오는 중):
   옛 코드는 1걸음에서 끊기고 `최신 발표분 = None` 이었다.

고친 자리 둘 —

| | |
|---|---|
| **판정** | 색 가짓수가 아니라 **해안선 픽셀 수**로 본다. 올라온 그림에는 경남 박스 안에 늘 30,925px(비 위에 그려진다), 안 올라온 그림에는 0px. 안 올라온 그림은 `(240,240,240)` 한 색으로 꽉 찬 950×800 이다 |
| **훑기 시작점** | 가진 것이 아무리 낡았어도 **90분 앞에서부터** 시작한다. 며칠 꺼져 있었다고 며칠 전부터 걸으면 따라잡는 데 호출이 슬롯 수만큼 들고(열흘이면 1,440번), 중간에 한 칸만 막혀도 영영 못 따라잡는다 |

⚠️ **비가 없는 프레임도 저장한다.** '앞으로 3시간 비 없음'은 빈손이 아니라
   정보다. 예전에는 버려서 한 발표분이 18장을 못 채웠고(실측: 9.7. 11:50 이
   ef 10~110 열한 장뿐), '다 받았다' 판정이 안 서서 매 주기마다 같은 발표분을
   다시 받으러 갔다.

## 지켜야 할 것

- **비밀은 저장소에 넣지 않는다.** `config/api_keys.txt`·`.env`는 `.gitignore`에 있다.
  로그에도 남지 않게 httpx 로거를 WARNING으로 낮춰 뒀다(요청 URL에 `authKey`가 실린다).
- **조회 실패와 '자료 없음'을 구분한다.** 실패는 저장하지 않고 다음 주기에 다시 시도한다.
  DB의 `quality`, 화면의 `0.0` / `—` / `✕`가 그 구분이다.
- **시각은 전부 KST.** UTC로 바꾸지 않는다(기상청 API가 KST를 쓴다).

함정 목록은 `handoff-mac/docs/05-pitfalls.md`, 화면 설계는 `handoff-mac/docs/07-dashboard-design.md`.

## 권역 예보 — 단기예보를 권역·시군으로

`설정 → 종합 화면 → 오른쪽 아래`에서 **권역 예보**를 고르면 그 자리에 뜬다.
메뉴바에서 **권역/시군**, **오늘/내일/모레**를 고른다. 강수량만 그린다 — 권역별 기온 범위는 상황실에서 쓸 일이 적다.

권역은 기상청 예보 문구 단위다(`app/domain/regions.py` 의 `ZONES`).

| 권역 | 시군 |
|---|---|
| 경남서부내륙 | 함양, 거창, 합천, 진주, 하동, 산청 |
| └ 북서내륙 | 함양, 거창, 합천 |
| └ 남서내륙 | 진주, 하동, 산청 |
| 경남중부내륙 | 밀양, 의령, 함안, 창녕 |
| 경남동부내륙 | 김해, 양산 |
| 창원 (경남중부남해안) | 창원 |
| 경남서부남해안 | 통영, 사천, 거제, 고성, 남해 |

권역 이름을 누르면 그 밑에 시군이 펼쳐진다(다시 누르면 접힌다. 펼친 상태는 그 화면에 남는다).
서부내륙이 상위, 북서·남서내륙이 그 하위라 들여 적는다. 중부남해안은 창원 하나뿐이라
'창원'으로 적는다.

한 줄이 격자 분포다. 격자 칸(읍면동 대표 격자, 약 5km)마다 그날 강수량을 더한 뒤
권역 안에서 **상자 = 20~80백분위, 세로 금 = 중앙값, 점 = 95백분위(많이 오는 곳)**로 그린다.
오른쪽 숫자는 상자를 기상청이 쓰는 범위(5~10, 5~20, 10~40, 20~60 …)로 옮긴 것이다.
▲▼ 는 직전 발표보다 중앙값이 뚜렷이 오르거나 내린 것이다(3㎜ 이상이면서 20% 이상).

⚠️ **'오늘'은 발표 뒤 남은 시간만 담는다.** 14시 발표면 14~24시다. 판 머리글에 늘 그 구간을 적는다.
⚠️ **직전 발표 대비는 같은 시간끼리 견준다.** 직전 발표는 오늘의 더 이른 시간을 담고 있어
   그냥 견주면 늘 줄어든 것으로 보인다.
⚠️ **실측: PCP 는 30에서 막힌다** (2026-10-01, 8.28. 호우 발표분). `tmfc` 10자리(`YYYYMMDDHH`)로
   과거 발표분도 받아지고, PCP 는 **1㎜ 단위 정수**로 온다. 8.28. 23시·05시 발표 48개 대상시각에
   0~30 이 빠짐없이 나오고 **31 이상은 한 번도 없다** — 여섯 시각의 최대가 딱 30이다. 30 은
   '30㎜ 이상' 범주로 읽어야 한다(50 이상 표기는 아직 못 봤다). 그래서 시간당 30㎜ 를 넘는 비가
   예보된 날은 **권역 합계와 최대가 모자라게 나온다.** 극값은 초단기·실측으로 본다.

## 경남 지도 — 격자 강수

> 만드는 중. 지금은 0단계(실측)만 끝났다. 화면은 `map.html` 로 따로 먼저 만든다.

경계(SVG) 위에 격자 강수(Canvas)를 겹친다. 격자는 **기상청이 준 칸 그대로** 찍는다 —
보간하거나 등치선으로 바꾸지 않는다. 그래서 경계를 격자와 **같은 도법·같은 원점**으로 그려야
하고, 조금이라도 어긋나면 비가 엉뚱한 시군에 그려진다.

### ⚠️ 실측: 고해상도 격자 강수 500m (2026-10-01)

`/api/typ01/cgi-bin/url/nph-sfc_obs_nc_api?obs=rn_15m|rn_60m|rn_day&tm=YYYYMMDDHHMI&disp=B`

| | |
|---|---|
| 모양 | nx = ny = 2049. 앞 4바이트가 int16 **리틀엔디언** 둘(`01 08 01 08`), 이어서 float32(LE) × 4,198,401. 합 16,793,608바이트 |
| 순서 | **남서쪽 모서리부터.** 한 행은 서→동, 행은 **남→북.** `disp=A` 와 값 순서가 전 칸 같다 |
| 결측 | −999. 경남 bbox 안에서는 **늘 같은 23,352칸**(분석 영역 밖 바다) — 8.28.과 10.1.이 한 칸도 다르지 않다 |
| 지연 | 기준시각 +5분 남짓에 만들어진다(NetCDF `time_in`). 08:07 에 08:00 분이 있었고 08:08 에 08:05 분은 없었다 |
| 크기 | 바이너리는 늘 16.8MB·약 4초. 전송 압축도 영역 자르기 인자도 없다. 같은 자료의 NetCDF(`/api/typ01/url/sfc_grid_nc_down.php`)는 46KB(비 없음)~430KB(8.28. 일강수)·0.2초 — HDF5, int16, ÷10 |
| 과거 | 2026-08-28 도 그대로 나온다 |
| 위경도 API | `nph-sfc_obs_latlon_api` 는 **403**(활용신청 필요). API허브 목록 페이지에 붙은 `sfc_grid_latlon.nc`(칸별 위경도)로 대신 확인했다 |

**투영.** NetCDF 전역 속성에는 `Lambert Conformal Conic`, `map_slon=126`, `map_slat=38`,
`map_sx=880`, `map_sy=1540`, `grid_size=0.5` 만 있고 **표준위도가 없다.** 칸별 위경도 파일에 맞춰 보니:

| 식 | 칸별 위경도와 차이(전국) |
|---|---|
| **타원체(GRS80·WGS84) 람베르트, 표준위도 30°·60°, 원점 126°E·38°N, 500m, 원점 칸 (880, 1540)** | 최대 **0.0016칸**(0.8m) |
| 같은 매개변수를 동네예보식 **구면**(Re 6371.00877km)으로 | 최대 3.8칸(1.9km). 경남 안에서도 1.6칸(800m) |

칸 번호는 0부터, (열, 행) = (880, 1540) 이 126°E·38°N 이다.

두 가지로 더 확인했다.
- **기상청 지점 API**(`nph-sfc_obs_nc_pt_api` — 서버가 경위도→칸을 한다)에 이웃 8칸과 값이
  0.4㎜ 이상 다른 칸만 16곳 골라 물었다. **16/16 같은 값.** 한 칸만 어긋나도 드러나는 시험이다.
- **관측 대조**(8.28. 11시 60분 강수, 매분자료 전국 711개소): 차이 중앙값 0.0㎜, 0.5㎜ 이내 87%.
  행을 뒤집으면 경남 56곳에서 0.5㎜ 이내가 59% → 20% 로 무너진다. 창원(155) 관측 0.9 / 칸 1.5,
  진주(192) 3.3 / 3.0 — 객관분석이라 관측값을 그대로 지나지는 않는다.

⚠️ **`d3.geoConicConformal` 은 구면이다.** 그대로 쓰면 경남 안에서 경계와 격자가 최대 800m
   어긋난다. 경계는 파이썬에서 타원체 식으로 **격자 좌표로 미리 바꿔** 저장한다.
⚠️ **일강수(rn_day) 자정.** 00:00 값은 **전날 총량**이다(8.28. 23:55 최대 140.2 → 00:00 140.2).
   00:05 는 **반쯤 리셋된 값**이다(최대 13.2 → 00:10 에 0.4 → 00:30 1.5 → 01:00 3.2). 00:10 부터 믿는다.
   AWS `RN_DAY` 와 같은 성질인데 리셋 시각이 다르다(AWS 는 01시).

### ⚠️ 실측: 5km 동네예보 격자 (2026-10-01)

  (08:13 에 08:10 분 없음). 8.28. 11시도 받아진다(최대 42㎜).

### 경계와 bbox

시군 경계는 `statgarten/maps` 의 `json/{경상남도,부산광역시,울산광역시}_시군구_경계.json`
(SGIS **2020년** 경계, 저장소 커밋 `8d53dca` 2022-10-28). ⚠️ 좌표가 경위도가 아니라 **UTM-K
(EPSG:5179)** 인데 파일에 좌표계 표기가 없다. 창원(155)·진주(192) 관측소가 각각 창원시
마산합포구·진주시 안에 드는 것으로 해석을 확인했다. 창원은 5개 구로 나뉘어 있다.

읍면동은 `vuski/admdongkor` 행정동 **2026-07-01판**(경위도)에서 경남 305곳을 쓴다 — 시군별
최대값이 **어느 읍면동 칸**에서 났는지 이름을 붙이는 데만 쓴다.

`tools/build_geo.py` 한 번으로 만든다(node 필요 — 단순화는 `npx mapshaper`). 원본은
커밋에 고정해 `tools/.cache/` 에 받는다(45MB, 커밋하지 않음).

| 만드는 것 (`data/geo/`) | |
|---|---|
| `gyeongnam.topo.json` | 경남 18 + 부산·울산. **500m 격자 칸 좌표로 미리 바꿔 둔다.** 창원 5개 구·부산·울산은 하나로 합친다. 0.15칸(75m) 간격 단순화, 0.3칸² 미만 섬은 뺀다 → 93KB. 시군명 자리(`lx`,`ly`)는 다각형 안쪽 가장 깊은 점 |
| `grids.json` | 두 격자의 투영 매개변수, bbox, 5km→500m 아핀, 시군·읍면동 번호 |
| `mask_sigun.u8.gz` · `mask_emd.u16.gz` | bbox 칸마다 시군·읍면동 번호(0 = 밖). 칸 가운데가 경계 안이면 그 번호. 행은 남→북 |

권역 경계는 따로 두지 않는다. 시군마다 `zone`(상위 권역)·`sub`(하위 권역)을 달아 두고,
화면이 `topojson.mesh` 로 **권역이 바뀌는 시군 사이 선만** 뽑아 굵게 긋는다.
권역 정의는 `app/domain/regions.py` 의 `ZONES` 한 곳에서만 읽는다.

⚠️ 경계는 `d3.geoConicConformal` 로 투영하지 않는다(위 실측 — 구면이라 800m 어긋난다).
   화면은 `d3.geoIdentity` 로 **축척만** 곱한다. 격자도 경계도 같은 칸 좌표라 어긋날 수가 없다.

경계 외곽 + 20km 를 격자 칸으로 옮긴 범위:

| | 500m (0부터) | 5km (1부터) |
|---|---|---|
| 경남 + 부산 + 울산 | 열 1121~1536, 행 754~1131 → 416 × 378 = **157,248칸** | X 67~109, Y 57~96 → 43 × 40 = 1,720칸 |
| (경남만) | 열 1121~1494, 행 754~1131 → 141,372칸 | X 67~105, Y 57~96 |

한 프레임을 0.1㎜ uint16 으로 잘라 gzip 하면 314KB → 비 올 때 15~31KB, 비 없을 때 1.4KB.

### 수집 · 저장

받자마자 경남 bbox 만 잘라 `data/cache/grid/{층}/{키}.u16.gz` 에 둔다. 전국 원본은 두지 않는다.

| 층 | 자료 | 키 | 보관 |
|---|---|---|---|
| `obs15`·`obs60`·`obsday` | 500m NetCDF(`sfc_grid_nc_down.php`) | 기준시각 | 3일 |
| `odam` | 실황 RN1 5km | 발표시각 | 3일 |
| `vsrt` | 초단기 RN1 5km — **기존 수집기가 받는 격자를 그대로** | 발표_대상 | 최근 3발표분 |
| `shrt` | 단기 PCP 5km — **기존 수집기가 받는 격자를 그대로** | 발표_대상 | 최근 3발표분 |

값은 0.1㎜ uint16(`0` 무강수, `65535` 결측), 행은 남→북. **조회 실패는 파일이 없는 것**이다 —
결측과 다르다. 화면은 층마다 기준시각을 보고 늦었는지 안다.

| 하루 (PC 한 대) | 호출 | 용량 |
|---|---|---|
| 500m 셋 × 10분 | 432 | 20~100MB (NetCDF 46~430KB) |
| 실황 5km × 10분 | 144~290 (아직 없으면 한 칸 물러서 한 번 더) | 50~100MB |
| 초단기·단기 | **0** — 이미 받는 격자를 bbox 째 한 번 더 저장할 뿐 | 0 |

⚠️ **500m 는 NetCDF 로 받는다.** 바이너리(disp=B)는 같은 자료가 16.8MB 라 10분마다 셋이면
   하루 7.3GB 다. 기관키 한도(하루 50GB)는 대시보드를 띄운 PC 마다 나눠 쓴다.
   대신 `h5py`·`numpy` 가 필요하다(requirements). 없으면 이 수집기만 실패로 남는다.
⚠️ **받을 때마다 격자 틀을 확인한다.** NetCDF 속성(원점 칸 880·1540, 126°E·38°N, 0.5km,
   2049칸)이 실측과 다르면 저장하지 않고 실패로 남긴다 — 틀이 바뀐 채 그리면 비가 엉뚱한
   시군에 그려진다.
⚠️ 일강수는 00:00·00:05 를 받지 않는다(위 실측). 그동안 화면에는 23:55 값이 **제 시각과 함께** 남는다.

**지연 판정** — 평소 가장 늙은 때보다 더 늙으면 층을 흐리게 하고 `자료 지연` 을 붙인다.

| 층 | 평소 나이 | 지연 |
|---|---|---|
| 500m | 6분 물러선 5분 칸을 10분마다 → 6~21분 | 25분 넘으면 |
| 실황 5km | 발표 +3~13분, 10분마다 | 30분 넘으면 |
| 초단기 | 발표 슬롯에서 10분 물러서고 10분마다 → 10~30분 | 30분 넘으면 |
| 단기 | 발표 +20분부터 받는다 | 지금 받을 수 있는 발표분보다 30분 넘게 묵으면 |

**시군 통계**(`/api/grid/sigun`)는 시군 칸 지도로 낸다. 결측 칸은 평균에서 **뺀다**(0 으로 치지
않는다). 최대가 여러 칸이면(5km 칸을 500m 로 펼친 경우) 그 칸들 한가운데서 가까운 칸을 골라
그 칸이 드는 읍면동을 적는다. 5km 층은 500m 칸으로 펼쳐 같은 칸 지도를 쓴다.
단기 합계는 한 시간이라도 결측인 칸을 결측으로 둔다. PCP 가 30(=30㎜ 이상)인 시간이 든 칸 수를
`X-Grid-Capped` 로 함께 준다 — 그 칸의 합계는 **하한**이다.

### 화면 — `/map.html`

아직 종합 화면(`index.html`)에 붙이지 않은 **별도 창**이다. 오른쪽 위에서 층을 고른다
(숫자 `1`~`7` 키로도). 고른 층은 서버 설정(`map`)에 남는다 — 어느 PC 에서 열어도 같은 층.

| 층 | 색 단계(㎜, 그 값부터 그 색) |
|---|---|
| 15분 | 0.1 · 0.5 · 2 · 5 · 8 · 12 · 18 — `×4 환산` 을 켜면 값×4 에 60분 단계 |
| 60분 · 실황 5km · 초단기 | 0.1 · 1 · 5 · 10 · 20 · 30 · 50 |
| 오늘 누적 · 단기 오늘/내일 | 0.1 · 5 · 10 · 30 · 50 · 80 · 150 |

색은 청색 램프(`--rain-1`~`7`) 일곱 칸뿐이다. 0 은 칠하지 않는다(땅 색이 그대로 보인다).
면을 칠하므로 '지금 오는 비' 표(1㎜ 부터)보다 한 칸 아래인 0.1㎜ 부터 보인다.

| 올려 그리는 것 | |
|---|---|
| 시군 경계 | 가는 실선. 해안·바깥 경계는 조금 굵게 |
| 권역 경계 | 굵은 점선 — 상위 권역이 바뀌는 시군 사이. 북서·남서내륙 사이는 가는 점선 |
| 시군명 | 칸 크기를 따라 커진다(1080p 에서 23px, 4K 에서 46px). 부산·울산은 흐리게 |
| 시군 최대 | **값이 있는 시군만.** 점 = 그 칸, `12.5` + 작은 읍면동. 이름·다른 라벨·**다른 시군의 점**과 겹치면 자리를 옮긴다. 빈자리가 끝내 없어도 빼지 않는다(극값) |
| 마우스 | 그 칸 값, 시군·읍면동, 위경도, 칸 번호 |
| 결측 | **땅 칸만** 빗금. 바다의 결측은 늘 같은 분석 영역 밖이라 칠하지 않는다 |

머리에 층 이름 · 그 층의 기준시각 · 출처. 늦으면 층을 흐리게 하고 `자료 지연 · N분 전`,
수집이 실패하면 `수집 실패 · 마지막 정상 HH:MM`. 받은 격자가 하나도 없으면 지도 가운데에 그 이유.

| 주소 인자 | |
|---|---|
| `?layer=obs15` · `vsrt+3` … | 처음 띄울 층(서버 설정보다 먼저 — 화면 고정용) |
| `?theme=light` | 밝은 테마. 없으면 `index.html` 과 같은 자리(`gn-theme`)를 따른다 |
| `?test=1` (또는 `T` 키) | 테스트 모드 — 합성 격자. 판 테두리가 보라색이고 왼쪽 위에 크게 `테스트` |
| `?tm=YYYYMMDDHHMI` | 실측 층을 그 시각으로(남아 있는 사흘 안에서만). `지난 시각 보기` 가 붙는다 |
| `?debug=1` | 전환·그리기 시간 |

⚠️ 4K 벽면(배율 100%)에서는 머리글·범례가 1080p 의 절반 크기가 됐다. 화면 크기에 맞춰
   통째로 키운다(`--k` = min(가로/1920, 세로/1080), 1 아래로는 안 줄인다).
⚠️ 테스트 표시를 지도 한가운데 큰 글자로 얹었더니 옅게 해도 **비구름처럼** 보였다. 판 테두리와
   왼쪽 위로 옮겼다.
⚠️ **판 크기가 0 인 채로 열리면**(창이 가려진 채 뜸) 빗금용 캔버스가 0×0 이 되어 `drawImage` 가
   예외를 던졌고, 머리글까지 안 그려진 채 멈췄다. 크기가 0 이면 그리지 않고, 판 크기가 잡히는
   순간(`ResizeObserver`) 다시 그린다.
⚠️ 라벨 자리를 고를 때 다른 시군의 점을 피하지 않으면 `6.0 • 12.6` 처럼 붙어 **누구 값인지**
   헷갈린다(김해·양산). 점 자리도 미리 비워 둔다.

개발할 때는 `.venv\Scripts\python.exe -m app.main --no-collect --port 8010` 으로 **수집기 없이**
화면만 띄운다 — 같은 PC 에서 수집기가 둘 돌면 기상청 호출이 두 배가 된다.
Claude 미리보기(`.claude/launch.json`)의 `dashboard` 도 이렇게 뜬다. 수집기까지 띄우는 설정은
`dashboard-collect` 이고, run.bat 서버가 꺼져 있을 때만 쓴다.

**층 전환 시간** (2026-10-01, 이 PC 크롬, 실제 자료, `show()` 한 번 — 받기·색칠·라벨·머리글까지)

| 화면 | 처음 고를 때(받기 포함) | 받아 둔 뒤 | 그리기만 |
|---|---|---|---|
| 1920×1080 | 22~36ms (켠 뒤 첫 연결 한 번 355ms) | 중앙 0.4ms · 최대 45ms | 1~2ms |
| 3840×2160 | 24~35ms | 중앙 0.4ms · 최대 52ms | 최대 2.4ms |

목표(50ms)는 받아 둔 뒤 기준으로 맞는다. 띄우자마자 **나머지 층을 뒤에서 미리 받아 두므로**
벽면에서 누를 때는 늘 '받아 둔 뒤'다. 최대값의 튐(45·52ms)은 21번 중 한 번이고 그리기는 2ms
안쪽이다 — 창이 가려진 채로 쟀다. 그리기가 싼 까닭은 칸을 칸 = 픽셀인 작은 그림(416×378)으로
