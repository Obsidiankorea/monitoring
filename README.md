# 경남 기상 대시보드

경상남도 18개 시군의 강수·특보·초단기예측을 한 화면에 표출하는 재난상황실 대시보드.
상주 서버 하나로 수집·저장·표출을 모두 한다 — 지금은 언레이드(도커, 아래 '언레이드 서버').

## 실행

폴더째 옮겨 놓고 실행 파일 하나만 누르면 된다. 가상환경 생성·의존성 설치·키 배치·
포트 찾기·브라우저 열기를 알아서 한다.

| | |
|---|---|
| **맥** | `run.command` 더블클릭 (또는 터미널에서 `./run.command`) |
| **윈도** | `run.bat` 더블클릭 |

띄우면 이 순서로 간다.

1. **새 버전이 있는지 확인하고 물어본다.** 있으면 무엇이 바뀌는지 보여 준다.
   ⚠️ **10초 안에 답이 없으면 아니오다.** 벽면 PC 는 부팅하며 스스로 뜨는데,
   아무도 없는 새벽에 물음표에 걸려 화면이 안 뜨면 안 된다. 받기가 실패해도
   멈추지 않는다 — 지금 버전으로라도 뜨는 게 낫다.
   의존성 설치보다 **먼저** 한다. `requirements.txt` 가 함께 바뀔 수 있어서다.
2. 가상환경·의존성·키·포트를 챙긴다.
3. 서버가 응답하면 **웹앱 창**으로 연다 — 주소창도 탭도 없는 창(`--app`).
   상황실 화면이라 주소창이 보일 이유가 없고, 실수로 다른 데로 옮겨 가지도 않는다.
   창 아이콘은 화면의 파비콘(비바람)을 그대로 쓴다.
   윈도는 크롬 → 엣지 순으로 찾고(엣지는 윈도 10 에 늘 있다), 맥은 크롬을 찾는다.
   없으면 기본 브라우저로 그냥 연다.

처음 실행은 의존성을 받느라 1~2분, 뜬 뒤에도 자료를 받느라 화면이 채워지기까지
10~40초 걸린다. 받아 둔 것은 `data/` 에 남으므로 두 번째부터는 바로 뜬다.

포트를 바꾸려면 `PORT=9000 ./run.command`, 다른 기기에서도 보려면 `HOST=0.0.0.0`.
포트가 이미 쓰이고 있으면 다음 빈 포트를 알아서 찾는다 — **수집기가 둘 돌면
기상청 호출이 두 배가 되므로** 같은 포트에 겹쳐 띄우지 않는다.

### 직접 띄우기

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
mkdir -p config && cp handoff-mac/config/api_keys.txt config/   # 키는 저장소에 없다
.venv/bin/python -m app.main
```

윈도는 `.venv\Scripts\python.exe -m app.main`.

### 시연(스냅숏) — 그때를 굳혀 두고 발표 때 그대로 띄운다

비가 오는 지금을 **그 시각 그대로** 굳혀 두면, 나중에 맑은 날 발표에서도 그때 화면을 지도 · 종합 화면 둘 다에서 띄운다.
지어낸 값이 없다 — 그때 모은 자료를 그 시각으로 자른 것.

| | |
|---|---|
| 저장 | 실황 화면 **지도 설정 › 데모 · 종합 화면 설정 › 데모 시연 의 `지금 저장`**(제목은 비우면 `10.19. 00:24 · 호우주의보(고성·남해)` 꼴). 서버가 뒤에서 굳힌다(수 초~수십 초, 화면은 `/api/snaps` 의 `job` 을 본다 — PC 가 서버로 넘길 때 20초에 끊기지 않게). 담는 것: 지금 실측 · 그전까지 온 비(관측 72시간 · 매분 50시간 · 격자 72시간) · 초단기(읍면동 · 격자) · 단기(오늘~모레) · 예측 분포 그림 · **특보(그 시각으로 기상청에서 다시 읽는다, `tm=`)** · 설정(지도 층 · 누적 구간 — 종합 화면에서 저장하면 그 화면 구간). 그 시각 뒤 자료는 버린다(화면이 '가장 새 것'을 고르므로). 10MB 안팎 |
| 쌓이는 곳 | `config.SNAPS` — 서버 `/state/snaps`(언레이드 `/mnt/user/appdata/gn-monitor/state/snaps/<이름>/`), PC `data/snaps/`. **저장소(git)에는 넣지 않는다** |
| 지우기 | 같은 목록의 휴지통(`지우기`) — 확인 뒤 **서버 폴더째 지운다(되돌릴 수 없다)**. 재현 사례(지난 호우)는 저장소 자료라 지우지 않는다 |
| 띄우기 | 시연 서버 **:8001** 하나(`gn-demo`, `GN_DEMO=1` · `/state/snaps` 읽기 전용). 목록의 줄을 누르면 `:8001/snap/<이름>?to=/map.html` — 지금 띄운 것이 다르면 **그 자리에서 다시 떠서 갈아 탄다**(몇 초, 기다림 화면). ⚠️ 한 번에 하나 — 두 사람이 서로 다른 시연을 열면 나중 것으로 바뀐다. PC: `.venv\Scripts\python.exe -m app.main --demo`(기본 :8001, 가장 새 것) · `--snap <이름>` |
| 시연 모드 | 수집 안 함(수동 조회 · 과거 메우기도 막음), 시계를 그 시각에 멈춤(`app/clock.py`, 화면은 `/api/clock.js` 의 `GN_NOW`), 저장 · 지우기 안 됨. 굳힌 것은 손대지 않고 띄울 때마다 사본(`GN_SNAP_STATE`)으로 — 발표 중 바꾼 층 · 설정은 다음에 처음으로. 실황 DB 는 쓰지 않는다 |
| 표시 | 지도 머리 · 종합 화면 메뉴바에 보라색 `시연 · 10.19. 00:24 저장` — 발표 화면이 실황으로 읽히지 않게 |
| 주소 | 같은 주소의 :8001. PC 가 **서버에서 받는 중**이면 서버의 :8001(이 PC 의 :8001 이 아니라) |

⚠️ **지난 시각으로는 굳히지 않는다.** 서버는 초단기 격자 · 예측 분포 그림을 마지막 몇 발표분만 남겨서(용량), 지난 시각에는 그때 예측이 없다.
   비가 올 때 그 자리에서 `지금 저장`. 떠 온 서버 자료로 PC 에서 굳히려면 `tools/snapshot.py <뜬 폴더> --now YYYYMMDDHHMM`(같은 코드).

굳혀 둔 것(2026.10.19 기준, 원본 — 자르기 전 — 은 언레이드 `/mnt/user/appdata/gn-monitor/snap-raw-<시각>/`):

| 이름 | 시각 | 무엇 |
|---|---|---|
| `live-20261019-0024` | 10.19. 00:24 | 10.18. 18시~24시 비(지도 지난 6시간 · 종합 화면 18시부터) · 00:10 초단기 앞으로 6시간 · **고성 · 남해 호우주의보 발효 중**(23:05~00:30) · **경남 AWS 263곳 덧붙임**(아래) |
| `live-20261018-1536` | 10.18. 15:36 | 비 오는 중 · 앞으로 6시간 |

> [!note] 서버 시연에 경남 AWS(스방) 덧붙이기 — 내부망에서
> 서버는 스방에 닿지 않아 굳힌 시연에 경남 AWS 가 없다. 스방은 지난 날짜의 시간 강수도 주므로, **내부망 PC 에서**
> `tools\snap_bangjae.py <시연 이름> "YYYY-MM-DD HH:MM"` 으로 그 시각 앞 72시간을 받아 `data/demo/bangjae/<시연 이름>.json`
> 에 두고 커밋한다. 서버를 갱신하면 시연 서버가 그 시연을 띄울 때 **사본** DB 에 얹는다(`snaps.add_bangjae`, 굳힌 원본은 그대로).
> 그 시각이 든 스방 칸(00:24 면 00시 칸)은 넣지 않는다 — 지금 받으면 그 뒤 비까지 들어 있다. 시군 평균(dt090)은 계정이 없으면
> 빈 응답이라 넣지 않았다. `live-20261019-0024`: 10.16. 00시~10.18. 23시, 263곳 · 18,844칸(72시간 최다 산청 시천 88.5 · 고성 학림 87.0).

### 언레이드 서버(도커) — 어디서든 브라우저로

집 언레이드(tower, Tailscale `100.106.116.92`)에 컨테이너 `gn-monitor` 로 상주한다(2026-10-17~).
**화면 `http://100.106.116.92:8000/` · 지도 `/map.html`** — Tailscale 이 켜진 기기면 어디서든 연다.
언레이드 웹 화면 Docker 탭의 `gn-monitor` 아이콘 → WebUI 로도 열린다.

> [!tip] 서버 갱신 — 화면에서
> 종합 화면 **설정 › 업데이트 › 서버(언레이드)** — 지금 판 · GitHub 최신 · 밀린 커밋 · 마지막 갱신 기록, [다시 확인] [서버 갱신].
> 경남 강수 지도에도 같은 칸이 있다 — **지도 설정(`Ctrl`+`,`) › 업데이트**(지도 창만 띄워 둔 벽면에서도 갱신한다).
> 누르면 컨테이너가 `state/update/request` 파일만 두고, **언레이드 예약 작업**(`deploy/unraid/updater.sh`, 1분마다 —
> `/boot/config/plugins/dynamix/gn-monitor.cron`)이 `deploy.sh` 로 다시 빌드해 띄운다(1~2분, 시연 :8001 도). 10분마다 GitHub 를 본다.
> 자동 갱신은 하지 않는다(누를 때만). 컨테이너에는 도커 권한을 주지 않는다. PC 가 서버에서 받는 중이면 PC 화면에서도 서버를 갱신한다.
> 예약 설치/해제: `bash /mnt/user/appdata/gn-monitor/repo/deploy/unraid/updater.sh --install`(`--uninstall`). 화면에 '갱신 장치가 N분째 조용하다'가 뜨면 다시 설치.

| | |
|---|---|
| 폴더 | `/mnt/user/appdata/gn-monitor/` — `repo/`(받은 저장소) · `config/api_keys.txt`(ORG_API_KEY, PC 에서 SSH 로 복사) · `state/`(DB · 격자 캐시 — 컨테이너를 갈아도 남는다) |
| 갱신 | GitHub 에 올린 뒤 `bash /mnt/user/appdata/gn-monitor/repo/deploy/unraid/deploy.sh` — 받기(ff-only) → 빌드 → 갈아끼우기 → `/api/status` 확인 |
| 이미지 | `Dockerfile`(python 3.14.3-slim + tzdata, KST). 키·DB 는 굽지 않는다(`.dockerignore`) — 실행할 때 연결 |
| 쌓이는 자료 | `GN_STATE=/state` — DB·격자 캐시만 바깥에. 지도 경계·사례(`data/geo`·`data/demo`)는 이미지 안 |
| 스방 | 집에서는 내부망에 닿지 않는다 — `SKIP_COLLECT=bangjae`(쉼표로 여럿). 누적 카드 AWS 는 기상청으로 물러선다 |

⚠️ **PC 와 서버가 둘 다 수집하면 기상청 호출이 두 배**다(같은 키). 첫 배포 때 PC 의 DB(설정·기록)를
SQLite 백업으로 떠서 옮겨 두었다.

**PC 에서 받는 곳 고르기 — 설정(Ctrl+,) › 자료 › 자료 받는 곳**: `이 PC 에서 수집`(기본, 예전과 같다) /
`서버에서 받기`. 서버면 이 PC 는 수집기를 멈추고(스케줄러 pause — 재시작 없이), 화면이 부르는 `/api/…` 를
서버로 넘긴다(`app/origin.py`, 미들웨어). 화면 파일은 이 PC 것. **넘기지 않는 것**: 받는 곳 설정(`/api/origin`) ·
업데이트(`/api/update…`) · 저장공간(`/api/storage…`, 보관 기간) — 이 PC 의 것이다. 바꾸기 전에 그 주소의
`/api/status` 를 불러 보고(연결 확인) 닿지 않으면 바꾸지 않는다. 서버에서 받는 중에는 메뉴바에 `서버`,
지도 머리에 `서버` 배지. 서버에 닿지 않으면 화면의 요청이 502(까닭 적힘)로 온다. 설정은 이 PC DB(`origin`).
⚠️ 화면의 '업데이트' 단추는 서버(컨테이너)에서는 안 된다(git 이 없다) — 서버 갱신은 deploy.sh.

## 구조 — 수집과 표출을 분리한다

**화면을 열 때 기상청을 부르지 않는다.** 수집기가 주기적으로 받아 SQLite에 넣고,
웹은 저장된 것을 읽기만 한다. 접속자가 몇이든 기상청 호출은 한 번이고,
API가 죽어도 마지막 정상 자료가 화면에 남는다.

```
기상청 API ──▶ app/collectors/ ──▶ SQLite(data/gnweather.db) ──▶ /api/* ──▶ 화면
               (APScheduler)          + data/cache/qpf/*.png
```

| 파일 | 하는 일 |
|---|---|
| `app/config.py` | 키 로드, 수집 주기, 화면 폴링 기본값 |
| `app/kma.py` | 기상청 호출 한 곳. euc-kr, 타임아웃, 재시도, 200인데 본문이 오류인 경우 |
| `app/db.py` | 스키마. `quality` 열이 무강수·결측·조회실패를 가른다 |
| `app/domain/regions.py` | 관제순, 대표지점, 특보구역 세분화, 강원 고성 배제, 중대경보 파싱 |
| `app/collectors/rain.py` | AWS 정시(`awsh`) + 매분 보강(`nph-aws2_min`). `collect_minute` = 매분자료만 1분마다 |
| `app/collectors/forecast.py` | 초단기예측 격자 RN1(`nph-dfs_vsrt_grd`) |
| `app/collectors/alerts.py` | 기상특보(`wrn_now_data`). ⚠️ `disp=1` 이 2026.10 무렵부터 **JSON(UTF-8)** 으로 온다(예전엔 콤마 글 · euc-kr) — 둘 다 읽는다. 글로만 읽었더니 행이 0개라 09.30~10.19 내내 '특보 없음'으로 쌓였다(그날 밤 고성 · 남해 호우주의보를 못 봤다). 이제 모양이 낯설면 '없음'이 아니라 수집 실패로 남긴다 |
| `app/collectors/shortfc.py` | 단기예보 격자(`nph-dfs_shrt_grd`) — 1시간 강수량(PCP), 오늘~모레 |
| `app/collectors/qpf.py` | 예측 분포 이미지(`nph-qpf_ana_img`) — 전국을 받아 PIL로 경남만 크롭 |
| `app/collectors/grid_rain.py` | 경남 지도 — 500m 격자(NetCDF)·실황 5km 를 받아 경남 bbox 만 저장 |
| `app/gridstore.py` · `app/gridview.py` | 격자 프레임 저장(uint16 gzip 파일) · 층 풀기·합계·지연·시군 통계 |
| `app/domain/gridproj.py` | 격자 투영(500m 타원체·5km 구면 람베르트, UTM-K) |
| `app/bangjae.py` | 스방(경남 스마트 통합 방재시스템) 호출 — 로그인, 조회 시각 규칙 |
| `app/collectors/bangjae_rain.py` | 스방 시군 평균·다우지점 + 지점별 시간강우량 |
| `app/maint.py` | 저장공간 재기·정리(보관 기간) |
| `app/demo.py` | 데모 사례 — 실제 호우 때를 되돌려 띄운다 |
| `app/queries.py` | DB 읽기. 결측을 0으로 더하지 않고 뺀 시간 수를 함께 준다 |
| `app/main.py` | FastAPI + 스케줄러 + `/api/*` |
| `app/web/static/index.html` | 화면 |

## 수집 주기

| 자료 | 주기 | 근거 |
|---|---|---|
| 특보 | 1분 | 발표 리듬이 없다. 아무 때나 나온다 |
| 강수량 | 10분 | 정시 자료 + 최근 구간은 매분자료로 보강 |
| 매분자료(`minute`) | 1분 | **지도 판 AWS 실시간 감시(`R`, 설정 `aws_live`)를 켠 동안만** — 끄면 기상청을 부르지 않는다. '지금 −1분' 한 시각(아직이면 −2분)만 — 지도 AWS 층 '지금' 칸 · 지금 오는 비가 1분마다 따라간다. 켜 두면 하루 1,440회, 응답 수십 KB. 이미 받은 분은 다시 부르지 않는다(강수량 수집기의 보강도). 이틀 지난 매분은 10분 칸만 남긴다(밤 정리) |
| 초단기예측 | 10분 | 발표 주기 10분, 실제 업로드는 발표 +2~8분 뒤 |
| 예측 분포 이미지 | 10분 | 발표분이 바뀔 때만 실제로 받는다 |
| 스방 강수량 | 10분 | 기상청과 같은 리듬. 다른 서버라 따로 돈다 |
| 단기예보 격자 | 10분 | 발표는 3시간마다(02·05·…·23시). 다 받은 발표분은 다시 부르지 않는다 |
| 경남 지도 500m(`grid`) | 10분 | 15분·60분·일강수 NetCDF 셋. 5분마다 만들어지고 +5분 남짓 걸린다. **10분 칸(:00·:10…)만** 받는다 — 재생 간격이 늘 맞아떨어지게 |
| 경남 지도 실황 5km(`odam`) | 10분 | 10분 발표 |

저장해 둔 수집 주기에 없는 새 수집기(`minute` 처럼 뒤에 생긴 것)는 기본 주기로 돈다(`main.intervals()` — 저장한 것만
읽으면 영영 예약되지 않는다). 종합 화면 메뉴바 주기 메뉴에서 '지금비' 창을 앞에 두면 이 수집 주기를 바꾼다(실시간 감시를 켠 동안 쓰인다).

화면의 갱신 주기는 **이것과 별개**다. 메뉴바에서 활성 창의 자료별로 따로 정하고,
바꿔도 기상청 호출량은 변하지 않는다 — 화면은 DB만 읽는다.

## 배치파일 인코딩 — 건드리지 말 것

`run.bat` 은 **CP949(한국어 ANSI)** 로 저장되어 있다. `.gitattributes` 의 `*.bat -text`
로 git 이 손대지 못하게 못 박아 두었다.

⚠️ **UTF-8 로 저장하면 실행이 중간에 멈춘다.** cmd 는 배치파일을 콘솔 코드페이지(한국어
   윈도는 949)로 읽는다. 글자가 깨지는 데 그치지 않고, 깨진 바이트가 파싱까지 어긋나게
   해서 어느 줄에선가 조용히 죽는다. 실제로 그렇게 멈췄다.
⚠️ 파일 첫머리에서 `chcp 949` 로 콘솔을 못 박는다. UTF-8(65001) 터미널에서 부르면
   CP949 파일이 다시 깨지기 때문이다.
⚠️ `—`(em dash, U+2014)는 CP949 에 **없다.** 배치파일에는 쓰지 않는다.

git 이 뱉는 커밋 제목만은 UTF-8 이라 따로 처리한다. `i18n.logOutputEncoding=cp949` 는
제목에 CP949 에 없는 글자가 하나라도 있으면 **그 줄을 통째로 포기**하므로, 파워셸로
읽어 그런 글자를 바꿔 찍는다. 그때 두 가지를 조심한다 —
큰따옴표 안에서는 cmd 가 `^` 를 처리하지 않으므로 `^|` 가 아니라 `|` 를 쓰고,
파워셸이 `@{u}` 를 해시테이블로 읽으므로 `'HEAD..@{u}'` 로 묶는다.

## 과거를 얼마나 채워 두는가

수집기는 **화면이 고른 구간만큼만** 과거를 받는다(`rain_depth` 설정, 기본 26시간).
`/api/rain?hours=N` 이 들어오면 그만큼 깊이를 올리고 그 자리에서 한 번 받아 온다.
화면은 `missing`(아직 한 줄도 안 받은 시각 수)이 0이 될 때까지 몇 번 더 물어본다.

⚠️ 이게 없을 때는 **'2일'을 골라도 26시간 앞이 영원히 비어 있었다.** 그래프 왼쪽이
   통째로 빈 채였고, 다음 주기가 와도 채워지지 않았다 — 수집기가 26시간만 보기 때문이다.

⚠️ 오래된 시각이 빈 응답으로 오면 **결측으로 적어 둔다.** 그냥 넘기면 행이 하나도
   안 남아 매 주기마다 영영 다시 묻는다(기상청에 그 자료가 없는 것뿐인데).

## 업데이트

배포처는 **GitHub 하나**다. 상주 서버(NAS)가 없어도, 각 PC 가 저장소를 클론해 두었으면
`설정 → 업데이트`에서 단추 한 번으로 최신 코드를 받는다. 속은 `git pull` 이다.
경남 강수 지도도 **설정(`Ctrl`+`,`) › 업데이트**에 같은 칸(이 PC 지금 받기 · 서버 갱신)이 있다 — 같은 API 를 부르고, 탭을 열 때 GitHub 를 본다.

| | |
|---|---|
| `GET /api/update` | 지금 버전 · 원격에 몇 개 밀렸는지 · 손댄 파일이 있는지 |
| `POST /api/update/pull` | 받아 온다 |
| `POST /api/update/restart` | 스스로 끝난다. 실행 스크립트가 다시 띄운다 |

⚠️ **덮어쓰지 않는다.** `--ff-only` 로만 당긴다. 그 PC 에서 손댄 파일이 있으면 합치기를
   시도하다 어중간한 상태로 남는 대신 **실패하고 이유를 그대로 보여 준다.** 현장 PC 가
   반쯤 병합된 코드로 도는 것보다 안 받는 편이 낫다.
⚠️ **받았다고 바로 바뀌지 않는다.** 화면(`index.html`)은 새로고침이면 되지만 파이썬
   코드는 프로세스를 다시 띄워야 한다. 무엇이 바뀌었는지 보고 필요할 때만 물어본다.
⚠️ **확인 실패를 '최신'으로 읽지 않는다.** 모르는 것과 최신은 다르다 — 인터넷이 막힌
   내부망 PC 에서 '최신입니다'라고 적으면 거짓말이 된다.

⚠️ **첫 한 번은 손으로 받아야 한다.** 이 기능이 들어오기 전 판에는 업데이트 갈피가
   없기 때문이다. 이미 깔린 PC 에서는 `git pull` 을 한 번 돌리고 `run.bat` 을 다시
   누르면, 그 뒤로는 화면에서 받을 수 있다.

⚠️ **새 구성요소(requirements.txt)는 받는 자리에서 깐다.** 화면의 '다시 띄우기'(종료 코드 42)는
   `run.bat` 의 설치 단계를 건너뛰고 서버만 다시 띄운다(`:runserver` 고리). 받기에서 안 깔면
   새 의존성 없이 떠서 그 기능만 실패로 남는다(경남 지도의 h5py 가 그랬을 것이다). 그래서
   `requirements.txt` 가 바뀐 업데이트는 이 서버의 파이썬으로 `pip install -r` 까지 하고
   `.venv/.installed` 를 새로 찍는다. 내부망에서 pip 가 막혀 실패하면 화면에 그렇게 적는다 —
   그때는 run.bat 창을 닫고 새로 띄우면 다시 깔려고 한다.

`run.bat`·`run.command` 는 서버가 **종료 코드 42** 로 끝났을 때만 다시 띄운다.
다른 코드로 끝나면(닫기·오류) 그대로 멈춘다 — 오류로 죽는 서버를 무한히 되살리면
무엇이 잘못됐는지 알 수가 없다.

## 저장공간

`설정 → 저장공간`에서 지금 얼마나 쌓였는지 보고 보관 기간을 정한다.
DB 한 파일과 예측 분포 이미지 캐시 두 군데에 쌓이는데 **이미지가 훨씬 빨리 자란다**
(한 발표분이 수십 장, 10분마다 새 발표분). 매일 새벽 4시 20분에 한 번 정리하고,
`지금 정리`로 즉시 돌릴 수도 있다. 되돌릴 수 없으므로 **오늘 것은 어떤 설정에서도 남긴다.**

## 판 대비 — 모니터마다 다르다

⚠️ **같은 색이 화면마다 다르게 보인다.** 맥에서는 바탕 `#090D13` 과 판 `#111823` 이
또렷이 갈라지는데, 흔한 윈도 모니터에서는 둘 다 '까만색'으로 뭉개져 판의 경계가
사라진다. 감마와 색역이 달라서다. 코드에 한 값을 박아 두면 어느 한쪽에서는 반드시
틀리므로, 보는 사람이 자기 화면에서 맞추도록 열어 뒀다.

`설정 → 화면 꾸미기`

| 조절기 | 하는 일 |
|---|---|
| **판 대비** | 바탕을 어둡게 밀고 판을 조금 들어 올린다. 테두리도 함께 세운다 |
| 바탕색 · 판 색 | 직접 지정. `✕` 를 누르면 자동으로 돌아간다 |

판을 크게 밝히지 않는 까닭은 글자가 그 위에 얹히기 때문이다 — 본문 대비가 같이
흔들린다. 끝까지 올려도 `#E8EEF6` 글자의 명암비는 15.5:1 → 13:1 로, 기준(7:1)보다
한참 위다. 밝은 테마는 판이 이미 흰색이라 더 들 곳이 없어 바탕만 민다.

**회색 테마(10-24).** 다크는 너무 까맣고 라이트는 너무 눈부시다는 말에 그 사이를 더했다 — 메뉴 `표시 › 테마 › 회색`
(지도는 설정 › 화면 › 테마). 바탕 `#2B2F35`(어두운 회색) · 판 `#363B42`(조금 밝은 회색) · 글자 `#F1F3F6`. 글자가 밝은 쪽이라
강수 램프 방향은 다크와 같고(값이 클수록 밝다) 첫 칸만 회색 판에서 갈라지게 한 톤 밝혔다. 특보 예약색은 다크 그대로.
종합 화면과 지도가 같은 자리(`gn-theme`)에 둬 한쪽에서 바꾸면 다른 쪽도 따라간다(토큰 블록은 두 파일에 같은 값).

⚠️ 대비 0은 **손대지 않은 것과 완전히 같아야 한다.** 판 계열을 판 색에서 늘
   계산하면 그게 깨진다 — 기본 토큰들이 판 색을 그냥 밝힌 값이 아니라 색조가
   조금씩 다르기 때문이다(계산하면 `#1E2836` 이 `#222832` 로 나왔다). 그래서 판 색을
   직접 고르지 않았으면 기본 토큰을 같은 만큼만 들어 올린다.

## 편집모드 — 글자 크기를 모음마다

메뉴바 오른쪽 `편집` 을 켜면 판 안의 **글자 모음**에 우클릭해 그 모음만 키우고
줄일 수 있다(70~220%, 10%씩). `Esc` 또는 `편집 중` 을 다시 눌러 나온다.

**판 전체가 아니라 모음마다다.** 벽에서 키우고 싶은 것은 판 하나가 통째가 아니라
그 안의 한 덩어리다 — 시군명만 키우고 싶을 때가 있고, 시간별 강수량만 키우고
싶을 때가 있다. 판을 통째로 키우면 자리를 먹어 오히려 보이는 줄 수가 줄어든다.

**표에서는 열이 단위다. 칸이 아니다.** 한 열은 통째로 같은 성격이라 한 시군만
키우는 일은 없다. 머리글도 제 열에 딸려 간다 — `다우지점` 은 시군명 열의 머리글이고
`누적 12시간` 은 강수량 열의 머리글이다. 그 열 어디를 눌러도 열이 통째로 바뀐다.

|---|---|
| 강수 타임라인 | 판 전체 · **시군·지점명 열** · **누적 강수량 열** · **시간별 강수량 열** · **합계 열** |
| 예측 분포 재생 | 판 전체 · 판 머리글 · 시각 시계 · 발표 딱지 · 범례 |
| 예측 상위 시군 | 판 전체 · 판 머리글 · 시각 눈금 · 시군 칸 |
| 지금 오는 비 | 판 전체 · 판 머리글 · 15분 열 · 60분 열 |

우클릭한 자리에서 **제일 좁은 모음**을 집는다. 빈 자리를 누르면 `판 전체` 다.
중첩은 안쪽이 이긴다 — `판 전체` 를 120%로 두고 `시군·지점명 열` 만 145%로 둘 수 있다.

⚠️ **무엇이 바뀌는지 물들여 보인다.** 편집 중 마우스를 올리면 그 모음 **전부**가
   점선으로 물든다(메뉴가 열려 있는 동안에는 붙잡아 둔다). 예전에는 `:hover` 로
   테두리를 둘러서 **마우스 밑 한 칸만** 감쌌는데, 실제로는 열이 통째로 바뀌는데
   화면은 한 시군만 바뀔 것처럼 말했다 — 실제로 그렇게 읽혔다.
⚠️ 글자를 키우면 한 화면에 드는 시군이 줄어든다. 표는 넘치면 스크롤된다
   (`.panel > .body { overflow: auto }`). 줄 높이는 그 줄에 든 열 가운데 **제일 큰**
   배율을 따라 바닥·천장이 올라간다.

⚠️ **편집모드에서만 바뀐다.** 상황실 화면은 늘 켜져 있고 사람이 지나가며 건드린다.
   평소 우클릭은 하던 일(다우지점 얹기)을 그대로 해야 한다.
⚠️ 배율은 **규칙(`<style id="fs-css">`)으로 깐다.** 인라인 `style` 로는 안 된다 —
   표는 그릴 때마다 `innerHTML` 이 통째로 갈려 얹어 둔 style 이 날아간다.
⚠️ 타임라인은 글자를 **SVG 안에도** 그린다(봉우리 숫자·시각 눈금). CSS만 바꾸면
   그것들만 그대로 남으므로, 배율이 바뀌면 그 판을 다시 그린다.
⚠️ 판 안 글자에만 태운다. 메뉴바·설정창까지 커지면 정작 자료가 들어갈 자리를 먹는다.
⚠️ 줄 높이(`ROWH`)의 바닥·천장도 배율을 따라 올린다. 안 그러면 22px 줄에서 잘린다.
⚠️ `.panel::after` 에 '편집 중' 배지를 얹지 않는다. **거기는 '갱신 중' 띠가 이미 쓴다**
   (`inset: 0`). 얹었더니 그 inset 이 남아 판만 한 타원이 화면을 덮었다.
   편집 중이라는 것은 메뉴바 딱지와 판 테두리로 알린다.

## 종합 화면 구성

왼쪽에 강수 타임라인, 오른쪽 위에 예측 분포 재생, **오른쪽 아래**에 한 판이 더 들어간다.
그 자리에 무엇을 놓을지 `설정 → 종합 화면`에서 고른다.

| | 무엇 |
|---|---|
| 예측 상위 시군 | 초단기예측 격자에서 뽑은 읍면동 순위 |
| 지금 오는 비 | **15분·60분 강수량 상위** — 왼쪽 칸 15분, 오른쪽 칸 60분 |

`지금 오는 비`는 **기상청 매분자료(`nph-aws2_min`)만 쓴다.** 스방에는 분 단위가 없다.
15분치를 왼쪽에 두는 까닭은 그게 제일 빠르기 때문이다 — 60분치는 이미 지나간 한 시간을
담고 있어서, 막 쏟아지기 시작한 곳을 한 박자 늦게 알린다. 한 칸에 몇 곳을 세울지는
설정에서 정한다(4~16곳).

15분 칸 머리의 토글로 **`그대로 ↔ ×4`** 를 오간다. 둘은 같은 값의 다른 표기다 —
15분에 12.5㎜는 `×4` 로 보면 50㎜/h 이고, 이건 '시간당 50㎜의 기세'라는 뜻이지
한 시간에 50㎜가 온다는 말이 아니다(그 기세가 이어질 때의 값이다). 환산해서 봐야
60분치·특보 기준(시간당 ㎜)과 같은 자로 견줄 수 있고, 그대로 봐야 실제로 떨어진 양을
안다. 자료를 다시 받지 않고 표기만 바꾼다. `×4` 일 때는 색 단계도 60분 것을 쓴다.

⚠️ 두 값은 **각자 제 시각**을 찾는다. 낡은 수집기가 15분치를 안 넣고 덮어쓰면 그 시각의
   15분 칸이 통째로 비는데, 그때 화면을 비워 버리면 멀쩡한 직전 자료까지 사라진다.
   시각이 서로 다를 때만 각 칸 머리에 그 시각을 적는다.
⚠️ 막대 색은 두 칸이 **다른 단계표**를 쓴다. 같은 눈금으로 칠하면 15분에 8㎜
   (시간당 32㎜의 기세)가 옅은 색으로 묻힌다.

## 합계 칸

**숫자만 적는다.** 예전에는 값에 따라 칸을 색으로 채우고 특보 기준을 넘으면 테두리까지
둘렀는데, 바로 옆 막대가 이미 같은 말을 하고 있어 한 화면에서 같은 사실을 세 번 강조하는
꼴이었다. 결측 시간 수(`1h`)도 여기 적지 않는다 — 값인지 단위인지 읽히지 않았다.
알아야 할 때는 줄에 마우스를 올리면 나온다.

## 예측 · 최근 1시간 단추

경남 강수 지도의 강수 누적 카드와 같은 두 단추가 강수 타임라인 메뉴바에 있다(이 PC 브라우저에 기억).

| 단추 | 켜면 | 끄면 |
|---|---|---|
| 예측(`F`) | 막대 끝 빗금 · `+6` · 타임라인 점선 · 히트맵 예측 칸 · 합계에 앞으로 N시간(`예측 3h/6h`) | 실측만 — 합계 머리는 `실측 합`, 구간 표시의 `+6` 도 뺀다 |
| 1시간(`H`) | 실측 막대의 끝 몫을 **최근 1시간**으로 어두운 빗금(기상청 직전 60분값, 없으면 마지막 칸 · 시군 평균은 지점들의 60분 평균) | 실측 막대 한 색 |

`누적순`이면 예측을 켜고 끌 때 줄을 다시 세운다 — 켜면 실측+예측, 끄면 실측 순.
⚠️ 예전에는 `누적순`이 다우지점(시군 펼침)에서만 먹었다 — 기본인 대표지점 · 시군 평균에서는
   골라도 그대로였다. 이제 셋 다 같다. 예측 분포 · 예측 상위 시군 판은 이 단추와 상관없다.

예측 값은 초단기 RN1 을 **그대로**(0.1㎜) 더한다 — 막대 끝 `+N` 과 예측 상위 시군 판의 합이 같은 숫자다(지도 위 카드도).
⚠️ 예전에는 시간마다 0·5·10·20·30·50 가운데 가까운 값으로 바꿔 더했다 — 3㎜ 가 5, 2㎜ 가 0 이 되어 거제(시간 3㎜)가
   타임라인에는 +25 인데 예측 상위 시군(그대로 합 15)에는 없었다(10-23 고침). 재난상황보고서 예측 표도 RN1 을 그대로 쓴다.

## 누적 막대 눈금

**늘 실제 값에 맞춘다.** 예전에는 특보 기준(110/180㎜)까지 눈금을 늘려 놨는데,
6.8㎜가 온 날은 막대가 3%밖에 안 차 아무것도 못 읽고 600㎜가 오면 넘쳤다.

**점선 두 줄도 실제 값에서 뽑는다.** 그때 화면에 있는 시군 누적값의 **중앙값**과
**상위 25%**(75분위)다. 값이 바뀌면 두 줄도 함께 움직인다.

⚠️ 예전에는 여기에 호우특보 12시간 기준(110/180㎜)이 박혀 있었다. **강수량은
   그보다 훨씬 유동적이다.** 900㎜ 온 날에는 두 줄이 막대 왼쪽 끝(12%·20%)에
   나란히 붙어 어느 시군도 가르지 못했고, 5㎜ 온 날에는 눈금 밖이라 아예 긋지도
   못했다. 어느 쪽이든 '기준'이 하는 일이 없었다. 분위수는 5㎜ 오는 날에도
   900㎜ 오는 날에도 늘 눈금 안에 있고, 늘 같은 것을 말한다 — **이 시군이 도
   전체에서 어디쯤인가.**
⚠️ 특보 예약색(주의보 노랑·경보 빨강)으로 긋지 않는다. 특보 기준이 아니기 때문이다.
   무강수라 중앙값이 0이면 그 줄은 긋지 않는다.

한 시군만 유독 길면 나머지가 다 뭉개진다. 그때는 눈금을 한 번 꺾어(broken axis)
뒷부분을 눌러 담고, 꺾은 자리에 **물결 자국**을 남긴다. 실측: 662㎜ 한 줄과
150㎜대 여럿이 섞였을 때 — 꺾기 전 142.5㎜는 21.5%였고, 꺾은 뒤 58.1%가 되어
서로 견줄 수 있게 됐다.

## 묶음 칸은 다른 자로 잰다

히트맵은 지난 시간을 `01~23` 처럼 묶어 한 칸에 담는다. **그 칸은 1시간 칸과
색조도 눈금도 다르다** — 시우량 램프는 청색(`--rain-*`), 묶음 램프는 청록(`--acc-*`).

⚠️ 같은 램프로 칠했을 때 **23시간 합계 64.5㎜가 1시간 50㎜와 똑같은 최고 단계**로
   앉았다. 오래 묶을수록 무조건 진해지는 바이어스다 — 색이 '많이 왔다'가 아니라
   '오래 묶었다'를 말하게 된다.

눈금은 **묶음 길이마다 따로, 그때 화면에 있는 실제 값에서** 잡는다(`ACC_FRAC`).
길이가 다른 두 묶음은 각자 제 눈금을 쓴다 — 한 눈금에 얹으면 긴 쪽이 늘 이긴다.
칸은 세로로 읽는 것이다(이 구간에서 어느 시군이 두드러지나). 실측(8.28. 사례):

```
23시간 묶음  최대 64.5㎜  →  64.5 가 그 열의 최고 단계
24시간 묶음  최대 105㎜   →  같은 64.5 는 중간 단계
```

0.5㎜를 최고 단계로 칠하지는 않으려고 눈금 바닥을 10㎜로 둔다.

## 데모 시연

비가 안 오는 날에는 화면이 온통 0.0 이라 무엇을 보여 주는 화면인지 알 수 없다.
`표시 → 데모 시연…`(또는 `설정 → 데모 시연`)에서 실제로 호우가 내렸던 때를
그대로 되돌려 띄운다. 화면을 점검할 때 쓴다 — 비가 안 오는 날에는 무엇이 고장 나도
0.0 이라 알 수가 없다.
보는 동안 화면 맨 위에 띠가 떠 있어 실황과 헷갈리지 않는다.

| 사례 | 내용 |
|---|---|
| 2026.8.28. 경남 호우 | 실측. 김해 율하 123.5㎜/일, 창원 111.0㎜/일 |
| 2026.8.28. 11시 — 한창 올 때 | 봉우리에서 끊은 화면. **그때 발표된 초단기예측이 함께 담겼다** |
| 2026.8.28. 호우 ×2 | **가상.** 같은 실측을 두 배로 키운 시연용 — 경보까지 걸린 화면 |

**강수량도 초단기예측도 실측이다.** 스방 265개소의 시간강우량과, 격자 API
(`nph-dfs_vsrt_grd`)로 받은 **그 시각의 실제 발표분**을 파일로 굳혀 둔다
(8.28. 11시 발표 → 남해 고현면 20㎜, 창원 진동면 20㎜).

담지 못한 것이 둘 있다.

- **특보.** 이력 API(`wrn_met_data.php`)가 이 키로 403 이라 과거 발표 내역을 받을 수 없다.
  그래서 담긴 강수량에 호우 기준(3시간 60/90㎜, 12시간 110/180㎜)을 적용해 **산출**하고,
  화면에 `산출`이라고 적어 발표 내역과 구분한다.
- **예측 분포 이미지.** `nph-qpf_ana_img` 는 과거 시각이 404 다. 최신분만 나온다.

예측이 안 담긴 사례에서는 **예측을 비운다** — 오늘 예측을 8월 자료 옆에 붙이면
통째로 거짓말이 된다. 분 단위 자료도 마찬가지라 `지금 오는 비` 판은 데모에서 비워 둔다.

⚠️ 스방은 며칠치만 남긴다. 그래서 사례를 **파일로 굳혀** 두고, 새 사례는 원본을 다시
   받는 대신 굳혀 둔 파일에서 잘라 만든다(`build_cut`).

## 스방 자료

기상청과 **다른 관측망**이다. 경남 자체 AWS 212개소에 기상청 것을 더해 **시군 평균**을
낸다. 기상청 값은 시군 대표지점 하나이므로 두 숫자는 뜻이 다르고, 실제로 자주 어긋난다
(고성 학림 500.5mm를 기상청 AWS는 아예 못 본다). 그래서 `obs_hourly` 에 섞지 않고
`bangjae_rain` 에 따로 쌓고, 화면에도 출처를 밝혀 적는다.
같은 응답(`dt090/list3`)에서 시군별 **다우지점**(그 시군에서 제일 많이 온 곳)도 함께
받는다 — 따로 부르면 두 값의 기준시각이 어긋난다.

### 지표가 자료원을 정한다

표 머리글을 누르면 `대표지점 → 다우지점 → 시군 평균`으로 돌아가고, **관측망도 같이 바뀐다.**

| 지표 | 자료원 | 왜 |
|---|---|---|
| 대표지점 | 기상청 56개소 | '시군 대표지점'은 기상청 관측망의 개념이다 |
| 다우지점 | **스방 265개소** | 후보가 다섯 배. 56개소로 고르면 창녕 계성 28.5㎜를 아예 못 본다 |
| 시군 평균 | **스방 265개소** | 56개소로는 창원이 5개소·진주가 3개소다. 그걸 시군 평균이라 부를 수 없다 |

스방 265개소면 창원 23·진주 18·합천 23개소가 되고, 다우지점은 스방이 스스로 내는
`rtu_area` 와 비가 온 모든 시군에서 일치한다(계성·마상·가야산·상동·구기·오부·서하…).
머리글 옆 딱지가 지금 어느 관측망인지 늘 밝힌다. 스방이 멈추면 기상청으로 물러서고
딱지가 `스방 안 됨→기상청` 으로 바뀐다 — 조용히 다른 값을 보여 주지 않는다.
설정 → 자료에서 한쪽으로 고정할 수도 있다.

시군 평균 줄은 `창원²³` 뿐이다 — 시군명만 크게, 개소 수는 윗첨자. 줄을 찾는 눈은
시군을 보지 '평균 23개소'를 보지 않는다. 시군을 누르면 같은 기간의 **지점별 강수량**이
많이 온 순으로 펼쳐지고, 몇 개소가 자료를 주는지도 함께 적는다.

### ⚠️ 스방 기간조회(list3)와 값이 다른 두 가지 이유

화면은 **그린 시간 칸을 그대로 더한다** — 표의 누적은 곡선의 합이어야 하기 때문이다.
스방의 시군별 강우량 화면(`dt090/list3`)과 대조해 보니 어긋나는 자리가 둘 있었고,
둘 다 **시간강우량(dt096) 쪽이 맞았다.** 실측 근거를 남긴다.

**하나. 여러 날을 걸치면 첫날이 한 번 더 세어진다.** `일누적`이 다음날 01시에야
리셋되는 구조라 그렇다.

```
사천 곤양  9.3. 시간강우 합계 30.5㎜  →  9.3.~9.5. list3 다우지점 61.0㎜  (= 30.5 × 2)
창녕 계성  9.2. 에 28.5㎜            →  9.3. 하루만 조회해도 계성 28.5 가 얹혀 온다
```

**둘. 시군 집계에서 기상청 관리 지점이 빠진다.** 스방은 같은 시군을 관리주체에 따라
`창원`(경남)·`창원시`(기상청)로 나눠 담는데, list3 의 시군 줄은 경남 쪽만 센다.

```
창원 9.3.  경남 18개소 평균 2.56 (최대 오동 27.5)
           기상청 5개소 평균 14.58 (최대 마산회원 44.5)  ← 여기가 통째로 빠진다
           전부 23개소 평균 5.17 (최대 마산회원 44.5)
           list3: 평균 3.7 · 다우지점 '오동(27.5)'
```

즉 그날 창원에서 제일 많이 온 곳은 **마산회원 44.5㎜**(15시에 43.5㎜)인데 스방 화면은
오동 27.5㎜를 다우지점으로 내놓는다. 대시보드는 265개소를 다 보므로 마산회원을 잡는다.
처음에 기상청 AWS 56개소를 버린 이유(고성 학림 500.5㎜)와 같은 종류의 누락이다.

하루를 통째로, 한쪽 관리주체 쏠림이 없는 시군으로 대조하면 둘이 정확히 맞는다
(사천 7.62 vs 7.3, 진주 0.97 vs 1.0, 하동 4.14 vs 4.1, 고성 1.40 vs 1.4).

**조회 시각 규칙.** 스방은 `toTime=H` 를 '**H시까지**'로 본다. 지금이 06:47인데 06으로
물으면 06:00에서 잘려 **지금 오는 비가 빠진다.** 그래서 **다음 정시(07)로 조회**하고,
받은 값은 07시치가 아니라 지금까지의 값이므로 **기준시각은 `지금 - 5분`(06:42)으로
저장**한다. 없는 시각을 적지 않으려는 것이다. 23시대에는 다음 정시가 없어 23으로 둔다.
규칙은 `app/bangjae.py` 의 `as_of()` 한 곳에 있다.

**계정은 필요할 때만 쓴다 — 없다고 건너뛰지 않는다.** 부르는 자리에 따라 로그인 없이도
자료가 그대로 온다. 상황실 내부망 PC 에서 실측(2026-09-05): 계정 없이 `dt090/list3`
18개 시군, `dt096/list` 532줄이 왔다. 그래서 **일단 부르고, `[]` 가 올 때만** 로그인한다.

⚠️ 예전에는 계정이 없으면 한 발도 안 떼고 건너뛰었다. 그 바람에 상황실에서는 화면이
   늘 `스방 안 됨→기상청` 이었다 — **서버는 멀쩡했고 부르지를 않았다.**
   수집기록에 `스방 계정 없음 — 건너뜀` 만 남아 있어 조회 실패와 구분되지 않았다.

계정이 필요한 자리라면 `config/api_keys.txt` 의 `BANGJAE_ID`/`BANGJAE_PW` 로 넣는다.
비워 두면 옆 프로그램(`code/bangjae`)이 DPAPI로 저장해 둔 계정을 쓴다. 둘 다 없는데
서버가 로그인을 요구하면 이 수집기만 `조회 실패`로 남고 나머지는 정상 동작한다.

주소는 `BANGJAE_URL` 환경변수 또는 `config/api_keys.txt` 의 `BANGJAE_BASE` 로 바꾼다
(기본 `http://112.100.10.186:8080`). 내부망 밖에서는 이 주소가 응답하지 않으므로
**연결 타임아웃만 5초**로 따로 두었다 — 한 번이 60초씩 걸리면 10분 주기를 갉아먹는다.

**내부망 SSL.** 내부망 장비가 인증서를 갈아 끼워 기본 설정으로는 검증에 걸린다.
`DISABLE_SSL_VERIFICATION` 이 기본 켜짐(=검증 안 함)이고, 끄려면 `0` 으로 둔다.

## 예측 분포 범례

그림 **오른쪽 가운데에 세로로** 얹는다. 센 값이 위 — 기상청 원본 범례와 같은 방향이라
둘을 나란히 놓고 봐도 헷갈리지 않는다. `예측 분포 재생` 창의 **범례** 메뉴로 켜고 끈다
(고른 값은 기억된다).

⚠️ 처음에는 아래쪽에 눕혀 놨는데, 비구름이 화면 아래로 몰릴 때 통째로 가렸다.
   비가 오는 자리를 가리는 범례는 없느니만 못하다. 오른쪽은 대체로 바다라 덜 가린다.

**색은 흉내 내지 않는다.** 기상청 QPF 색계는 우리 청색 램프와 전혀 달라서 비슷하게
칠하면 거짓말이 된다. 원본 그림 오른쪽 끝의 세로 색 띠에서 24단계를 그대로 뽑아
`qpf_legend` 설정에 담아 두고(`GET /api/qpf/legend`), 화면은 그것을 가로로 편다.

⚠️ 예전에는 화면이 범례 **그림**을 받아 캔버스로 색을 뽑았는데, 그 그림 주소를 담는
   변수가 끝내 비어 있어 범례가 통째로 안 그려졌다. 조용히 사라지는 길이라 아무도
   몰랐다. 이제 색을 못 받았으면 그렇게 적는다.
⚠️ 경계값은 원본 범례에 **찍힌 대로** 옮겨 적었다(그림 속 글자라 뽑아낼 수 없다).
   약한 쪽에 `0.1` 이 **두 번** 나오는 것도 기상청 범례가 그렇게 찍는 것이지 오타가
   아니다. 그래서 화면에는 `0.1 · 1 · 5 · 10 · 20 · 30 · 50 · 110` 만 띄엄띄엄 적는다.
⚠️ 단위(mm/h)를 눈금과 같은 격자에 넣으면 칸이 하나 늘어 눈금이 통째로 한 칸씩
   밀린다. 색 띠와 눈금만 같은 격자를 쓰고 단위는 그 밖에 둔다.
⚠️ 저장공간 막대에 `.bar` 라는 흔한 이름을 붙였더니 그 `height: 7px` 가 범례 색 띠를
   눌러 190px 짜리가 7px 로 찌그러졌다. `.usebar` 로 바꿨다 — 흔한 이름은 반드시
   부딪힌다.
⚠️ 어두운 상자를 눈금·단위까지 감싸면 그만큼 지도를 가린다. 상자는 **색 띠에만**
   두르고 글자는 지도 위에 그대로 얹는다(폭 52px → 31px).
⚠️ 그 글자색을 테마에서 가져오면 안 된다. 얹히는 바탕이 우리 판이 아니라 **기상청
   지도 그림**이고 그건 다크 테마에서도 늘 흰 바탕이다. 테마색(밝은 회백색)으로
   뒀더니 흰 바다 위에서 통째로 사라졌다. 검은 글자에 흰 테두리를 두른다.

## 예측 이미지 호출량

한 발표분의 장수 = **최대 선행시간 ÷ 간격**. 발표가 10분마다 나오므로
이 숫자가 곧 10분당 호출 수다. 화면의 `예측 분포 재생` 창 메뉴에서 바꾼다 — 선행 3 · 4 · 5 · 6시간
(`ahead` 180 · 240 · 300 · 360). 지도 판 설정 › 재생 '이미지 길이'도 같은 설정이다(다음 발표분부터 그만큼 받는다).

| 간격 · 선행 | 장수 | 하루 호출 |
|---|---|---|
| 10분 · 6시간 | 36 | 5,184 |
| 20분 · 3시간 | 9 | 1,296 |
| 30분 · 3시간 | 6 | 864 |

**발표가 났는지 먼저 확인하고 난 것만 받는다.** 미래 시각을 요청하면 최신
발표분이 오는 성질을 이용해, 이미지에 찍힌 발표시각 표시를 해시로 비교한다.
확인은 호출 한 번이고, 정시 이후 감시 구간에서만 한다.
재는 방법과 실측값은 `docs/02-발표주기.md`.

### ⚠️ '비가 안 오는 그림'을 '아직 안 올라온 그림'으로 보면 통째로 멎는다

**경남에 비가 없는 정상 그림은 색이 딱 두 가지다** — 바탕 `(250,250,250)` 과
해안선 `(0,0,0)`. 예전 판정(`색 2가지 이하 = 빈 그림`)이 이걸 '아직 안 올라온
그림'으로 읽었다. 그래서 **비가 그치면 수집이 멎었다.**

실측: 2026.9.7. 11:50 발표분이 **열흘 동안** 화면에 걸려 있었다. 훑기는 '가진 것
다음 슬롯'(9.7. 12:00)에서 출발하는데 그 자리에 비가 없어 첫 걸음에서 끊겼다.

⚠️ **저절로 풀리지 않는다.** 9.7. 12:00 은 과거 이미지라 영원히 안 바뀐다 —
   오늘 비가 와도 오늘 슬롯까지 가지를 못한다. 실측(9.17. 09:20, 비 오는 중):
   옛 코드는 1걸음에서 끊기고 `최신 발표분 = None` 이었다.

고친 자리 둘 —

| | |
|---|---|
| **판정** | 색 가짓수가 아니라 **해안선 픽셀 수**로 본다. 올라온 그림에는 경남 박스 안에 늘 30,925px(비 위에 그려진다), 안 올라온 그림에는 0px. 안 올라온 그림은 `(240,240,240)` 한 색으로 꽉 찬 950×800 이다 |
| **훑기 시작점** | 가진 것이 아무리 낡았어도 **90분 앞에서부터** 시작한다. 며칠 꺼져 있었다고 며칠 전부터 걸으면 따라잡는 데 호출이 슬롯 수만큼 들고(열흘이면 1,440번), 중간에 한 칸만 막혀도 영영 못 따라잡는다 |

⚠️ **비가 없는 프레임도 저장한다.** '앞으로 3시간 비 없음'은 빈손이 아니라
   정보다. 예전에는 버려서 한 발표분이 18장을 못 채웠고(실측: 9.7. 11:50 이
   ef 10~110 열한 장뿐), '다 받았다' 판정이 안 서서 매 주기마다 같은 발표분을
   다시 받으러 갔다.

## 지켜야 할 것

- **비밀은 저장소에 넣지 않는다.** `config/api_keys.txt`·`.env`는 `.gitignore`에 있다.
  로그에도 남지 않게 httpx 로거를 WARNING으로 낮춰 뒀다(요청 URL에 `authKey`가 실린다).
- **조회 실패와 '자료 없음'을 구분한다.** 실패는 저장하지 않고 다음 주기에 다시 시도한다.
  DB의 `quality`, 화면의 `0.0` / `—` / `✕`가 그 구분이다.
- **시각은 전부 KST.** UTC로 바꾸지 않는다(기상청 API가 KST를 쓴다).

함정 목록은 `handoff-mac/docs/05-pitfalls.md`, 화면 설계는 `handoff-mac/docs/07-dashboard-design.md`.

## 권역 예보 — 단기예보를 권역·시군으로

`설정 → 종합 화면 → 오른쪽 아래`에서 **권역 예보**를 고르면 그 자리에 뜬다.
메뉴바에서 **권역/시군**, **오늘/내일/모레**를 고른다. 강수량만 그린다 — 권역별 기온 범위는 상황실에서 쓸 일이 적다.

권역은 기상청 예보 문구 단위다(`app/domain/regions.py` 의 `ZONES`).

| 권역 | 시군 |
|---|---|
| 경남서부내륙 | 함양, 거창, 합천, 진주, 하동, 산청 |
| └ 북서내륙 | 함양, 거창, 합천 |
| └ 남서내륙 | 진주, 하동, 산청 |
| 경남중부내륙 | 밀양, 의령, 함안, 창녕 |
| 경남동부내륙 | 김해, 양산 |
| 창원 (경남중부남해안) | 창원 |
| 경남서부남해안 | 통영, 사천, 거제, 고성, 남해 |

권역 이름을 누르면 그 밑에 시군이 펼쳐진다(다시 누르면 접힌다. 펼친 상태는 그 화면에 남는다).
서부내륙이 상위, 북서·남서내륙이 그 하위라 들여 적는다. 중부남해안은 창원 하나뿐이라
'창원'으로 적는다.

한 줄이 격자 분포다. 격자 칸(읍면동 대표 격자, 약 5km)마다 그날 강수량을 더한 뒤
권역 안에서 **상자 = 20~80백분위, 세로 금 = 중앙값, 점 = 95백분위(많이 오는 곳)**로 그린다.
오른쪽 숫자는 상자를 기상청이 쓰는 범위(5~10, 5~20, 10~40, 20~60 …)로 옮긴 것이다.
▲▼ 는 직전 발표보다 중앙값이 뚜렷이 오르거나 내린 것이다(3㎜ 이상이면서 20% 이상).

⚠️ **'오늘'은 발표 뒤 남은 시간만 담는다.** 14시 발표면 14~24시다. 판 머리글에 늘 그 구간을 적는다.
⚠️ **직전 발표 대비는 같은 시간끼리 견준다.** 직전 발표는 오늘의 더 이른 시간을 담고 있어
   그냥 견주면 늘 줄어든 것으로 보인다.
⚠️ **실측: PCP 는 30에서 막힌다** (2026-10-01, 8.28. 호우 발표분). `tmfc` 10자리(`YYYYMMDDHH`)로
   과거 발표분도 받아지고, PCP 는 **1㎜ 단위 정수**로 온다. 8.28. 23시·05시 발표 48개 대상시각에
   0~30 이 빠짐없이 나오고 **31 이상은 한 번도 없다** — 여섯 시각의 최대가 딱 30이다. 30 은
   '30㎜ 이상' 범주로 읽어야 한다(50 이상 표기는 아직 못 봤다). 그래서 시간당 30㎜ 를 넘는 비가
   예보된 날은 **권역 합계와 최대가 모자라게 나온다.** 극값은 초단기·실측으로 본다.

## 경남 지도 — 격자 강수

> 만드는 중. 지금은 0단계(실측)만 끝났다. 화면은 `map.html` 로 따로 먼저 만든다.

경계(SVG) 위에 격자 강수(Canvas)를 겹친다. 격자는 **기상청이 준 칸 그대로** 찍는다 —

하고, 조금이라도 어긋나면 비가 엉뚱한 시군에 그려진다.

**투영.** NetCDF 전역 속성에는 `Lambert Conformal Conic`, `map_slon=126`, `map_slat=38`,

| 식 | 칸별 위경도와 차이(전국) |
|---|---|
| **타원체(GRS80·WGS84) 람베르트, 표준위도 30°·60°, 원점 126°E·38°N, 500m, 원점 칸 (880, 1540)** | 최대 **0.0016칸**(0.8m) |

칸 번호는 0부터, (열, 행) = (880, 1540) 이 126°E·38°N 이다.

두 가지로 더 확인했다.
- **기상청 지점 API**(`nph-sfc_obs_nc_pt_api` — 서버가 경위도→칸을 한다)에 이웃 8칸과 값이
  0.4㎜ 이상 다른 칸만 16곳 골라 물었다. **16/16 같은 값.** 한 칸만 어긋나도 드러나는 시험이다.
- **관측 대조**(8.28. 11시 60분 강수, 매분자료 전국 711개소): 차이 중앙값 0.0㎜, 0.5㎜ 이내 87%.
  행을 뒤집으면 경남 56곳에서 0.5㎜ 이내가 59% → 20% 로 무너진다. 창원(155) 관측 0.9 / 칸 1.5,
  진주(192) 3.3 / 3.0 — 객관분석이라 관측값을 그대로 지나지는 않는다.

⚠️ **`d3.geoConicConformal` 은 구면이다.** 그대로 쓰면 경남 안에서 경계와 격자가 최대 800m
   어긋난다. 경계는 파이썬에서 타원체 식으로 **격자 좌표로 미리 바꿔** 저장한다.
⚠️ **일강수(rn_day) 자정.** 00:00 값은 **전날 총량**이다(8.28. 23:55 최대 140.2 → 00:00 140.2).
   00:05 는 **반쯤 리셋된 값**이다(최대 13.2 → 00:10 에 0.4 → 00:30 1.5 → 01:00 3.2). 00:10 부터 믿는다.
   AWS `RN_DAY` 와 같은 성질인데 리셋 시각이 다르다(AWS 는 01시).

`tools/build_geo.py` 한 번으로 만든다(node 필요 — 단순화는 `npx mapshaper`). 원본은

### 수집 · 저장

받자마자 경남 bbox 만 잘라 `data/cache/grid/{층}/{키}.u16.gz` 에 둔다. 전국 원본은 두지 않는다.

| 층 | 자료 | 키 | 보관 |
|---|---|---|---|
| `obs15`·`obs60`·`obsday` | 500m NetCDF(`sfc_grid_nc_down.php`) | 기준시각 | 3일 |
| `odam` | 실황 RN1 5km | 발표시각 | 3일 |
| `vsrt` | 초단기 RN1 5km — **기존 수집기가 받는 격자를 그대로** | 발표_대상 | 최근 3발표분 |
| `shrt` | 단기 PCP 5km — **기존 수집기가 받는 격자를 그대로** | 발표_대상 | 최근 3발표분 |

값은 0.1㎜ uint16(`0` 무강수, `65535` 결측), 행은 남→북. **조회 실패는 파일이 없는 것**이다 —
결측과 다르다. 화면은 층마다 기준시각을 보고 늦었는지 안다.

| 하루 (PC 한 대) | 호출 | 용량 |
|---|---|---|
| 500m 셋 × 10분 | 432 | 20~100MB (NetCDF 46~430KB) |
| 실황 5km × 10분 | 144~290 (아직 없으면 한 칸 물러서 한 번 더) | 50~100MB |
| 초단기·단기 | **0** — 이미 받는 격자를 bbox 째 한 번 더 저장할 뿐 | 0 |

⚠️ **500m 는 NetCDF 로 받는다.** 바이너리(disp=B)는 같은 자료가 16.8MB 라 10분마다 셋이면
   하루 7.3GB 다. 기관키 한도(하루 50GB)는 대시보드를 띄운 PC 마다 나눠 쓴다.
   대신 `h5py`·`numpy` 가 필요하다(requirements). 없으면 이 수집기만 실패로 남는다.
⚠️ **받을 때마다 격자 틀을 확인한다.** NetCDF 속성(원점 칸 880·1540, 126°E·38°N, 0.5km,
   2049칸)이 실측과 다르면 저장하지 않고 실패로 남긴다 — 틀이 바뀐 채 그리면 비가 엉뚱한
   시군에 그려진다.
⚠️ 일강수는 00:00·00:05 를 받지 않는다(위 실측). 그동안 화면에는 23:55 값이 **제 시각과 함께** 남는다.

**관측소 값도 격자 시각에 맞춰 받는다.** 500m(·실황 5km)를 받은 시각마다 매분자료(`nph-aws2_min`)를
한 번 더 불러 `obs_minute` 에 그 시각으로 둔다(시각마다 한 번, 이미 있으면 안 부른다). 지도 '관측소'
층이 격자 옆에 놓을 실측이다. 강수 수집기의 매분 보강은 '지금 −1분'이라 10분 칸과 거의 안 맞는다 —
시각이 어긋난 둘을 나란히 두면 비교가 아니다. 이 호출이 실패해도 격자 수집을 실패로 치지 않는다
(메시지에만 남고, 화면은 그 시각 관측소 값이 없다고 적는다). 하루 +144회, 응답 수십 KB.

**빠진 정각을 메운다(60분만).** 수집기는 늘 최신 한 장만 받으므로 서버가 꺼져 있던 동안의 정각이 빈다.
격자 누적(오른쪽 카드 격자 기준)은 매시 정각 60분 격자를 더하므로, 누적 구간(설정 `acc_hours`) 안의
빠진 정각을 최근 것부터 **한 번에 4장까지** 받는다 — 12시간 구멍이면 30분, 48시간이면 두 시간에 찬다.

위치는 `data/geo/stations.json`(`tools/build_stations.py`, 기관키 필요 — 지점을 옮기거나 새로 놓았을 때만
다시 돌린다). ⚠️ 지점정보 API(`stn_inf.php`)는 이 키로 403 이다. 일자료(`sfc_aws_day.php`)가 지점마다
경도·위도·노장 해발고도를 같이 주므로 그것을 쓴다. 경남 56곳 중 55곳 — **사천공항(161)** 은 정시·매분·
일자료 어디에도 값이 없어(늘 결측) 위치도 없다. 경남 땅에 있는데 56곳 목록에 없는 지점 **하이(45, 고성)**
가 있다 — 목록(`data/aws_stations.json`)은 종합 화면과 같이 두었다.

**지연 판정** — 평소 가장 늙은 때보다 더 늙으면 층을 흐리게 하고 `자료 지연` 을 붙인다.

| 층 | 평소 나이 | 지연 |
|---|---|---|
| 500m | 6분 물러선 10분 칸을 10분마다 → 6~26분 | 30분 넘으면 |
| 실황 5km | 발표 +3~13분, 10분마다 | 30분 넘으면 |
| 초단기 | 발표 슬롯에서 10분 물러서고 10분마다 → 10~30분 | 30분 넘으면 |
| 단기 | 발표 +20분부터 받는다 | 지금 받을 수 있는 발표분보다 30분 넘게 묵으면 |

**시군 통계**(`/api/grid/sigun`)는 시군 칸 지도로 낸다. 결측 칸은 평균에서 **뺀다**(0 으로 치지
않는다). 최대가 여러 칸이면(5km 칸을 500m 로 펼친 경우) 그 칸들 한가운데서 가까운 칸을 골라
그 칸이 드는 읍면동을 적는다. 5km 층은 500m 칸으로 펼쳐 같은 칸 지도를 쓴다.
단기 합계는 한 시간이라도 결측인 칸을 결측으로 둔다. PCP 가 30(=30㎜ 이상)인 시간이 든 칸 수를
`X-Grid-Capped` 로 함께 준다 — 그 칸의 합계는 **하한**이다.

### 화면 — `/map.html`

아직 종합 화면(`index.html`)에 판으로 붙이지 않은 **별도 창**이다. 종합 화면 메뉴바 오른쪽의
**`지도 ↗`** 를 누르면 지도 전용 창이 하나 뜬다(다시 누르면 새로 안 만들고 그 창이 앞으로 온다.
Ctrl+클릭은 새 탭). run.bat 이 여는 웹앱 창에는 주소창이 없어 주소를 칠 수 없기 때문이다.
그 창을 다른 모니터로 끌어 F11 로 채우면 된다. 주소는 `http://localhost:8000/map.html`.

⚠️ 지도를 못 열게 막혀도(팝업 차단) **종합 화면을 지도로 넘기지 않는다** — 벽면 화면이 사라진다.

**머리줄은 없다 — 지도 위 왼쪽에 제목**(층 이름 · 시각 · 작게 출처)이 떠 있고, **제목을 누르면 층 메뉴**가
내려온다(유리판이 살짝 커지며 열리고 줄이 하나씩 따라 들어온다). 메뉴는 **'무엇을 보나' 다섯 줄**이다 —
줄마다 짧은 설명 · 최신 시각 · 숫자 키. ↑↓ · Enter · Esc 도 된다. 층을 바꾸면 제목이 스며 올라온다.
메뉴 맨 아래에 패널 · 도움말 · 설정. 데모(실황 · 테스트 · 재현 사례)는 설정 › 데모 로 옮겼다.

|---|---|---|
| 실측 머리 **자료** `격자 500m \| AWS` | `B` | 아래 1시간 · 누적 줄과 오른쪽 '강수 누적' 카드 기준을 **같이** 바꾼다 |

| 단기 예보 `오늘 · 내일` | `5` `6` | `shrt_today` · `shrt_tomorrow` |

⚠️ 예전에는 8줄(15분 · 60분 · 누적 · AWS 누적 · 실황 / 초단기 · 단기 오늘 · 내일)이었고, 지도의 '누적 / AWS 누적'과
   카드의 AWS↔격자 기준이 따로 놀아 둘이 다른 값을 보일 수 있었다. 이제 자료는 하나(`acc_basis`)다 — 저장해 둔 층이
   자료와 어긋나면(예: 60분 + 카드 AWS) **띄울 때 자료 쪽으로 맞춘다**(→ AWS 1시간). `?layer=` 로 고른 층은 반대로 자료를
   정한다(`?layer=obs60` → 격자, `?basis=` 를 같이 주면 그것이 먼저).

고른 층은 서버 설정(`map`)에 남는다 —
층 단추 가운데 **단기 오늘·내일은 켜고 끄는 단추**다 — 켠 것을 한 번 더 누르면(숫자 키도) 풀고 그 앞에 보던 층으로 돌아간다(카드도 '강수 누적'으로). 앞 층이 없으면 1시간.
오른쪽 위 도구는 지도 위 작은 유리 아이콘 셋 — 창(오른쪽 패널) · ?(도움말) · 톱니(설정), 패널이 열리면 그
왼쪽으로. 설정 › 화면 '오른쪽 위 도구'에서 마우스를 움직이면(기본 — 움직이면 2.5초 보였다 숨는다, 처음 뜰 때 한 번) · 항상 · 숨김(이 화면마다 기억). 어느 PC 에서 열어도 같은 층. 키: `1`~`6` 층 · `Space` 재생 · `←` `→` 한 장씩 · `L` 패널 ·
`A` 특보 · `S` 관측소 · `V` 지점 값 글자 · `B` 자료(격자 ↔ AWS — 지도 1시간 · 누적과 카드 기준) · `R` AWS 실시간 감시 · `Q` 아래에 초단기예측 이미지 재생 · `W` 바다 위젯 · `C` 지도 위치 · `T` 테스트 · `?` 도움말 · `Ctrl`+`,` 설정 ·
`Esc` 시군 고르기 풀기.

**도움말(`?` 단추 · `?` 키)** — 설정 단추 왼쪽. 세 칸이다: **자료 출처**(층마다 원본 API · 무엇으로 어떻게
만드나 · 주기 · 기상청 어디서 쓰나), **용어**(객관분석 · 다우지점 · 결측과 0 · 하한 · 산출 특보 …),
**조작**. '기상청 어디서 쓰나'는 날씨누리 지도가 받아 가는 파일을 직접 열어 확인한 것만 ✔ 로 적었다
(2026.10.3): 관측 › 3시간누적강수·현재기온 = 실황 5km(149×253), 관측 › 일강수 = AWS 지점값 약 720곳을
화면에서 면으로 칠한 것, 바람 표출 = 단기예보 격자. **500m 고해상도 격자는 날씨누리 지도에 쓰이지 않는다**

#### 레이어 — 왼쪽 위

`레이어 ▾` 를 누르면 지도 위에 겹칠 것을 고른다. 고른 것은 서버 설정(`overlays`)에 남는다.
**기상특보**(`A`) · **관측소**(`S`) · 그 밑에 딸린 **지점 강수량 글자**(`V`, 관측소를 켰을 때만)가 있고
차츰 늘린다(시군 위 막대 등 — `map.html` 의 `OVL` 에 한 줄 보태면 메뉴에 뜬다).
`?ov=alerts,stations,stnval` 로 켠 채 띄울 수도 있다.

**관측소 — 면은 그림, 점은 정답.** 500m 격자는 관측소 사이를 메운 분석값이라 관측소 자리에서도 값이
다르고 센 비의 봉우리가 깎인다. 관측소를 같은 시각으로 나란히 놓아 둘을 견주게 한다.

| | |
|---|---|
| 점 | **마름모** — 격자 최대 표식(동그라미)과 가른다. 속은 **지도와 같은 색 단계** — 둘레 칸과 색이 같으면 격자와 관측이 맞는 것, 다르면 어긋난 것 |
| 값이 없을 때 | 0 = 속 빈 마름모 · 기상청 결측 = × · 그 시각 값을 못 받음 = 점선 마름모. 셋을 섞지 않는다 |
| 같은 시각만 | 지금 그린 격자와 **같은 층·같은 시각** 값만 그린다(가까운 시각으로 메우지 않는다). 60분·오늘은 매분자료가 없으면 정시자료(`awsh`)로, 15분은 정시 대신이 없다. 예측 층에서는 자리만 |
| 값 글자 | 기본은 끔 — 점 색만으로도 단계가 읽히고, 켜면 지도가 붐빈다. 켜면 센 곳부터 빈자리에만 달고(시군명·특보 딱지·격자 최대 라벨·다른 점을 피한다) 상위 셋은 지점 이름도 |
| 마우스 | 점에 올리면 실측 · 그 칸 격자 · **차이(격자 − 관측)** · 해발 |
| 범례 | 왼쪽 관측소 아이콘을 누르면 오른쪽에 펼친다 — 견본 한 줄과 경고(그 시각 값을 못 받음 등)만. 출처·설명·위치 없는 지점은 `ⓘ` 에 |

**레이어 목록 · 범례는 짧게, 설명은 `ⓘ` 에.** 목록 한 줄은 이름 · 키 · `ⓘ` 뿐이고, 범례 머리에도 `ⓘ` 가 있다.
`ⓘ` 에 올리면 설명이 뜨고, 누르면 고정된다(다시 누르거나 밖을 누르면 닫힘 — 벽면 터치에서도 읽히게).
누르는 것은 잡는 단계에서 가로챈다 — `ⓘ` 가 레이어 줄(label) 안에 있어 그냥 두면 체크가 바뀌고,
특보 범례 머리에 있으면 접혔다. 레이어 메뉴·범례·오른쪽 카드 위에서는 지도 툴팁을 띄우지 않는다.

재현 사례에서는 사례를 만들 때 함께 굳힌 매시 `RN_HR1`(awsh)을 쓴다 — `누적` 층이면 사례 처음부터
그 시각까지 더한다(한 시간이라도 결측이면 하한 — 글자는 숫자만, 점에 올리면 `N시간 빠진 합`). 거제 사례 끝: 관측소 거제 967.7㎜ · 서이말 831.0 ·
통영 778.0 · 격자 최대 일운면 767.7. 매시 합이 일자료와 맞는지(거제 8.16 273.3 · 8.17 654.3 …) 만들 때 견준다.

| | |
|---|---|
| 면을 칠하지 않는다 | 강수는 청색 **면**이다. 특보까지 면이면 두 색이 섞여 둘 다 못 읽는다. 특보는 **선과 글자**뿐이다 |
| 예약색 선 | 주의보 노랑 · 경보 빨강 · 중대경보 보라(`--lv-*`, 종합 화면과 같다) — 청색과 색조가 겹치지 않는다 |
| 선 모양도 다르게 | 주의보 **점선** · 경보 **실선** · 중대경보 **겹실선**. 흑백 인쇄·색약에서도 갈린다 |
| 시군 안쪽에만 | 선을 그 시군 모양으로 잘라 안쪽 절반만 보인다 — 이웃 시군의 다른 특보 선과 겹치지 않는다. 한 시군에 여럿이면 제일 센 것으로 긋는다 |
| 글자 딱지 | 시군명 밑에 `호우경보` · `강풍주의보` 를 센 것부터 쌓는다. 일부 구역만이면 `호우주의보 · 서북`. 강수 최대 라벨은 딱지를 피해 자리를 잡는다 |
| 바다 · 예비 | 바다 특보는 **경남 바다만**(남해동부 먼바다 · 거제 · 경남 앞바다) — 특보 줄에 적고, 줄을 접고 바다 위젯도 끄면 거제 동남쪽 트인 바다 위에 글로(둘째 줄에 구역 `동쪽안쪽 먼바다 · 거제 앞바다`). 땅(시군)에는 긋지 않는다. 남해서부(전남 쪽) · 부산 · 전남 바다는 뺀다. 예비특보(태풍 등) · 발효 예정은 지도에 긋지 않고 특보 줄에만 — 발효 예상 날짜 · 시간대와 함께(아직 발효 전이다) |

범례에 특보마다 선 견본 · 이름 · 시군을 적는다. 1분마다 다시 읽는다(DB 만).

**레이어는 아이콘으로.** 왼쪽 위에 레이어 아이콘 하나, 그 밑에 **켜진 레이어만** 작은 아이콘(특보 ⚠ · 관측소 ◇)을
세운다. 특보 아이콘은 지금 가장 센 특보 색(주의보 노랑 · 경보 빨강 · 중대경보 보라)에 특보 종류 수 딱지.
레이어 아이콘을 누르면 메뉴가, 관측소 아이콘을 누르면 그 범례·설명이 아이콘 오른쪽에 잠깐 펼쳐진다
(다시 누르거나 범례 머리를 누르면 닫힌다, 창마다 기억). ⚠️ 예전엔 '레이어 · 특보' 단추와 특보 범례 상자가
지도 북서쪽(함양·거창)을 늘 덮었다.

**특보 줄 — 지도 왼쪽 빈자리에 얇게 세로로(10-24).** 특보 아이콘을 누르면 아이콘들 **밑에** 188px 줄로 펼쳐진다(범례 위까지,
넘치면 굴린다). 한 특보가 두 줄 — 이름(색 · 주의보 점선 · 경보 실선 · 중대경보 겹선 견본) / 어디(작게). 바다 · 예비 · 예정은 앞에 딱지.
**펼쳐 두면 지도가 그 오른쪽으로 비켜 선다** — 겹치지 않게(1920×1080 · 패널 켬에서 지도가 4% 남짓 줄어든다). 줄 머리나 아이콘을
누르면 접히고 지도가 다시 넓어진다. 창마다 기억(`gn-map-alopen`, 처음엔 펼침), 관측소 범례와 따로 논다.
⚠️ 예전에는 아이콘 오른쪽 340px 상자라 지도 북서쪽을 덮어 평소엔 접어 뒀다 — 바다 위젯에 특보를 넣었더니 그 판이 너무 커졌다.
줄이 펼쳐져 있거나 바다 위젯이 켜져 있으면 지도 위 바다 특보 글자는 그리지 않는다(줄이 적는다 · 위젯이 그 바다 자리를 쓴다).

**예비특보(태풍 · 호우 …).** 지도에 긋지 않고(아직 발효 전이다) 특보 줄에 `예비 · 태풍 예비특보 / 25일 오전(06~12시) / 거제 · 통영`
처럼 — **발효 예상 날짜 · 시간대**, 이름 · 시간대가 같은 것끼리 묶어 시군(바다 구역은 줄인 이름). 종합 화면 아래 특보 줄에도
예비 색 칩(`태풍 예비특보 2개시군 · 25일 오전(06~12시)`)으로, 누르면 구역. ⚠️ 예전에는 받기만 하고 종합 화면에는 띄우지 않았고,
시간대만 적어(`새벽(03~06시)`) 오늘인지 내일인지 몰랐다 — 태풍 예비특보는 하루 이틀 앞을 말한다. 수집기는 CMD 뿐 아니라
레벨 칸 · 특보 이름에 '예비'가 와도 예비로 읽는다(발효 중인 '태풍예비' 특보로 세지 않게). 응답에 예비가 실제로 어떤 모양으로
오는지는 태풍 예비특보가 걸린 날 서버 `/api/alerts` 의 `pending` 으로 확인한다.

**경계선 테두리.** 시군 경계·해안선·권역 선 밑에 반대색 테두리(어두운 테마는 어두운, 밝은 테마는 흰 halo)를 깔고
시군 경계는 조금 밝게 — 단기·누적처럼 강수 청색이 넓게 칠해지면 경계가 묻혔다. 비 없는 땅 위에서는 테두리가
바탕과 같은 색이라 예전 모양 그대로다.

⚠️ 작은 섬(4㎢ 미만)까지 특보 선을 두르면 통영·거제 바다가 점선으로 어지럽다. 선은 큰 땅에만 긋는다.
⚠️ 특보구역 경계(합천 서북부 등)는 아직 지도에 없다 — 시군 전체에 긋고 딱지에 구역을 적는다.
⚠️ **테스트 모드는 색을 쓰지 않는다.** 처음엔 보라 테두리였는데 특보(중대경보 보라)를 켜자
   헷갈렸다. 지금은 무채색 점선 테두리 + 위 가운데 줄무늬 띠다. 테스트 모드의 특보는 합성이다.

#### 데모 — 테스트 · 재현 사례를 한 메뉴에

머리글 오른쪽 **데모 아이콘(슬레이트)** 하나에 실황이 아닌 화면을 모았다(종합 화면 설정의 '데모 시연'과 같은 말).
**실황(지금)** · **테스트 — 합성**(점검) · **재현 사례**(지난 호우). 지금 어느 쪽인지는
글자 없이 **단추 색**으로 알린다(테스트 무채색 · 재현 강조색, 올리면 지금 무엇인지 뜬다). 실황에서 테스트를 켜고 끄는 것은 다시 띄우지 않고 그 자리에서
(`T` 키도 같다), 사례는 주소를 바꿔 띄운다. 처음엔 `사례` · `테스트` 단추가 따로 있었는데 둘 다 '실황이 아닌
화면'이라 한 메뉴가 맞다.

테스트에는 **합성 지점**도 있다(`/api/grid/testrain`) — 기상청 지점 자리 55곳과 시군마다 '스방 흉내' 가상
지점 셋(`○○동(가상)`, 위치 없음). 값은 합성 60분 격자를 그 칸에서 읽어 지점마다 늘 같은 비율을 곱한다(관측소
층 테스트와 같은 비). 비 없는 날 테스트에서 시군을 누르면 **내부망(스방)에서 보일 목록 모양**을 미리 본다.

#### 재생 · 강수 타임라인

**재생은 '1시간 강수량'의 흐름 하나**다 — 지난 N시간 실측(500m 60분, 고른 간격) → `지금` →
초단기 +1~6시간 예측. 1시간 · 초단기 층에서 아래 재생 막대가 뜬다. 막대를 끌면 그 시각으로 가고,
`Space` 로 재생, `←` `→` 로 한 장씩. 실측 칸은 틱이 촘촘하고 예측 쪽은 빗금 바탕이다.

**자료가 AWS 면 실측이 AWS 1시간 면(`aws60`)이다**(`/api/grid/flow?src=aws`) — 정시마다 한 장(경남 AWS 가 정시
자료라 '실측 간격' 설정은 격자에만 걸린다), 손잡이 글자에 `· AWS`. 흐름의 끝은 관측소 값이 든 가장 최근 정시다 —
정시자료(awsh)가 정시 뒤 늦게 오므로 격자 60분보다 한 시간쯤 앞에서 끝날 수 있다. 지금 뒤는 격자와 같은 초단기.

**오른쪽 패널**(창 아이콘 · `L`)이 나오면 지도는 그만큼 왼쪽으로 비켜서고(모자라면 살짝 줄인다)
둘을 함께 본다. 방식은 설정에서 고른다.

**카드(기본) — 종합 화면의 판을 작게.** 지도 오른쪽 바다 위에 유리 카드 셋이 차례로 미끄러져
들어오고, 뒤로는 지도가 그라데이션으로 가라앉는다. 딱 맞춘 격자로 나누지 않고 지도 위에 띄운다.

**위 카드는 지도를 따른다.** 지도가 누적(격자 · AWS)이면 위 표의 `강수 누적`, 지도가 15분 · 1시간 · AWS 1시간 ·

머리 시각 = 지도 시각). 재생 · `←` `→` 로 지도가 넘어가면 카드도 같이 넘어간다. 줄은 시군마다 가장 많은 곳 —
AWS 1시간은 관측소(그 정시 한 시간, `/api/grid/stations?layer=aws60&tm=`), 그 밖은 읍면동 최대 칸(시군당 1곳이면 지도
시군 라벨과 같은 값, 여러 곳이면 `/api/grid/emd`). 선 그래프는 재생 흐름의 그 시군 최대이고 세로선이 지도 재생 위치다

그림 위에 떠오른다. 그림 시각과 발표 시각(`12:30 +50분 │ 11:40 발표`)은 늘 왼쪽 위에.

| **AWS**(실황 기본) | 시군 다우지점 — 스방 265(내부망) → 비면 기상청 56 | 그 시군 **지점 전부** — 내부망이면 스방 지점까지(기상청 지점 포함, 머리에 `기상청 n · 스방 m`). 기상청 지점은 읍면동 · 위치 · 예상(그 읍면동 예측)이 붙고, 스방 자체 지점은 `스방` 표 — 위치는 아래 '스방 지점 위치(임시)' |
| **격자**(사례 기본) | 시군 **누적 최대 칸** + 그 칸의 읍면동. 매시 정각 60분 격자를 칸마다 더한다 | 그 시군 **읍면동 전부** — 읍면동마다 누적 최대 칸. 예상은 그 읍면동 예측 |

선 그래프는 그 지점·그 칸의 매시 값이다. 빠진 정각이 있으면 `정시 격자 N시간 빠짐 — 합은 하한`.
실황에서 고른 기준은 서버 설정(`acc_basis`)에 남는다.

**시군 고르기 — 지도에서 시군을 누르면** 오른쪽 패널이 그 시군으로 바뀐다(패널이 닫혀 있으면 연다).
누적 카드는 위 표대로 읍면동·지점, **지금 오는 비·예측 상위도 그 시군 읍면동** — 세 카드가 같은 단위다
(지금 오는 비는 매분자료 지점이 한 시군에 두세 곳뿐이라 500m 격자 15분·60분 최신 칸을 읍면동마다 최대로 읽는다.
사례는 1시간·3시간, 호우 기준은 고른 시군만).

**여러 시군 비교 — `Ctrl`(맥 `⌘`)+클릭으로 더하고 빼고, 몇 곳이든(경남 18곳까지).** 함양을 누르고 Ctrl+거창을 누르면 두 시군
읍면동이 한 판에 섞여 줄 선다(줄마다 시군 표). 지도는 고른 시군을 다 담게 날아가고 테두리·읍면동 선·이름도
고른 시군 전부에. ⚠️ 예전에는 3곳까지였다 — 넷 이상 견주고 싶다는 말에 풀었다(10-24). 넷 이상이면 이름을 `함양·거창 외 3` 으로
줄여 적는다(칩에 올리면 전부). 그냥 누르면 그 시군 하나로, 카드 머리의
`함양·거창 ✕` · `Esc` 로 경남 전체로. 카드의 시군 줄도 Ctrl+클릭으로 더한다. 주소는 `?sig=함양,거창`.
API 는 `sigun=함양,거창`(쉼표, 여럿)을 받는다 — `/api/forecast` · `/api/grid/acctable` · `/api/grid/emd`.
`sigun=all` 은 경남 열여덟 시군 전부(위 카드 줄 세우기 — 시군당 2 · 3곳 · 시군 무관).
지도는 고른 시군 밖을 바다색으로 가라앉히고 밝은 겹선을 두르며(강조색 선 하나는 청색 강수 면에
묻혀 안 보였다) 다른 시군 관측소를 흐리게 한다. 순위 원 1~3 은 그 지점·칸 자리에 붙고, 줄에 마우스를
올리면 그 자리까지 빛줄과 고리가 그어진다. 다시 누르거나 바다를 누르거나 `Esc`, 카드 머리의
`창원 ✕` 로 경남 전체로 돌아간다. 시군 줄을 눌러도 고른다.
**지도 위 순위 원(1~3위)은 경남 전체 지도일 때만** — 시군을 골라 확대하면 천천히(0.6초) 사라지고, 경남 전체로 돌아오면 다시 나온다.
바다 위젯도 같다(확대하면 바다 자리가 땅이 된다).

**지도 위치 — 오른쪽 위 십자 단추 · `C`(10-24).** 판 위를 끌어 옮기고 휠로 키우고 줄인다(커서 자리를 붙잡고, 0.6~4배).
`0` · 두 번 누르기 = 처음대로, `Enter` · `Esc` · `다 됐다` = 끝. **이 브라우저에 기억**(`gn-map-cam` — 벽면 화면마다 크기가 달라서
서버 설정이 아니다), 설정 › 화면 › 지도 위치에도 있다. 경남 전체 틀(패널이 비켜선 틀) 위에 얹는 배율 · 옮김이라 패널을 켜고 꺼도 따라간다.
시군을 골라 확대하면 그 틀이 먼저고, 풀면 이 틀로 돌아온다. ⚠️ CSS 확대가 아니라 지도 틀(V) 자체를 바꿔 그린다 —
키워도 격자 칸 · 선이 또렷하다. 끄는 동안은 경계를 viewBox 로만 옮기고(시군 확대 비행과 같은 수) 손을 떼면 새로 그린다.

**바다 위젯 — 지도 위 반투명 판 · `W`(10-24).** 예전에는 바다 특보 글자만 떠 있던 남는 자리다. 머리 탭으로 고른다:
`예측 상위`(초단기 앞으로 6시간, 오른쪽 카드와 같은 그림) · `지금 오는 비`(15분 · 60분). `W` 는 차례로 넘기고 끝은 끔, `✕` 도 끔.
⚠️ 처음에는 `특보` 탭(바다 · 육상 · 예비)과 다른 탭 머리 밑 바다 특보 한 줄도 있었다 — 판이 너무 커서 뺐고, 특보는 왼쪽 특보 줄로 옮겼다.
서버 설정 `sea_w`(off · fc · now, 기본 fc — 화면 모두 같이, 남은 alert 값은 fc 로 읽는다), 설정 › 화면 › 바다 위젯.
**자리는 스스로 찾는다** — ⚠️ 처음에는 지도 빈자리 오른쪽 아래에 붙였더니 1920×1080 에서 거제를 덮었다(10-24). 이제 판을 8px 칸으로 나눠
경남 시군(이웃 부산 · 울산 · 바다는 빈자리)을 칠하고, 범례 · 재생 막대 · 제목 · 도구 · 오른쪽 패널은 못 가는 칸으로 둔 뒤, 땅을 가장 적게
덮는 자리를 고른다. 꼴은 둘 — 넓게(430) · **세로로 길쭉하게**(262, 지금 오는 비는 15분 · 60분을 위아래로 · 예측 상위는 칸을 좁히고 ·
탭 이름을 줄인다). 땅을 덜 덮는 것 → 줄이 많은 것(모자라면 예측 상위 · 지금 오는 비를 4 · 3 줄로) → 길쭉한 것 → 지도 위쪽 오른편에 가까운 것.
1920×1080 · 패널을 켜면 거제 동쪽 · 부산 남쪽 바다에 길쭉하게 앉아 땅을 하나도 덮지 않는다(1536×864 는 조금 덮는다 — 끌어 옮기면 된다).
지도 틀 · 패널 · 범례가 그대로면 다시 재지 않는다(1분마다 줄 수가 조금 바뀌어 판이 들썩이지 않게 — 높이가 40px 넘게 바뀔 때만).
**머리를 끌어 옮기면 마지막으로 놓은 자리가 이 화면의 기본 자리**가 된다(`gn-map-sw` — 가까운 끝, 위나 아래에 붙여 잰다. 줄 수가
바뀌어도 그 끝에 붙어 있게). 머리의 `⇔` · `⇕` 로 꼴을 바꾼다(그 자리에 기억). 두 번 누르면 다시 자동. 오른쪽 패널 밑으로는 들어가지 않는다.
지도를 비켜 세우고 싶으면 지도 위치(`C`) — 이것도 이 화면에 기억한다.
예측 상위 · 지금 오는 비는 오른쪽 패널(카드)의 자료라 패널이 꺼져 있으면 그렇게 적는다.

**시군 확대(설정 → 화면 → 시군 누르면: `확대 — 읍면동 경계·이름` / `테두리만`, 서버 설정 `sel_zoom`, 기본 확대).**
고르면 카메라가 그 시군으로 날아가 지도 빈자리(범례 오른쪽 ~ 패널 왼쪽, 레이어 단추 아래 ~ 재생 막대 위)를
채운다(경남 전체의 9배까지). 다른 시군을 누르면 그리로 날아가고(멀면 살짝 물러났다 다가간다 — van Wijk 줌),
풀면 경남 전체로 물러난다. 확대하면 그 시군 **읍면동 경계**(안쪽 선만 — 시군 경계와 원본이 달라 바깥 둘레는
수십 m 어긋나므로 쓰지 않고, 시군 모양으로 잘라 끝을 감춘다)와 **읍면동 이름**(큰 곳부터, 최대 라벨·관측소와
겹치지 않는 자리에만)이 나온다. 격자는 칸 그대로 커지고 선 굵기·글자 크기는 그대로다.
⚠️ 경계를 다시 그리는 데 26ms 라 매 장 다시 그리지 않는다 — 날아가는 동안은 SVG `viewBox` 만 옮기고(선은
`non-scaling-stroke`) 격자 Canvas 만 다시 그린다(장당 0.2ms). 글자·점은 잠깐 감췄다가 다 오면 새로 그린다.
창이 가려져 `requestAnimationFrame` 이 멈춰도 시간이 지나면 끝 상태로 가 있다. `?sig=` 로 열면 날지 않고 바로 확대.
시군을 고르면 누적 카드는 줄을 **다 그리고 카드 안에서 굴린다** — 내부망이면 한 시군에 지점이 수십 곳이라
'외 N곳'으로 자르면 안 보인다.

**경남 AWS · 기상청 AWS — 위치와 관리기관.** 내부망(스방 — 경남 스마트 통합 방재시스템)은 경남 AWS(도 자체 216곳)와
기상청 AWS 를 합쳐 263곳쯤을 준다(아래 점검). 화면은 '스방' 대신 **경남 AWS / 기상청 AWS** 로 부르고, 강수 누적 카드 막대를
**경남 AWS 파랑 · 기상청 AWS 청록**으로 가른다(최근 1시간 빗금도 같은 색조, 범례 `경남 AWS · 기상청 AWS`).
자료원 이름은 `경남+기상청 AWS 265` · 물러서면 `경남 AWS 안 됨→기상청`.

위치는 **경남 AWS 목록**(`data/geo/aws_sites.json` — 도에서 받은 엑셀을 `tools/build_aws_sites.py <aws.xlsx>` 로 만든다.
시군 · 장치명 · 주소 · 위경도 · 관리기관 · 설치위치 · 해발고도)이 먼저다(`app/sites.py`). 스방은 지점을 장치코드(lnk_id) ·
장치명 · 시군으로 주는데 목록에 장치코드가 없어 **시군 + 장치명**으로 짝짓는다 — 띄어쓰기 · 괄호를 떼고, `김해시`처럼
시군 이름에 붙은 시/군도, 앞머리 시군 이름도(목록 `거창북상` = 스방 `북상`) 떼고 본다. 같은 시군에 같은 이름이 둘이면
(합천 · 거창 북상 — 경남 · 기상청) 기상청 지점번호로 오는 것이 기상청이다. 관리기관(`org` = gn | kma)은 서버가
`/api/rain` 줄마다 준다. `(가상)` 테스트 지점은 짝짓지 않는다.

> [!warning] 엑셀 목록에서 같은 이름 두 줄의 자리가 엇갈려 있다
> 장기(거창↔고성) · 당항(고성↔남해) · 도천(창녕↔통영) · 성산(창녕↔합천) — 고성 `당항` 줄이 남해 남면사무소에 찍히는 식.
> 두 줄이 서로 상대 시군에 떨어지면 `build_aws_sites.py` 가 위경도 · 주소 · 설치위치 · 해발을 맞바꾼다(`aws_sites.json` 의
> `swapped`). 짝 없이 제 시군 밖인 줄은 그대로 두고 `sigun_off` 에 남긴다 — 진주 `금곡면`(좌표가 고성 영오면),
> 통영 `매물도` · `하소`(섬, 칸 밖).

목록에서 못 찾은 지점만 **이름이 가리키는 읍면동 가운데**(안쪽 가장 깊은 점)에 임시로 둔다 — 그대로(`시천면`) →
읍·면·동을 붙여(`시천`→시천면) → 괄호 안(`덕산(시천면)`) → 앞머리가 하나뿐일 때. 카드 밑에 `경남 AWS N곳은 목록에 없어 …
읍면동 가운데에 임시로 둔다`. 장치코드로 따로 바로잡을 지점은 `data/geo/bangjae_sites.json`
(`{"sites": {"<lnk_id>": {"lon": 127.83, "lat": 35.26}}}`) — 무엇보다 먼저다. 스방이 **시군을 잘못 주면**
`{"<lnk_id>": {"sigun": "산청"}}` — DB 에는 스방 값 그대로 두고 읽을 때(`sites.sigun_of`) 바꾼다. 시군 평균 · 짝짓기 · 위치가
다 따른다(`/api/aws/match` 줄에 `sigun_bj` 로 스방이 준 시군). 지금 하나 — 8857 `신등`(스방은 사천, 목록 · 비 값은 산청 신등면).

> [!note] 엑셀 216곳 vs 스방 — 내부망 점검(2026-10-19)
> 스방 `dt096` 은 평소 263곳(경남 209 · 기상청 지점번호 54)을 준다. 엑셀의 경남 216곳 가운데 **7곳이 오지 않는다** —
> 고성 당동 · 당항(당항리), 밀양 신곡, 사천 사남, 의령 운곡, 하동 고전, 합천 덕촌. 신곡 · 사남 · 운곡 · 덕촌은 9.6. 까지 왔고
> (9.7.~10.15. 은 DB 가 비어 언제 빠졌는지 모른다), 고전은 8.31. 하루, 당동 · 고성 당항은 한 번도 안 왔다.
> 기상청 54곳은 **10.18. 11시 칸부터 스방에서 값이 끊겼다**(10.19. 은 목록에서도 빠짐) — 그 뒤 구간의 강수 누적 카드(스방 원천)에는
> 기상청 AWS 막대가 없거나 모자란다.

> [!warning] 경남 AWS 00시 칸은 스방이 비워 준다 — 일누적 줄로 메운다
> `dt096` 시간 줄의 `times00` 이 경남 AWS 는 늘 비어 온다(기상청 지점은 있다). 그래서 어제 0시부터 같은 누적은 경남 AWS 가
> 모두 한 시간 빠진 하한(`≥`)이었고, 10.19. 00시 호우(78곳)가 통째로 빠졌다. 같은 응답의 일 줄(`gubun='일'`)은 그 날 00시부터의
> 누계라(일[h] − 일[h−1] = 시간[h] — 실측 약 6천 칸 다 맞음, 기상청 지점은 시간[0] = 일[0] 54곳 다 맞음) 00시는 **일[0]** 이다
> (`Client.station_hourly`). 근처 기상청 01시(00~01시)와 평균 차 1.3㎜(앞뒤 시각은 4~8㎜).

**기상청 지점은 기상청 값으로.** 내부망(스방 원천) 카드 · 표도 기상청 AWS 56곳은 스방이 준 값이 아니라 기상청 API 값(obs_hourly ·
매분 보강)을 쓴다 — 스방이 기상청 몫을 떨군 적이 있고(10.18. 11시~10.19.), 외부망 화면과 같은 지점이 다른 값이면 헷갈린다.
막대는 기상청 AWS 청록 · 경남 AWS 파랑. 경남 AWS 만 스방에서.
스방 지점이 하나도 없으면(서버 · 집) `/api/rain?src=bangjae` 는 **빈 줄**이다 — 화면이 `경남 AWS 안 됨→기상청` 으로 물러선다.
⚠️ 기상청 줄을 늘 덧붙이자 줄이 차서 화면이 물러서지 않았고, 서버 화면에서 매분 마지막 칸(정시 뒤 지금까지)이 사라졌다(10-23 고침).

**지점 값 글자는 숫자만.** 구간 중 빠진 시각이 있으면 있는 시각만 더한 하한인데 `≥` 를 붙이지 않는다 — 점에 마우스를 올리면
`N시간 빠진 합(실제는 이보다 클 수 있다)`(`/api` 관측소 줄의 `miss`), 관측소 ⓘ 에 그런 곳 수. 누적 카드 숫자도 같다(숫자에 올리면 설명).
기상청 색(범례 색 띠)일 때는 알록달록한 면 위에서 글자가 색 칸처럼 읽혀 **값 글자에 바탕 상자**를 깐다.

> [!note] 기상청 AWS 위치는 기상청 지점 목록(`stations.json`)을 그대로 쓴다
> 엑셀의 기상청 54곳 가운데 50곳이 이름으로 짝지어지고(`김해시`·`양산시`·`의령군`·`함양군` = 기상청 김해 · 양산 · 의령 · 함양),
> 대부분 수십 m 안이다. 몇 곳은 같은 읍면동 안에서 꽤 떨어진다 — 시천 10.6km · 화개 4.5km · 금남 4.4km · 도천 3.5km ·
> 삼장 1.4km · 장목 1.3km · 송백 0.4km(`aws_sites.json` 의 `kma_check`). 어느 쪽이 맞는지 확인되면 고친다.

**관측소 층 — AWS 전부.** 기상청 AWS 55곳(◇) + 경남 AWS 216곳(○, 경남 AWS 목록 위치)을 짚는다. 경남 AWS 값은 스방
시간 강우량이라 **누적 · AWS 누적 층에서만**(같은 구간 정시 합) — 15분 · 60분 · 실황 층에서는 자리만(점선). 점에 올리면
관리기관 · 설치위치 · 주소.

**AWS 비활성화 — 관측소 점 오른쪽 클릭 → `비활성화 — 계산에서 빼기`.** 주변과 동떨어진 값(진주 한 곳 1㎜, 둘레 12~14㎜ —
고장 · 막힘)을 사람이 골라 뺀다. 서버 설정 `map.aws_off`([{id, name, sigun, org}], 벽면 화면 · 종합 화면도 같이) — 면(AWS 누적 · 1시간
IDW, 그 지점 없이 둘레 관측소로 다시 메운다) · 강수 누적 카드(`/api/rain`) · 지금 오는 비(`/api/minute`)에서 빠진다. 점은 남겨 회색 속 ·
빨간 빗금으로 그리고 툴팁에 그 값을 적는다(관측소 줄 `q: off`). 같은 메뉴로 다시 켠다. **설정(`Ctrl`+`,`) › 관측소**에 목록 · `다시 켜기` ·
`모두 다시 켜기`. 열쇠는 기상청 AWS 지점번호, 경남 AWS `gn:시군:목록 이름`(스방 장치코드와 지도 관측소 번호가 달라 이름으로 맞춘다).
격자(500m) 층은 기상청 분석값이라 그대로다.

**AWS 누적 층(`aws`) — 관측소 값만으로 메운 면.** 격자 분석값(500m)을 쓰지 않고, 강수 누적 카드 구간의 관측소 합
(기상청 AWS obs_hourly + 경남 AWS 스방, 목록 위치가 있는 것)을 가까운 8곳 역거리 제곱(IDW)으로 1km 마다 메워 500m 로
늘린다. 경남 땅 밖은 칠하지 않는다. 제목 `AWS 어제 0시부터 누적`, 출처 줄에 쓴 관측소 수. 내부망 밖에서는 기상청 55곳뿐이라
거칠다 — 경남 AWS 가 들어와야 촘촘하다. 카드 구간을 바꾸면 이 층도 따라 바뀐다(누적 층과 같다). 자료 AWS 에서 숫자 키 `3`.

**AWS 1시간 층(`aws60`) — 같은 관측소 · 같은 IDW 를 정시 한 시간 몫으로.** 시각은 누적 층과 같은 정시 격자 키이고,
정시 칸은 관측소 값이 하나라도 든 정시(최근 넷까지만 거슬러 본다). 관측소 층을 켜면 마름모가 그 정시 한 시간 값이다.
재생 흐름의 AWS 실측이 이 층이다(관측소 값이 하나도 없는 정시는 흐름에서 뺀다 — 한 장 때문에 흐름이 통째로 404 였다).
자료 AWS 에서 숫자 키 `2`.

> [!info] AWS 실시간 감시(`R`) — 켜면 지도가 1분마다(2026-10-23)
> 평소 AWS 누적 · 1시간은 **정시마다** 바뀐다. 층 메뉴 실측 머리의 **`실시간`**(초록 점) · `R` · 설정 › 재생 'AWS 실시간'
> (서버 설정 `aws_live`, 기본 끔)을 켜면 마지막 정시 뒤 매분자료(1분 수집기 `minute` — 켠 동안만 부른다)까지 잇는다 —
> 제목 시각 · 재생 막대 끝 칸(`지금`)이 그 분이고 머리에 `실시간 감시`(누르면 끈다). 켜자마자 매분을 한 번 받는다
> (`POST /api/refresh/minute`). 위 카드(AWS 누적)도 같이 — 끈 동안은 `/api/rain?tail=0` 으로 정시까지만(지도와 같은 시각),
> 켜면 정시 뒤 지금까지 칸이 붙는다. 종합 화면은 그대로(늘 매분 보강 칸). 격자 층은 감시와 상관없이 아래 표대로.
>
> | 층 | '지금' 칸 | 바뀌는 간격 |
> |---|---|---|
> | AWS 누적(`aws`) — 감시 켬 | 정시 합 + **정시 뒤 지금까지** — 기상청 RN_DAY 증분(`queries.minute_tail`, 종합 화면 강수량 판 마지막 칸과 같은 셈 — 정시자료가 늦으면 그 정시 매분자료를 기준으로), 경남 AWS 는 스방 진행 칸(스방 10분 · 5분 물러선 값). 제목 `… 14:37까지` | 1분 |
> | AWS 1시간(`aws60`) — 감시 켬 | 그 분의 **직전 60분**(기상청 RN-60m) — 제목 `14:37 · 직전 1시간(매분)`. 경남 AWS 는 정시 자료라 정시 칸에만(내부망에서도 이 칸은 기상청 55곳 면) | 1분 |
> | 격자 누적(`acc`) — 늘 | 정시 60분 합 + **정시 뒤 ~ 최근 10분 칸** — 일강수 격자 증분(`obsday`, 음수 칸 0 · 0시 정각 뒤는 그날 일강수 그대로 · 정시 일강수가 없으면 잇지 않는다). 카드 줄 마지막 칸이 그 몫이고 빗금(최근 1시간)은 그 시각 60분 격자, 머리 `14:40까지` | 10분 |
> | 격자 15분 · 1시간 · 5km 실황 — 늘 | 그대로 — 기상청이 5 · 10분마다 만든다(1분 자료가 없다) | 10분 |
>
> 지도는 30초마다 `/api/grid/meta` 를 읽어 **바뀐 층만** 다시 그린다 — 보고 있는 층이 바뀌었으면 지도(재생 중이거나
> 지난 시각을 보는 중이면 그대로), 재생 흐름의 실측 층이나 초단기가 바뀌었으면 흐름. 시각을 준 프레임(재생 · 지난 시각)은
> 최신이 바뀌어도 다시 받지 않는다(예전에는 늘 다시 받았다 — AWS 가 1분마다 바뀌자 흐름 정시 장들을 1분마다 받을 뻔했다).
> 관측소 점도 같은 시각까지(AWS 누적 — 그 분, 격자 누적 — 그 10분 칸의 매분자료). 매분이 90분 넘게 멈췄으면 잇지 않는다.
> API: `/api/grid/aws60?tm=…1437`(그 분 직전 60분) · 응답 머리 `X-Grid-Live` · 메타 층마다 `live`. 정시도 매분도 없으면 404.

목표(50ms)는 받아 둔 뒤 기준으로 맞는다. 띄우자마자 **나머지 층을 뒤에서 미리 받아 두므로**
벽면에서 누를 때는 늘 '받아 둔 뒤'다. 최대값의 튐(45·52ms)은 21번 중 한 번이고 그리기는 2ms
안쪽이다 — 창이 가려진 채로 쟀다. 그리기가 싼 까닭은 칸을 칸 = 픽셀인 작은 그림(416×378)으로
한 번 만들어 두고 확대만 하기 때문이다(층·눈금·테마마다 한 번, 5~6ms).

⚠️ 경계·격자 맞물림은 그림으로도 확인했다 — 8.28. 11시 60분 격자를 이 화면에 띄워 기상청이
   그린 같은 시각 분포도(`nph-sfc_obs_nc_img`)와 나란히 놓으면, 부산 남쪽 해안의 가장 센 곳·

   바이너리(disp=B)로 받은 것과 NetCDF 로 받은 것도 경남 bbox 에서 같은 값·같은 결측 칸이다.
